## The Theory (The What)

A **scope** defines the region of code where a name (variable, function, class) is visible and accessible. In Kotlin, scopes are created by blocks (`{}`), functions, classes, files, and modules. A variable declared inside a `when` branch is not visible outside that branch; a private function is scoped to its file or class.

Scopes serve two purposes: they control **visibility** (who can see this name) and **lifetime** (how long this value exists). When a scope ends, local variables become eligible for [garbage collection]({{ "/en/glossary/garbage-collector/" | relative_url }}).

## The Senior Nuance

- Kotlin's [scope functions]({{ "/en/01-kotlin-core/scope-functions/" | relative_url }}) (`let`, `run`, `with`, `apply`, `also`) are named after this concept: they create a temporary scope where the context object is the primary focus.
- **Coroutine scopes** (`viewModelScope`, `lifecycleScope`, `GlobalScope`) define the lifetime of coroutines — when the scope is cancelled, all coroutines within it are cancelled. Understanding this is critical for avoiding memory leaks.
- In dependency injection, **scopes** (`@Singleton`, `@ActivityScoped`) determine the lifetime of provided dependencies. A scope mismatch (injecting an activity-scoped object into a singleton) is a common source of leaks.
- **Visibility modifiers** (`private`, `internal`, `protected`, `public`) are scope declarations — they control which parts of the codebase can access a symbol.
