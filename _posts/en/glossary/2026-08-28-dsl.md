## The Theory (The What)

A **DSL** (Domain-Specific Language) is a mini-language tailored to a specific problem domain. In Kotlin, DSLs are built using lambdas with [receiver types]({{ "/en/glossary/receiver-type/" | relative_url }}), [extension functions]({{ "/en/glossary/extension-functions/" | relative_url }}), and operator overloading. The result is code that reads like a declarative description rather than imperative instructions. Jetpack Compose, Gradle Kotlin DSL, and Ktor routing are all Kotlin DSLs.

```kotlin
// From FollowApp Suite — BackupSerializer.kt
// apply {} as a builder DSL on JSONObject
private fun taskToJson(task: TaskEntity): JSONObject = JSONObject().apply {
    put("id", task.id)
    put("title", task.title)
    put("description", task.description)
    put("parentTaskId", task.parentTaskId)
    put("status", task.status)
    put("isCompleted", task.isCompleted)
}
```

```kotlin
// From FollowApp Suite — CsvExporter.kt
// buildString {} — a stdlib DSL for constructing strings
fun serialize(tasks: List<TaskEntity>): String = buildString {
    append(COLUMNS.joinToString(","))
    append("\r\n")
    for (task in tasks) {
        append(rowFor(task).joinToString(",", transform = ::escape))
        append("\r\n")
    }
}
```

## The Senior Nuance

- The magic behind Kotlin DSLs is the lambda with receiver (`T.() -> Unit`). Inside the lambda, `this` is the receiver object, so you can call its methods without qualification. `apply {}`, `buildString {}`, `buildList {}` all use this mechanism.
- `@DslMarker` prevents scope leakage in nested DSLs. Without it, inner lambdas can accidentally call methods from outer receivers. Compose uses `@LayoutScopeMarker` to ensure you cannot call `Column`'s `Modifier.weight()` inside a `Row`.
- A well-designed DSL is discoverable through IDE autocomplete — the [receiver type]({{ "/en/glossary/receiver-type/" | relative_url }}) restricts what methods are available, guiding the developer. This is type-safe metaprogramming: the compiler validates the DSL structure, unlike string-based DSLs (XML, YAML).
