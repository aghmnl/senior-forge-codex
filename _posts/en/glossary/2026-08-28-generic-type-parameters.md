## The Theory (The What)

**Generic type parameters** (the `T` in `List<T>`, `Flow<T>`, `Class<T>`) are placeholders that let classes, interfaces, and functions operate on any type while still being type-safe at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}). The compiler verifies type correctness — you can't put a `String` into a `MutableList<Int>` — but on the [JVM]({{ "/en/glossary/jvm/" | relative_url }}), generic type parameters are **erased** at [runtime]({{ "/en/glossary/runtime/" | relative_url }}): the bytecode only sees the raw type (`List`, `Flow`, `Class`). This is called *type erasure*.

## The Senior Nuance

- Type erasure means you **cannot** check generic types at runtime: `value is List<String>` doesn't compile because the JVM cannot distinguish `List<String>` from `List<Int>`. The workaround is [`reified`]({{ "/en/glossary/reified/" | relative_url }}) type parameters on [inline functions]({{ "/en/glossary/inline-functions/" | relative_url }}), where the compiler substitutes the concrete type at each call site.
- Kotlin adds **declaration-site variance** (`out T`, `in T`) which the compiler checks at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}). `List<out T>` is covariant — a `List<String>` can be assigned to a `List<Any>`. Java requires use-site wildcards (`? extends T`) for the same thing.
- **Star projection** (`List<*>`) is the Kotlin equivalent of Java's raw type, but safer — the compiler treats it as `List<out Any?>` (readable) but prevents writing unsafe values into it.
- In Android, generic type parameters are everywhere: `Flow<UiState>`, `LiveData<List<Task>>`, `Result<T>`, `Adapter<VH>`. Understanding variance and erasure is critical for writing reusable, type-safe components.
- `Class<T>` and `KClass<T>` carry the class token through type erasure, which is why patterns like `intent.getParcelableExtra<T>(key)` or `Room.inMemoryDatabaseBuilder(context, MyTasksDatabase::class.java)` require passing the class explicitly — the generic `T` alone would be erased.

```kotlin
// From FollowApp Suite — TaskDaoSortTest.kt
db = Room.inMemoryDatabaseBuilder(context, MyTasksDatabase::class.java)
    .allowMainThreadQueries()
    .build()
```

`MyTasksDatabase::class.java` is the class token that survives type erasure — Room needs the concrete class at runtime to instantiate the database implementation generated by [annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}).
