## The Theory (The What)

A **lambda** in Kotlin is an anonymous function literal — a block of code that can be passed as a value, stored in a variable, or used as an argument to higher-order functions. Lambdas are enclosed in braces `{ }`, with parameters before the `->` arrow. If a lambda is the last parameter of a function, it can be placed outside the parentheses (trailing lambda syntax).

```kotlin
// From FollowApp Suite — TasksViewModel.kt
val tags = allLabels
    .filter { (label, _) -> label.type == LabelType.TAG }
    .flatMap { (_, options) -> options.map { it.label } }
    .distinct()
    .sorted()
```

## The Senior Nuance

- Lambdas in Kotlin compile to anonymous inner classes (or `Function` objects) on the [JVM]({{ "/en/glossary/jvm/" | relative_url }}). Each non-[inline]({{ "/en/glossary/inline-functions/" | relative_url }}) lambda creates an object allocation. In hot paths, this matters — use `inline` higher-order functions to eliminate this cost.
- A lambda captures variables from its enclosing [scope]({{ "/en/glossary/scope/" | relative_url }}). Unlike Java, Kotlin lambdas can capture and *modify* `var` variables — the compiler wraps them in a `Ref` object. This is convenient but can cause subtle issues in concurrent code.
- [Destructuring]({{ "/en/glossary/destructuring/" | relative_url }}) in lambda parameters (`.map { (key, value) -> ... }`) makes iteration over [maps]({{ "/en/glossary/maps/" | relative_url }}) and pairs cleaner, but remember: destructuring binds by position, not by name.
