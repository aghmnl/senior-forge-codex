## The Theory (The What)

**Mutation** means changing an object's state after it has been created. In Kotlin, `var` declares a mutable variable (reassignable), while `val` declares a read-only reference. For collections, [`MutableList`]({{ "/en/glossary/mutable-list/" | relative_url }}), [`MutableMap`]({{ "/en/glossary/mutable-map/" | relative_url }}), and [`MutableSet`]({{ "/en/glossary/mutable-set/" | relative_url }}) expose mutating operations ([`add`]({{ "/en/glossary/add/" | relative_url }}), [`remove`]({{ "/en/glossary/remove/" | relative_url }}), [`put`]({{ "/en/glossary/put/" | relative_url }})), while their read-only counterparts ([`List`]({{ "/en/glossary/list/" | relative_url }}), [`Map`]({{ "/en/glossary/maps/" | relative_url }}), [`Set`]({{ "/en/glossary/sets/" | relative_url }})) do not.

```kotlin
// From FollowApp Suite — PresetMapper.kt
// Build-then-expose pattern: mutate locally, return immutable
val result = mutableMapOf<String, LabelFilterState>()
obj.keys().forEach { key ->
    runCatching { LabelFilterState.valueOf(obj.getString(key)) }
        .onSuccess { result[key] = it }
}
return result  // returned as Map — callers see read-only
```

## The Senior Nuance

- Kotlin's read-only collections are not truly immutable — they are interfaces that hide mutation methods, but the underlying instance can still be cast to its mutable counterpart. For structural immutability, use `kotlinx.collections.immutable` (`persistentListOf`, `persistentMapOf`).
- In [unidirectional data flow]({{ "/en/glossary/unidirectional-data-flow/" | relative_url }}) architectures, avoiding mutation is the foundation: instead of modifying state in place, you create a new state object via `copy()`. This makes [state transitions]({{ "/en/glossary/state-transitions/" | relative_url }}) explicit, traceable, and thread-safe.
- The "build mutable, expose immutable" pattern (as in the FAS example) is idiomatic Kotlin: use a [`MutableMap`]({{ "/en/glossary/mutable-map/" | relative_url }}) internally during construction, then return it as [`Map`]({{ "/en/glossary/maps/" | relative_url }}). The [`buildMap {}`]({{ "/en/glossary/build-map/" | relative_url }}), [`buildList {}`]({{ "/en/glossary/build-list/" | relative_url }}), and `buildSet {}` functions formalize this pattern.

**Kotlin docs:** [Collection types: read-only vs mutable](https://kotlinlang.org/docs/collections-overview.html#collection-types)
