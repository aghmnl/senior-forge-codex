## The Theory (The What)

**`reified`** is a Kotlin modifier for type parameters of [inline functions]({{ "/en/glossary/inline-functions/" | relative_url }}) that makes the type argument available at [runtime]({{ "/en/glossary/runtime/" | relative_url }}). Normally, the [JVM]({{ "/en/glossary/jvm/" | relative_url }}) erases generic type parameters during [compile time]({{ "/en/glossary/compile-time/" | relative_url }}) — `List<String>` becomes just `List` in [bytecode]({{ "/en/glossary/bytecode/" | relative_url }}). With `reified`, the compiler substitutes the actual type at each call site (because the function is `inline`), so operations like `is T`, `T::class`, and `filterIsInstance<T>()` work as if the type were known.

## The Senior Nuance

- `reified` only works with `inline` functions because the mechanism is compile-time substitution: the compiler replaces `T` with the concrete type at each call site before generating bytecode. There is no runtime reflection involved — it's a compile-time trick that produces type-specific bytecode.
- Without `reified`, you would need to pass a `KClass<T>` parameter explicitly: `fun <T : Any> parse(json: String, clazz: KClass<T>)`. With `reified`, the call becomes `parse<MyData>(json)` — cleaner API, same safety.
- Common use cases: `Gson().fromJson<T>(json)` (type token for deserialization), `intent.getParcelableExtra<T>(key)` (Android extras), `startActivity<T>()` (navigation helpers), and `filterIsInstance<T>()` (collection filtering).
- Because `reified` inlines the type at each call site, you **cannot** call a `reified` function from Java — Java has no concept of inline functions. This is a trade-off: cleaner Kotlin API at the cost of Java interop.
- `reified` does not work with non-inline functions, class-level type parameters, or `suspend` functions (since coroutine suspension breaks the inlining contract).

```kotlin
// Not found in FAS — standalone example
inline fun <reified T : Activity> Context.startActivity(extras: Bundle? = null) {
    val intent = Intent(this, T::class.java)  // T::class works because T is reified
    extras?.let { intent.putExtras(it) }
    startActivity(intent)
}

// Usage — the compiler substitutes SettingsActivity for T at this call site
context.startActivity<SettingsActivity>()
```
