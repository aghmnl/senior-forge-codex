## The Theory (The What)

The **safe call** operator (`?.`) accesses a member of a nullable receiver only if the receiver is non-null; otherwise the entire expression evaluates to `null`. It is one of Kotlin's core [null safety]({{ "/en/01-kotlin-core/null-safety-elvis-safe-calls/" | relative_url }}) mechanisms and can be chained: `user?.address?.city` returns `null` if any link in the chain is null, without throwing [NullPointerException]({{ "/en/glossary/null-pointer-exception/" | relative_url }}).

## The Senior Nuance

- Safe calls compose cleanly with the Elvis operator (`?.` + `?:`) and with [scope functions]({{ "/en/01-kotlin-core/scope-functions/" | relative_url }}) (`?.let { ... }`). The combination `nullable?.let { use(it) } ?: fallback()` is the idiomatic Kotlin pattern for "do something if present, otherwise do something else."
- Each `?.` in a chain introduces a potential `null` propagation point. Long chains (`a?.b?.c?.d?.e`) can hide structural problems — if five levels of nullability exist, the data model may need redesigning rather than more safe calls.
- At the bytecode level, `x?.method()` compiles to a null check + conditional call. There is no performance penalty compared to writing the `if` manually — it is pure [syntax sugar]({{ "/en/glossary/syntax-sugar/" | relative_url }}).
