## The Theory (The What)

A **Set** in Kotlin is an unordered collection of unique elements. The standard library provides `Set<T>` (read-only) and `MutableSet<T>` (modifiable). Common implementations include `HashSet` (hash-based, O(1) lookup), `LinkedHashSet` (preserves insertion order), and `TreeSet` (sorted). Factory functions like `setOf()` and `mutableSetOf()` create instances concisely.

```kotlin
// From FollowApp Suite — BulkSelectionTest.kt
val selected = setOf("1", "2", "3", "4")
val visible = listOf("1", "2", "3")
val result = toggleSelectAll(selected, visible)
assertEquals(setOf("4"), result)
```

## The Senior Nuance

- Like [maps]({{ "/en/glossary/maps/" | relative_url }}), sets rely on `hashCode()` and `equals()` for element identity. When storing `data class` instances in a set, only [primary constructor]({{ "/en/glossary/primary-constructor/" | relative_url }}) properties determine uniqueness — body properties are ignored.
- Kotlin's `Set` interface is read-only but not truly immutable: the underlying `HashSet` can still be cast and modified. For guaranteed immutability, use `persistentSetOf()` from `kotlinx.collections.immutable`.
- Set operations like `union`, `intersect`, `subtract`, and the `-` operator are powerful for bulk selection logic — the FAS example above uses set difference to compute remaining selections after toggling.
