## The Theory (The What)

**Dagger** is a fully static, compile-time dependency injection framework for Java and Kotlin. It generates all the wiring code at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}) via [annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}), producing a [dependency graph]({{ "/en/glossary/dependency-graph/" | relative_url }}) that the [JVM]({{ "/en/glossary/jvm/" | relative_url }}) can execute with zero [runtime reflection]({{ "/en/glossary/runtime-reflection/" | relative_url }}) overhead. [Hilt]({{ "/en/glossary/hilt/" | relative_url }}) is built on top of Dagger and provides Android-specific conventions (predefined components, scopes, and entry points) that eliminate most of Dagger's boilerplate.

```kotlin
// From FollowApp Suite — DatabaseModule.kt
@Module
@InstallIn(SingletonComponent::class)
object DatabaseModule {

    @Provides
    @Singleton
    fun provideMyTasksDatabase(
        @ApplicationContext context: Context
    ): MyTasksDatabase {
        return Room.databaseBuilder(
            context,
            MyTasksDatabase::class.java,
            "mytasks_database.db"
        )
            .addMigrations(MIGRATION_1_2)
            .build()
    }

    @Provides
    @Singleton
    fun provideTaskDao(database: MyTasksDatabase): TaskDao = database.taskDao()
}
```

`@Module` + `@Provides` tells Dagger how to create each dependency; `@InstallIn(SingletonComponent::class)` scopes it to the app's lifetime.

## The Senior Nuance

- **Dagger vs [Hilt]({{ "/en/glossary/hilt/" | relative_url }})**: Hilt is Dagger with opinions. It predefines component hierarchies (`SingletonComponent`, `ActivityComponent`, `ViewModelComponent`) so you don't have to wire them yourself. Senior developers use Hilt for Android projects and raw Dagger only for non-Android modules or multi-platform libraries.
- **Compile-time safety**: Unlike service-locator patterns (Koin), Dagger catches missing bindings at compile time. If a dependency is not provided, the build fails — you never discover a missing binding at [runtime]({{ "/en/glossary/runtime/" | relative_url }}).
- **`@Inject` constructor vs field injection**: [Constructor]({{ "/en/glossary/constructor/" | relative_url }}) injection is preferred because it makes dependencies explicit and enables immutability (`val`). Field injection (`lateinit var` + `@Inject`) is reserved for Android entry points (`Activity`, `Fragment`, `Service`) where the framework controls [construction]({{ "/en/glossary/constructor/" | relative_url }}).
- **Build time cost**: Dagger's [annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}) adds to build time, especially in large projects with many modules. KSP (Kotlin Symbol Processing) support is improving this, but it remains a trade-off senior developers consider when choosing a DI framework.
- **Testing**: Dagger/Hilt modules can be replaced in tests with `@TestInstallIn` or `@UninstallModules`, allowing you to swap real implementations for fakes without changing production code.
