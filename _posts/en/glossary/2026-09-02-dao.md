## The Theory (The What)

A **DAO** (Data Access Object) is a design pattern that encapsulates all access to a data source behind an interface. In Android, [Room]({{ "/en/glossary/room/" | relative_url }}) uses `@Dao`-annotated interfaces where each method maps to a SQL operation. The [annotation processor]({{ "/en/glossary/annotation-processing/" | relative_url }}) generates the implementation at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}) — you write the query, Room writes the [bytecode]({{ "/en/glossary/bytecode/" | relative_url }}).

```kotlin
// From FollowApp Suite — LabelDao.kt
@Dao
interface LabelDao {

    @Query("SELECT * FROM labels ORDER BY name ASC")
    fun getLabelsStream(): Flow<List<LabelEntity>>

    @Query("SELECT * FROM labels WHERE name = :name LIMIT 1")
    suspend fun getLabelByName(name: String): LabelEntity?

    @Insert(onConflict = OnConflictStrategy.IGNORE)
    suspend fun insertLabel(label: LabelEntity): Long

    @Query("DELETE FROM labels WHERE id = :labelId")
    suspend fun deleteLabel(labelId: String)
}
```

## The Senior Nuance

- **SQL verified at compile time**: [Room]({{ "/en/glossary/room/" | relative_url }}) validates every `@Query` against the database schema during build. A column name typo or type mismatch is a build error, not a [runtime]({{ "/en/glossary/runtime/" | relative_url }}) crash.
- **Flow returns are reactive**: A DAO method returning `Flow<List<T>>` automatically re-emits whenever the underlying table changes. This eliminates manual refresh logic and pairs naturally with [coroutines]({{ "/en/glossary/coroutines/" | relative_url }}).
- **[Suspend functions]({{ "/en/glossary/suspend-functions/" | relative_url }}) for one-shot operations**: `suspend fun` DAO methods run on the caller's coroutine context. Room ensures they execute off the main thread — calling a suspend DAO from `Dispatchers.Main` still runs the query on Room's background executor.
- **DAO as abstraction boundary**: Repositories depend on DAOs, not on Room directly. This means you can swap the database implementation or provide an in-memory DAO for testing without changing business logic.
