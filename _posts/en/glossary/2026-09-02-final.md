## The Theory (The What)

In Kotlin, classes and functions are **final by default** — they cannot be inherited or overridden unless explicitly marked `open` or `abstract`. This is the opposite of Java, where everything is open by default and must be marked `final` to prevent extension.

```kotlin
// Not found in FAS — standalone example
class PaymentProcessor {                       // final — cannot be subclassed
    fun validate(amount: Double): Boolean = amount > 0  // final — cannot be overridden
}

open class BaseRepository {                    // open — subclassing allowed
    open fun findAll(): List<Any> = emptyList() // open — overriding allowed
    fun count(): Int = findAll().size            // final — cannot be overridden
}
```

At the [JVM]({{ "/en/glossary/jvm/" | relative_url }}) level, `final` methods enable **devirtualization**: the [JIT compiler]({{ "/en/glossary/jit-compiler/" | relative_url }}) knows no subclass can override them, so it can bypass the [vtable]({{ "/en/glossary/vtable/" | relative_url }}) and inline the method directly — turning a [virtual dispatch]({{ "/en/glossary/virtual-dispatch/" | relative_url }}) into a [static dispatch]({{ "/en/glossary/static-dispatch/" | relative_url }}).

## The Senior Nuance

- Kotlin's final-by-default is a deliberate design choice following "Effective Java" Item 19: *Design and document for inheritance or else prohibit it*. Making developers opt into openness forces conscious decisions about which extension points to support.
- Final-by-default creates friction with frameworks that rely on subclass proxies — [Mockito]({{ "/en/glossary/mockito/" | relative_url }}) cannot mock final classes without the `mockito-inline` extension, and Hibernate needs the `kotlin-allopen` compiler plugin to generate entity proxies. Senior developers know these workarounds.
- [Data classes]({{ "/en/01-kotlin-core/data-classes/" | relative_url }}) are implicitly final and cannot be made `open`. This is intentional: the `equals`/`hashCode` contract would break with inheritance (a classic violation of the Liskov Substitution Principle).
- [Sealed classes]({{ "/en/01-kotlin-core/sealed-classes-interfaces/" | relative_url }}) invert the pattern: the hierarchy is open *within its module* but closed to the outside world. This enables [exhaustiveness]({{ "/en/glossary/exhaustiveness/" | relative_url }}) checking in `when` expressions while still permitting controlled subtyping.
- In performance-critical paths, `final` matters: the JVM's [JIT compiler]({{ "/en/glossary/jit-compiler/" | relative_url }}) can devirtualize and inline final methods, eliminating [vtable]({{ "/en/glossary/vtable/" | relative_url }}) lookups entirely. Kotlin gives you this optimization by default.
