## The Theory (The What)

The **heap** is the region of [JVM]({{ "/en/glossary/jvm/" | relative_url }}) memory where objects live. Every time you create an instance — calling a [constructor]({{ "/en/glossary/constructor/" | relative_url }}), boxing a [primitive]({{ "/en/glossary/primitives/" | relative_url }}), or capturing variables in a [lambda]({{ "/en/glossary/lambdas/" | relative_url }}) — the JVM [allocates]({{ "/en/glossary/allocations/" | relative_url }}) space on the heap. Unlike the stack (which holds method frames and local primitives), the heap is shared across all threads and managed by the [Garbage Collector]({{ "/en/glossary/garbage-collector/" | relative_url }}).

The JVM heap is divided into generations:

- **Young Generation** (Eden + Survivor spaces): where new objects are allocated. Most objects die young, so minor GC collections here are fast.
- **Old Generation** (Tenured): objects that survive multiple minor GCs are promoted here. Full GC pauses are more expensive.
- **Metaspace** (off-heap since Java 8): stores class metadata, replacing the old PermGen.

```kotlin
// Not found in FAS — standalone example
val name = "Alice"           // String object allocated on the heap
val list = listOf(1, 2, 3)   // List + 3 boxed Integer objects on the heap
val x = 42                   // primitive int — lives on the stack, NOT the heap
```

## The Senior Nuance

- On Android, the heap is limited per app (typically 256–512 MB depending on the device). Exceeding it causes `OutOfMemoryError`. Bitmaps are the most common heap consumer — always use `BitmapFactory.Options.inSampleSize` or Coil/Glide to downsample.
- [Inline functions]({{ "/en/glossary/inline-functions/" | relative_url }}) avoid heap [allocations]({{ "/en/glossary/allocations/" | relative_url }}) for lambda objects by copying the lambda body to the call site. This is why Kotlin's [scope functions]({{ "/en/01-kotlin-core/scope-functions/" | relative_url }}) (`let`, `apply`, `run`, `also`, `with`) are all `inline` — zero heap overhead.
- [Autoboxing]({{ "/en/glossary/autoboxing/" | relative_url }}) silently puts primitives on the heap: a `List<Int>` stores `Integer` objects, not `int` values. Use [`IntArray`]({{ "/en/glossary/intarray/" | relative_url }}) to keep values in a flat, unboxed array — no per-element heap allocation.
- Kotlin's [value classes]({{ "/en/01-kotlin-core/value-classes/" | relative_url }}) (`@JvmInline value class`) avoid heap allocation in most cases by erasing the wrapper at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}). The underlying value stays on the stack or in a register.
- ART (Android Runtime) uses a generational, concurrent, moving GC. The "moving" part means object addresses change during compaction — this is why you cannot safely hold raw pointers to heap objects across JNI boundaries.
