## The Theory (The What)

**Hilt** is Android's recommended dependency injection (DI) framework, built on top of Dagger 2. It uses [annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}) to generate the [dependency graph]({{ "/en/glossary/dependency-graph/" | relative_url }}) at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}), providing type-safe, zero-reflection DI with predefined Android component scopes (`@Singleton`, `@ViewModelScoped`, `@ActivityScoped`, etc.).

Hilt's module system uses [higher-order function]({{ "/en/01-kotlin-core/higher-order-functions-lambdas/" | relative_url }}) patterns under the hood: `@Provides` methods act as factory functions, and `@Binds` declares interface-to-implementation mappings that the generated code resolves statically.

```kotlin
// Not found in FAS — standalone example
@Module
@InstallIn(SingletonComponent::class)
abstract class RepositoryModule {
    @Binds
    abstract fun bindTaskRepository(impl: TaskRepositoryImpl): TaskRepository
}

@Module
@InstallIn(ViewModelComponent::class)
object UseCaseModule {
    @Provides
    @ViewModelScoped
    fun provideGetTasksUseCase(repo: TaskRepository): GetTasksUseCase =
        GetTasksUseCase(repo)
}
```

## The Senior Nuance

- Hilt generates all DI wiring at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}) via [annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}) (KSP or KAPT). This means DI errors are caught during build, not at [Runtime]({{ "/en/glossary/runtime/" | relative_url }}) — unlike service-locator patterns like Koin, which fail at runtime when a dependency is missing.
- Hilt's scoped [DSL]({{ "/en/glossary/dsl/" | relative_url }}) (`@InstallIn(SingletonComponent::class)`, `@InstallIn(ViewModelComponent::class)`) maps directly to Android lifecycle scopes. A `@ViewModelScoped` dependency lives as long as the ViewModel, then is garbage-collected — this automatic lifecycle alignment prevents [memory leaks]({{ "/en/glossary/memory-leaks/" | relative_url }}).
- `@HiltViewModel` + `@Inject constructor` is the standard pattern for injecting dependencies into ViewModels. Hilt creates the ViewModel via `ViewModelProvider.Factory` automatically — no manual factory needed.
- In multi-module projects, Hilt's `@InstallIn` ensures each feature module contributes to the global graph without coupling. This is a key architectural advantage for large Android apps with dynamic feature modules.
- The trade-off is build time: Hilt's annotation processing adds seconds to incremental builds, especially with KAPT. Migrating to KSP reduces this significantly. Senior developers evaluate this cost against the safety of compile-time DI.
