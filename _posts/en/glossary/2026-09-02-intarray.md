## The Theory (The What)

**`IntArray`** (and its siblings `LongArray`, `FloatArray`, `DoubleArray`, `BooleanArray`, `ByteArray`, `ShortArray`, `CharArray`) is Kotlin's specialized array that maps directly to a JVM primitive array (`int[]`). Unlike `Array<Int>` or `List<Int>`, which store boxed `Integer` objects on the [heap]({{ "/en/glossary/heap/" | relative_url }}), an `IntArray` stores raw `int` values in a contiguous block of memory — zero [autoboxing]({{ "/en/glossary/autoboxing/" | relative_url }}), zero per-element [allocations]({{ "/en/glossary/allocations/" | relative_url }}).

```kotlin
// Not found in FAS — standalone example
val boxed: List<Int> = listOf(1, 2, 3)     // 3 Integer objects + List wrapper on the heap
val unboxed: IntArray = intArrayOf(1, 2, 3) // one int[] — flat memory, no boxing

// Converting between them
val fromList: IntArray = boxed.toIntArray()
val fromArray: List<Int> = unboxed.toList()  // re-boxes each element
```

## The Senior Nuance

- The difference matters in performance-critical paths: iterating over an `IntArray` of 10,000 elements creates zero garbage, while iterating over `List<Int>` may trigger 10,000 [autoboxing]({{ "/en/glossary/autoboxing/" | relative_url }}) [allocations]({{ "/en/glossary/allocations/" | relative_url }}) depending on how the list was built. In `onDraw()` or Compose recomposition, this is the difference between smooth rendering and jank.
- `IntArray` lacks the rich Collection API (`map`, `filter`, `flatMap` returning `List`). Kotlin provides extension functions like `IntArray.map {}` that return `List<R>` — which re-boxes the results. For truly allocation-free processing, use indexed loops or `forEach` that operates in-place.
- [Primitives]({{ "/en/glossary/primitives/" | relative_url }}) in Kotlin compile to JVM primitives only when non-nullable and not generic. `IntArray` is the way to maintain that guarantee for collections of values.
- In Android, `IntArray` is commonly used for resource ID arrays, color arrays, and dimension arrays where the values are passed to framework methods expecting `int[]`. Parcelable's `writeIntArray()`/`createIntArray()` also work directly with `IntArray`.
- Kotlin's [inline functions]({{ "/en/glossary/inline-functions/" | relative_url }}) like `IntArray.sumOf {}` or `IntArray.count {}` process the array without allocating iterator or lambda objects, combining two allocation-avoidance strategies.
