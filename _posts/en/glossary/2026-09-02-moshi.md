## The Theory (The What)

**Moshi** is a JSON serialization library for Kotlin and Java by Square. It converts between JSON strings and Kotlin/Java objects. Moshi can work via [runtime reflection]({{ "/en/glossary/runtime-reflection/" | relative_url }}) (`moshi-kotlin-reflect`) or via [annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}) (`moshi-kotlin-codegen`), which generates `JsonAdapter` classes at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}) — the codegen path is preferred on Android for both performance and APK size.

## The Senior Nuance

- **Codegen vs reflection**: `moshi-kotlin-codegen` uses [KSP]({{ "/en/glossary/ksp/" | relative_url }}) (or [kapt]({{ "/en/glossary/kapt/" | relative_url }})) to generate adapters at compile time — no `kotlin-reflect` dependency needed, no reflection overhead, and [R8]({{ "/en/glossary/r8/" | relative_url }}) can shrink the result freely. The reflection adapter pulls in ~2.5 MB of `kotlin-reflect`, which is significant on Android.
- **`@JsonClass(generateAdapter = true)`**: This annotation triggers adapter codegen. The generated adapter handles nullability, default values, and unknown keys correctly — things Gson notoriously gets wrong with Kotlin.
- **Kotlin-first**: Moshi understands Kotlin's type system — nullable vs non-null, default parameter values, and data classes. Gson was designed for Java and silently assigns `null` to non-null Kotlin properties, causing crashes downstream.
- **Retrofit integration**: Moshi is commonly paired with Retrofit via `MoshiConverterFactory`. The generated adapters ensure that API response parsing is both fast and type-safe.
- **Alternative: Kotlinx.Serialization**: For pure Kotlin projects, `kotlinx.serialization` is the first-party alternative — it uses a compiler plugin instead of annotation processing and works with Kotlin Multiplatform.
