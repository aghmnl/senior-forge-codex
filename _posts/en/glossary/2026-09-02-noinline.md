## The Theory (The What)

**`noinline`** is a modifier for [lambda]({{ "/en/glossary/lambdas/" | relative_url }}) parameters of [inline functions]({{ "/en/glossary/inline-functions/" | relative_url }}) that prevents a specific lambda from being inlined. When a function is `inline`, all its lambda parameters are inlined by default — their body is copied into the call site. Marking one as `noinline` keeps it as a regular `Function` object [allocated]({{ "/en/glossary/allocations/" | relative_url }}) on the [heap]({{ "/en/glossary/heap/" | relative_url }}), which is necessary when you need to store, pass, or return the lambda.

```kotlin
// Not found in FAS — standalone example
inline fun measure(
    action: () -> Unit,          // inlined — zero allocation
    noinline onComplete: () -> Unit  // NOT inlined — kept as Function object
) {
    val start = System.nanoTime()
    action()
    val elapsed = System.nanoTime() - start
    // We need to store onComplete for later — only possible because it's noinline
    completionCallbacks += onComplete
}
```

## The Senior Nuance

- You need `noinline` when a lambda must be treated as an object: stored in a collection, passed to a non-inline function, assigned to a variable, or returned from the function. Inlined lambdas don't exist as objects — they're code pasted at the call site — so they can't be referenced.
- `noinline` lambdas [allocate]({{ "/en/glossary/allocations/" | relative_url }}) a `Function` object on the [heap]({{ "/en/glossary/heap/" | relative_url }}), like any regular lambda. In [hot loops]({{ "/en/glossary/hot-loops/" | relative_url }}), this matters — prefer restructuring the API to keep lambdas inlineable rather than using `noinline`.
- Contrast with [`crossinline`]({{ "/en/glossary/crossinline/" | relative_url }}): `noinline` prevents inlining entirely (the lambda becomes a heap object). `crossinline` still inlines the lambda but blocks non-local `return`. Choose based on whether you need the lambda as an *object* (`noinline`) or just need to cross an execution boundary (`crossinline`).
- If all lambda parameters of an `inline` function are marked `noinline`, the compiler warns that making the function `inline` serves no purpose — the function itself would be inlined but gains no benefit since none of its lambdas avoid allocation.
- In practice, `noinline` is rare. Most inline functions exist precisely to avoid lambda allocation. The typical use case is an inline function with *multiple* lambda parameters where one needs inlining (the hot path) and another needs to be stored (a callback for later).
