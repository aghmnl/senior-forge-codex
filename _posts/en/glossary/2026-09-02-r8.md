## The Theory (The What)

**R8** is the default code shrinker, obfuscator, and optimizer for Android builds. It replaces [ProGuard]({{ "/en/glossary/proguard/" | relative_url }}) in the Android Gradle Plugin and runs at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}) during release builds. R8 performs three operations: **shrinking** (removing unused classes, methods, and fields), **obfuscation** (renaming identifiers to short names like `a`, `b`, `c`), and **optimization** (inlining methods, removing dead branches, merging classes). The result is a smaller, faster APK.

## The Senior Nuance

- **R8 and [runtime reflection]({{ "/en/glossary/runtime-reflection/" | relative_url }}) conflict**: R8 removes code it considers unused. If code is accessed only via reflection (Gson field names, Retrofit model classes), R8 doesn't see the reference and strips it. This is why libraries that use reflection require keep rules in `proguard-rules.pro`.
- **Keep rules**: `-keep class com.example.Model { *; }` prevents R8 from shrinking or renaming a class. `-keepnames` preserves names but allows shrinking. Senior developers write precise keep rules — blanket `keep` rules defeat the purpose of R8 by preserving everything.
- **[Annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}) is R8-friendly**: [Dagger]({{ "/en/glossary/dagger/" | relative_url }})/[Hilt]({{ "/en/glossary/hilt/" | relative_url }}) and [Room]({{ "/en/glossary/room/" | relative_url }}) generate code at compile time, so R8 can see all the references and safely shrink the rest. This is a key advantage of annotation processing over reflection.
- **Debugging**: R8 produces a `mapping.txt` file that maps obfuscated names back to originals. Upload it to Google Play Console or Firebase Crashlytics to decode [stack traces]({{ "/en/glossary/stack-trace/" | relative_url }}) from release builds.
- **Full mode**: R8 full mode (default since AGP 8.0) applies more aggressive optimizations than compatibility mode. It may remove more code — test your release build thoroughly, especially around serialization and reflection patterns.
