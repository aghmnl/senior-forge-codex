## The Theory (The What)

**Room** is Android's Jetpack persistence library that provides a compile-time verified abstraction layer over SQLite. It uses [annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}) to generate the boilerplate code for database operations: you define `@Entity` data classes, `@Dao` interfaces with SQL queries, and a `@Database` abstract class — Room generates the `_Impl` classes that do the actual SQLite work.

```kotlin
// From FollowApp Suite — MyTasksDatabase.kt
@Database(
    entities = [TaskEntity::class, LabelEntity::class, LabelOptionEntity::class, PresetEntity::class],
    version = 2,
    exportSchema = true
)
abstract class MyTasksDatabase : RoomDatabase() {
    abstract fun taskDao(): TaskDao
    abstract fun labelDao(): LabelDao
    abstract fun labelOptionDao(): LabelOptionDao
    abstract fun presetDao(): PresetDao
    abstract fun backupDao(): BackupDao
}
```

## The Senior Nuance

- **Compile-time SQL verification**: Room validates SQL queries at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}) against the schema. A typo in a column name or a type mismatch is a build error, not a [runtime]({{ "/en/glossary/runtime/" | relative_url }}) crash — unlike raw SQLite or `ContentValues`.
- **Flow and [coroutines]({{ "/en/glossary/coroutines/" | relative_url }}) integration**: Room DAOs can return `Flow<List<T>>` for observable queries (the Flow re-emits whenever the table changes) and [suspend functions]({{ "/en/glossary/suspend-functions/" | relative_url }}) for one-shot operations. This eliminates [callback]({{ "/en/glossary/callbacks/" | relative_url }})-based patterns for database access.
- **Migrations**: `Room.databaseBuilder(...).addMigrations(MIGRATION_1_2)` handles schema evolution. Senior developers write migrations explicitly (not `fallbackToDestructiveMigration()`) and test them with Room's `MigrationTestHelper` to prevent data loss in production.
- **[Runtime reflection]({{ "/en/glossary/runtime-reflection/" | relative_url }}) at initialization**: `Room.databaseBuilder(ctx, MyDb::class.java)` uses `::class.java` to locate the generated `_Impl` class. This is a lightweight reflection entry point — Room itself uses [annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}), not reflection, for the heavy lifting.
- **Testing**: Room's `inMemoryDatabaseBuilder` creates a database that lives only in RAM — fast, isolated, and automatically cleaned up. The FAS codebase uses this pattern in `@Before` setup methods for integration tests.
