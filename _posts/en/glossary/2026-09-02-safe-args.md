## The Theory (The What)

**Safe Args** is a Gradle plugin for the [Navigation Component]({{ "/en/glossary/navigation-component/" | relative_url }}) that generates [type-safe]({{ "/en/glossary/type-safety/" | relative_url }}) classes for navigating between destinations and passing arguments. Instead of manually constructing `Bundle` objects with string keys, Safe Args generates `Directions` classes (for navigation actions) and `Args` classes (for reading arguments at the destination). This is a form of [annotation processing]({{ "/en/glossary/annotation-processing/" | relative_url }}) — code generated at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}).

## The Senior Nuance

- **Compile-time argument checking**: If you add a required argument to a destination in the navigation graph, every navigation action that targets it must provide that argument — or the build fails. This catches missing arguments at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}) instead of [runtime]({{ "/en/glossary/runtime/" | relative_url }}).
- **Directions pattern**: `FragmentADirections.actionFragmentAToFragmentB(userId = 42)` generates a type-safe `NavDirections` object. The action name, argument types, and defaults are all verified at build time.
- **Compose migration**: In Jetpack Compose navigation, Safe Args is being replaced by route-based navigation with Kotlin serialization (`@Serializable data class ProfileRoute(val id: Int)`). The concept is the same — type-safe argument passing — but the mechanism shifts from XML graph + codegen to Kotlin serialization.
- **Supported types**: Safe Args handles primitives, strings, enums, `Parcelable`, and `Serializable`. Custom types must implement one of these interfaces.
- **Deep link arguments**: Safe Args also generates type-safe parsing for deep link URI arguments, ensuring consistency between in-app navigation and external deep links.
