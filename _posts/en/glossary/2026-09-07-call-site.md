## The Theory (The What)

The **call site** is the exact place in the [source code]({{ "/en/glossary/source-code/" | relative_url }}) where a function is invoked — as opposed to the *declaration site*, where it is defined. The distinction matters because several Kotlin features behave differently depending on which side of that line the compiler is working on.

```kotlin
// From FollowApp Suite — SelectableListScaffold.kt
// DECLARATION SITE: T is an unknown placeholder here.
fun <T> SelectableListScaffold(
    items: List<T>,
    itemKey: (T) -> String,
    // ...
) { /* ... */ }
```

```kotlin
// From FollowApp Suite — TrashScreen.kt
// CALL SITE: T is resolved to a concrete type here.
SelectableListScaffold(
    items = uiState.visibleTasks,   // T inferred from this argument
    itemKey = { it.id },
    // ...
)
```

At the declaration site the compiler only knows the constraints on `T` (its [upper bound]({{ "/en/glossary/upper-bound/" | relative_url }})). At the call site it knows the actual type, because [Type Inference]({{ "/en/glossary/type-inference/" | relative_url }}) has resolved it from the arguments.

## The Senior Nuance

- **[Inline functions]({{ "/en/glossary/inline-functions/" | relative_url }}) are copied into the call site.** The compiler does not emit a normal method invocation; it pastes the function body where the call was written. This is the mechanism that makes [`reified`]({{ "/en/glossary/reified/" | relative_url }}) possible — the concrete type argument is known at the call site, so it can be baked into the [bytecode]({{ "/en/glossary/bytecode/" | relative_url }}) there. It is also the source of [code bloat]({{ "/en/glossary/code-bloat/" | relative_url }}): one large `inline` function used in fifty places produces fifty copies.
- **Declaration-site vs use-site variance.** Kotlin lets you declare [variance]({{ "/en/glossary/variance/" | relative_url }}) once on the class (`interface Producer<out T>`), so every call site inherits the promise. Java has no such option: its wildcards (`List<? extends T>`) are *use-site* variance, restated at each call site. This is one of the concrete ergonomic wins of Kotlin's type system.
- **Non-local returns.** Inside an [inline function]({{ "/en/glossary/inline-functions/" | relative_url }})'s [lambda]({{ "/en/glossary/lambdas/" | relative_url }}), a bare `return` exits the *enclosing* function at the call site, not just the lambda — precisely because the lambda body is compiled into that call site. [`crossinline`]({{ "/en/glossary/crossinline/" | relative_url }}) is what forbids this when the lambda will be executed elsewhere.
- **Diagnosing generics starts at the call site.** When a generic API fails to compile, the error is usually reported at the call site but *caused* by the declaration — a missing `out`, or a type parameter used in both an *in* and an *out* position. Read the declaration's positions before rewriting the call.
