## The Theory (The What)

A **raw type** is a generic Java class used without its type argument — `List` instead of `List<String>`. Raw types exist only for backwards compatibility with pre-generics Java (before Java 5) and **Kotlin has none**: the language never lets you drop the type argument.

```java
// Java — legal, and dangerous
List raw = new ArrayList<String>();
raw.add(42);                  // unchecked warning only
String s = (String) raw.get(0);   // ClassCastException at runtime
```

Kotlin's replacement is the [star projection]({{ "/en/glossary/star-projection/" | relative_url }}):

```kotlin
// Not found in FAS — standalone example
fun sizeOf(list: List<*>): Int = list.size   // reads fine
// list.add(42)                              // does not compile
```

## The Senior Nuance

- **Raw types erase the compiler's memory; `<*>` does not.** With a raw type the compiler forgets a type argument was ever there and permits unchecked writes, deferring the failure to a [`ClassCastException`]({{ "/en/glossary/class-cast-exception/" | relative_url }}) somewhere unrelated. With [star projection]({{ "/en/glossary/star-projection/" | relative_url }}) the compiler still knows some concrete type exists and simply forbids operations that would need to know it.
- **They still reach Kotlin through Java interop.** A Java library method returning a raw `List` surfaces in Kotlin as a *platform type* (`List<!>`), which suppresses both nullability and type-argument checking. A Senior annotates or wraps these at the boundary rather than letting a platform type propagate into the [data layer]({{ "/en/glossary/data-layer/" | relative_url }}).
- **Raw types are a consequence of [Type Erasure]({{ "/en/glossary/type-erasure/" | relative_url }}), not the cause.** Erasure is why raw types can exist at all at [Runtime]({{ "/en/glossary/runtime/" | relative_url }}); Java's decision to keep accepting them at [compile time]({{ "/en/glossary/compile-time/" | relative_url }}) is the separate, deliberate compatibility choice Kotlin declined to repeat.
- **"Unchecked cast" warnings are the modern form of the same hazard.** `value as List<String>` in Kotlin compiles with a warning precisely because erasure makes it unverifiable. Treat that warning as an error in review: it is a raw type by another name.
