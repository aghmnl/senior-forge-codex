## The Theory (The What)

**`buildMap { }`** is the [`Map`]({{ "/en/glossary/maps/" | relative_url }}) counterpart of [`buildList`]({{ "/en/glossary/build-list/" | relative_url }}): an [inline]({{ "/en/glossary/inline-functions/" | relative_url }}) [builder function]({{ "/en/glossary/builder-functions/" | relative_url }}) whose receiver is a [`MutableMap`]({{ "/en/glossary/mutable-map/" | relative_url }}), returning a read-only `Map`.

```kotlin
// Not found in FAS — standalone example
fun activeFilters(state: TasksUiState): Map<String, LabelFilterState> = buildMap {
    state.labelFilters.forEach { (name, value) ->
        if (value != LabelFilterState.OFF) put(name, value)
    }
    state.doneFilter?.let { put("done", it) }
}
```

## The Senior Nuance

- It replaces the `mutableMapOf` + populate + return pattern where the map is genuinely built once, and it removes the possibility of the mutable reference escaping. FollowApp Suite still uses the explicit `mutableMapOf` form where the accumulation logic is long enough to want a named variable — both are correct; `buildMap` is the tighter one.
- Prefer it over `mapOf(*pairs.toTypedArray())` or `associate { }` when entries are conditional: `associate` allocates a `Pair` per element, `buildMap` calls [`put`]({{ "/en/glossary/put/" | relative_url }}) directly.
- Like every builder, the result is frozen on return, so it is safe to publish into shared state without a [defensive copy]({{ "/en/glossary/defensive-copy/" | relative_url }}).
