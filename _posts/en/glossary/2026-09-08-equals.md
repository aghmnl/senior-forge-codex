## The Theory (The What)

**`equals`** defines *structural* equality — what `==` calls in Kotlin, as opposed to `===`, which compares references. `Any.equals` is identity by default; a [data class]({{ "/en/01-kotlin-core/data-classes/" | relative_url }}) generates it from the [primary constructor]({{ "/en/glossary/primary-constructor/" | relative_url }}) properties, together with a matching `hashCode`.

```kotlin
// From FollowApp Suite — TasksScreen.kt
// Structural comparison decides whether to re-sync the whole list or patch one row
uiState.activeTasks.forEachIndexed { i, task ->
    if (localTasks[i] != task) localTasks[i] = task
}
```

## The Senior Nuance

- `equals` and `hashCode` are one contract: equal objects must have equal hash codes, or a [`Set`]({{ "/en/glossary/sets/" | relative_url }}) and [`Map`]({{ "/en/glossary/maps/" | relative_url }}) built from them break silently — [`contains`]({{ "/en/glossary/contains/" | relative_url }}) returns `false` for an element that is physically present.
- Collection properties inherit the collection's semantics: a [`List`]({{ "/en/glossary/list/" | relative_url }}) compares element-wise *and in order*, a [`Set`]({{ "/en/glossary/sets/" | relative_url }}) ignores order. Choosing the wrong one changes when two states are "equal" — and therefore when Compose recomposes.
- Compose skips recomposition when the previous and next state compare equal, so a [state holder]({{ "/en/glossary/state-holder/" | relative_url }}) that mutates a list in place and re-emits the same reference is `==` to itself and renders nothing. That is the deep reason UI state must be built from [immutable]({{ "/en/glossary/immutability/" | relative_url }}) values.
- A property that is not part of identity (a timestamp, a cached field) declared in the [primary constructor]({{ "/en/glossary/primary-constructor/" | relative_url }}) silently joins `equals`. Move it into the body instead.
