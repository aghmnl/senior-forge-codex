## The Theory (The What)

**`listOf(vararg elements)`** creates a read-only [`List`]({{ "/en/glossary/list/" | relative_url }}). Unlike an upcast [`MutableList`]({{ "/en/glossary/mutable-list/" | relative_url }}), the instance it returns is genuinely unmodifiable — an `Arrays.asList` wrapper for several elements, a shared singleton for `listOf()` and a `SingletonList` for one.

```kotlin
// From FollowApp Suite — TasksViewModel.kt
listOf(
    TaskGroup(chipLabel = NOT_DONE_CHIP_KEY, isAssigned = true, tasks = notDone),
    TaskGroup(chipLabel = DONE_CHIP_KEY, isAssigned = false, tasks = done)
)
```

## The Senior Nuance

- `emptyList()` allocates nothing — it returns a shared singleton — so it is the right default for a UI state property. `listOf()` with no arguments resolves to the same object.
- It is the one place where "read-only" and [immutable]({{ "/en/glossary/immutability/" | relative_url }}) genuinely coincide in the [standard library]({{ "/en/glossary/standard-library/" | relative_url }}), which is why a `listOf` literal is safe to share across threads without a [defensive copy]({{ "/en/glossary/defensive-copy/" | relative_url }}).
- `listOfNotNull(a, b, c)` filters nulls while building. When construction is conditional rather than nullable, [`buildList`]({{ "/en/glossary/build-list/" | relative_url }}) reads better than a chain of `takeIf`.
