## The Theory (The What)

**`mapOf(vararg pairs)`** creates a read-only [`Map`]({{ "/en/glossary/maps/" | relative_url }}) from `Pair` values written with the `to` infix function. It is backed by a `LinkedHashMap`, so iteration follows insertion order; `emptyMap()` is a shared singleton.

```kotlin
// From FollowApp Suite — TasksViewModel.kt
val labelFilters = mapOf(label to LabelFilterState.INCLUDE)
val scaleFilters = mapOf(scaleName to ScaleFilterState.Include(setOf(optionValue)))
```

## The Senior Nuance

- Each `a to b` allocates a `Pair`, and `mapOf` allocates the vararg array on top. In a [hot loop]({{ "/en/glossary/hot-loops/" | relative_url }}) prefer [`buildMap`]({{ "/en/glossary/build-map/" | relative_url }}), which puts entries directly.
- A `Map` keyed by domain name (`scaleName to filterState`) is how FollowApp Suite keeps its filter state open-ended without a class per label — the [data layer]({{ "/en/glossary/data-layer/" | relative_url }}) can add a label and the UI state needs no new field.
- `Map<K, out V>` is [covariant]({{ "/en/glossary/covariance/" | relative_url }}) in the value, so a `Map<String, Task>` can be passed where a `Map<String, Any>` is expected. Keys stay [invariant]({{ "/en/glossary/invariance/" | relative_url }}) because they are hashed.
