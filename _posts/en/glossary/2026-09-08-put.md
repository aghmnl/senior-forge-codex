## The Theory (The What)

**`put(key, value)`** inserts or replaces an entry in a [`MutableMap`]({{ "/en/glossary/mutable-map/" | relative_url }}) and returns the *previous* value for that key, or `null`. Kotlin's indexed-assignment [syntax sugar]({{ "/en/glossary/syntax-sugar/" | relative_url }}) `map[key] = value` compiles to exactly this call, discarding the return.

```kotlin
// From FollowApp Suite — GetLabelReferenceCounts.kt
refCounts[label] = (refCounts[label] ?: 0) + 1   // compiles to put(...)
```

## The Senior Nuance

- The discarded return value is a free "was this key already here?" check. `if (index.put(id, row) != null) { /* duplicate */ }` costs one lookup where `containsKey` plus `put` costs two.
- `getOrPut(key) { default }` is the idiomatic accumulator: it computes the default only on a miss. Note it is not atomic and it treats a stored `null` as a miss — a real trap for a `MutableMap<K, V?>`.
- A key whose `hashCode` changes after insertion is unreachable: `put` filed it in one bucket and lookups now search another. Map keys must be [immutable]({{ "/en/glossary/immutability/" | relative_url }}) — `String` or a value-like [data class]({{ "/en/01-kotlin-core/data-classes/" | relative_url }}).
