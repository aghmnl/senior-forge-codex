## The Theory (The What)

**`remove`** deletes an element from a `MutableCollection` by value and returns whether anything was removed. [`MutableList`]({{ "/en/glossary/mutable-list/" | relative_url }}) also has `removeAt(index)`, which returns the removed element, and `removeAll { }` for predicate-based deletion. On a [`MutableMap`]({{ "/en/glossary/mutable-map/" | relative_url }}), `remove(key)` returns the previous value or `null`.

```kotlin
// From FollowApp Suite — DragToReorder.kt
itemCoords.entries.removeAll { it.key != key && it.value === coords }
```

## The Senior Nuance

- `remove(element)` compares with [`equals`]({{ "/en/glossary/equals/" | relative_url }}), not identity — on a list of [data classes]({{ "/en/01-kotlin-core/data-classes/" | relative_url }}) it deletes the *first structurally equal* element, which is rarely the one you meant. Prefer `removeAt` or `removeAll { it.id == id }`.
- `removeAll { }` on a list is one pass; a loop of `remove` calls is `O(n²)` and, if it runs while iterating, throws `ConcurrentModificationException`. Removing through `entries` (as above) is the supported way to mutate a map during traversal.
- On an [`ArrayList`]({{ "/en/glossary/arraylist/" | relative_url }}), removal shifts the tail: `removeAt(0)` is `O(n)`, `removeAt(lastIndex)` is `O(1)`.
