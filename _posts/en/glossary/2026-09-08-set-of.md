## The Theory (The What)

**`setOf(vararg elements)`** creates a read-only [`Set`]({{ "/en/glossary/sets/" | relative_url }}), backed by a `LinkedHashSet`, so duplicates are dropped and iteration order is insertion order. `emptySet()` returns a shared singleton.

```kotlin
// From FollowApp Suite — TasksViewModel.kt
filters = setOf(TaskStatus.ACTIVE)

// From FollowApp Suite — ArchiveViewModel.kt
_uiState.update { it.copy(selectedTaskIds = setOf(taskId)) }
```

## The Senior Nuance

- Declaring a UI state field as `Set<String>` rather than `List<String>` states an invariant the type system then enforces: selection ids cannot repeat. In FollowApp Suite that is what makes selection toggling expressible as `+`/`-` set algebra returning new values.
- `Set` equality ignores order, so two states holding the same ids in different orders compare equal — which is exactly the behaviour you want for a Compose [`equals`]({{ "/en/glossary/equals/" | relative_url }}) check, and exactly the wrong behaviour for an ordered list of rows.
- Elements must have stable `hashCode`/[`equals`]({{ "/en/glossary/equals/" | relative_url }}). `setOf` on mutable objects builds a structure whose [`contains`]({{ "/en/glossary/contains/" | relative_url }}) silently stops working after the first [mutation]({{ "/en/glossary/mutation/" | relative_url }}).
