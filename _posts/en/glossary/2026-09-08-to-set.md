## The Theory (The What)

**`toSet()`** returns a new read-only [`Set`]({{ "/en/glossary/sets/" | relative_url }}) with the receiver's distinct elements, preserving insertion order via `LinkedHashSet`. It both deduplicates and converts an `O(n)` [`contains`]({{ "/en/glossary/contains/" | relative_url }}) into an `O(1)` one.

```kotlin
// From FollowApp Suite — BulkSelection.kt
val groupSet = groupTaskIds.toSet()
return if (groupSet.all { it in selectedTaskIds }) {
    selectedTaskIds - groupSet
} else {
    selectedTaskIds + groupSet
}
```

## The Senior Nuance

- Hoisting `toSet()` out of a loop is the single highest-value performance fix in list-heavy Android code: `O(n·m)` becomes `O(n + m)` for the cost of one allocation.
- Inside the loop it is the opposite — `list.toSet()` evaluated per element rebuilds the whole structure every iteration and is strictly worse than the linear scan it was meant to replace.
- `toSet()` also normalises for comparison: two lists with the same elements in different orders have equal `toSet()` results. Use it deliberately, since it discards both order and duplicates.
