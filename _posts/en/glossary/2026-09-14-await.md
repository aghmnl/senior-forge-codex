## The Theory (The What)

**`await()`** is the [suspend function]({{ "/en/glossary/suspend-functions/" | relative_url }}) on a [`Deferred`]({{ "/en/glossary/deferred/" | relative_url }}) that suspends the caller until the `async` block completes, then returns its value or rethrows its exception. It is a [suspension point]({{ "/en/glossary/suspension-point/" | relative_url }}), so it participates in [cancellation]({{ "/en/glossary/cooperative-cancellation/" | relative_url }}): cancelling the awaiting coroutine cancels the `Deferred` too (inside structured scopes). `awaitAll()` does the same for a list.

The same name appears in `kotlinx-coroutines-play-services` — `Task<T>.await()` — where it bridges a Google Play Services callback into a suspend call.

## The Senior Nuance

- **`await` is where the exception surfaces.** Put the `try/catch` around the `await()`, not around the `async { }` — the block's failure is deferred until someone asks for the result.
- **Awaiting sequentially defeats the purpose.** `async { a() }.await(); async { b() }.await()` runs `a` then `b`. Start both, *then* await both.
- **An un-awaited `Deferred` is a silent bug.** Its failure is never observed. If you do not need the value, it should have been a [`launch`]({{ "/en/glossary/launch/" | relative_url }}).
