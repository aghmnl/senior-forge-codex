## The Theory (The What)

A **`Deferred<T>`** is a [`Job`]({{ "/en/glossary/job/" | relative_url }}) that also carries a result: the handle returned by `async { }`. It represents a value that will exist later. [`await()`]({{ "/en/glossary/await/" | relative_url }}) suspends until the value is ready and returns it — or rethrows the exception the block failed with.

```kotlin
// Not found in FAS — standalone example
val (labels, presets) = coroutineScope {
    val l = async { labelRepository.getAll() }
    val p = async { presetRepository.getAll() }
    l.await() to p.await()
}
```

## The Senior Nuance

- **Exceptions are stored, not propagated to the handler.** A failing `async` block keeps its exception inside the `Deferred` until `await()`; a [`CoroutineExceptionHandler`]({{ "/en/glossary/coroutine-exception-handler/" | relative_url }}) never sees it. Wrap the `await`, not the `async`.
- **Never `async` without `await`.** If you do not need the value, use [`launch`]({{ "/en/glossary/launch/" | relative_url }}); an un-awaited `Deferred` silently swallows its failure.
- **Parallel decomposition belongs inside a [`coroutineScope`]({{ "/en/glossary/coroutine-scope-builder/" | relative_url }})**, so a failure in one branch cancels the other and the caller sees a single exception.
- It is the coroutine analogue of a `Future`/`Promise`, with structured cancellation attached.
