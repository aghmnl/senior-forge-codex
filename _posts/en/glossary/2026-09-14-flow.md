## The Theory (The What)

A **`Flow<T>`** is Kotlin's asynchronous stream: a cold sequence of values produced on demand inside a [coroutine]({{ "/en/glossary/coroutines/" | relative_url }}). Nothing runs until a terminal operator such as [`collect`]({{ "/en/glossary/collect/" | relative_url }}) is called, and each collector gets its own execution of the producer. Operators (`map`, `filter`, `combine`, `flatMapLatest`) build a pipeline the same way [collection operators]({{ "/en/glossary/collection-operators/" | relative_url }}) do, but over time instead of over a list.

```kotlin
// From FollowApp Suite — LabelDao.kt
@Query("SELECT * FROM labels ORDER BY name ASC")
fun getLabelsStream(): Flow<List<LabelEntity>>
```

Room returns a `Flow` for observable queries: it re-emits whenever the table changes, for as long as someone collects.

## The Senior Nuance

- **Cold by default, hot by conversion.** A plain `Flow` restarts per collector; [`StateFlow`]({{ "/en/glossary/stateflow/" | relative_url }}), `SharedFlow`, `stateIn`/`shareIn` turn it into a shared, always-running stream.
- **`Flow` vs suspend function is the API split**: one-shot value → `suspend fun`; stream of values → `Flow`. A repository interface that mixes them up forces callers to poll or to collect-and-cancel.
- **It runs on the collector's [dispatcher]({{ "/en/glossary/dispatcher/" | relative_url }})** unless `flowOn` moves the upstream. `withContext` inside a flow builder is forbidden — that is what `flowOn` is for.
- **Flow is `out T`-covariant**: it only produces, so a `Flow<Task>` is a `Flow<Any>`.
- See [Context & Dispatchers]({{ "/en/02-coroutines-flow/context-dispatchers/" | relative_url }}).
