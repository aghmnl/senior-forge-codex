## The Theory (The What)

A **`Job`** is the lifecycle handle of a [coroutine]({{ "/en/glossary/coroutines/" | relative_url }}) — the element of its [`CoroutineContext`]({{ "/en/glossary/coroutine-context/" | relative_url }}) that knows whether it is active, completing, cancelled or completed, and that links it to its parent and children. `launch` returns one. Calling `cancel()` on it requests [cooperative cancellation]({{ "/en/glossary/cooperative-cancellation/" | relative_url }}): the coroutine will throw [`CancellationException`]({{ "/en/glossary/cancellation-exception/" | relative_url }}) at its next [suspension point]({{ "/en/glossary/suspension-point/" | relative_url }}).

```kotlin
// From FollowApp Suite — TasksViewModel.kt
private var subtasksJob: Job? = null

fun onFabClicked() {
    subtasksJob?.cancel()
    subtasksJob = null
    // ...
}
```

Holding the `Job` of a long-running collector is how a ViewModel replaces one subscription with another: cancel the old, launch the new, keep the handle.

## The Senior Nuance

- **Jobs form a tree.** A child's failure cancels the parent, which cancels every sibling; a parent's cancellation cancels every child. That is the default (`Job`) behaviour and it is what makes structured concurrency safe. [`SupervisorJob`]({{ "/en/glossary/supervisor-job/" | relative_url }}) cuts the upward edge.
- **`join()` waits, `cancel()` does not.** `cancel()` returns immediately; the coroutine stops at its next suspension point. `cancelAndJoin()` is the version that waits for it to actually finish — use it before reusing a resource the coroutine held.
- **`isActive` is the flag cooperative code checks.** A CPU loop with `while (isActive)` is cancellable; the same loop without it runs to completion after `cancel()`.
- **Never pass a fresh `Job()` into `launch`.** It detaches the coroutine from the scope's tree; the scope's cancellation no longer reaches it. If you need supervision, use `supervisorScope` or a `SupervisorJob` in the *scope*, not in the `launch` call.
