## The Theory (The What)

**`launch { }`** is the coroutine builder that starts a new [coroutine]({{ "/en/glossary/coroutines/" | relative_url }}) in a [`CoroutineScope`]({{ "/en/glossary/coroutine-scope/" | relative_url }}) and returns its [`Job`]({{ "/en/glossary/job/" | relative_url }}) without waiting for it — fire-and-forget. The new coroutine inherits the scope's [`CoroutineContext`]({{ "/en/glossary/coroutine-context/" | relative_url }}); anything passed as an argument (`launch(Dispatchers.IO)`) is merged on top.

```kotlin
// From FollowApp Suite — TasksViewModel.kt
viewModelScope.launch(Dispatchers.IO) {
    val snapshot = runCatching { tasksViewPreferences.read() }.getOrNull()
    // ...
}
```

Compare `async`, which returns a [`Deferred`]({{ "/en/glossary/deferred/" | relative_url }}) you [`await`]({{ "/en/glossary/await/" | relative_url }}) for a result.

## The Senior Nuance

- **Use `launch` for side effects, `async` for values.** Writing to the database, sending analytics, updating state: `launch`. Computing two things concurrently and combining them: `async` + `await`.
- **An uncaught exception in `launch` propagates to the parent `Job`.** With a plain `Job` it cancels the scope; with a [`SupervisorJob`]({{ "/en/glossary/supervisor-job/" | relative_url }}) it goes to the [`CoroutineExceptionHandler`]({{ "/en/glossary/coroutine-exception-handler/" | relative_url }}) or crashes. Handle errors inside the block.
- **On [`Main.immediate`]({{ "/en/glossary/dispatchers-main-immediate/" | relative_url }}) it runs synchronously up to the first suspension** — statements after the `launch` call see the coroutine's first effects. On plain `Main` it is always deferred.
- **Never `launch` from a suspend function into an outer scope you were handed.** That escapes structured concurrency; use the [`coroutineScope`]({{ "/en/glossary/coroutine-scope-builder/" | relative_url }}) builder instead.
- See [Context & Dispatchers]({{ "/en/02-coroutines-flow/context-dispatchers/" | relative_url }}).
