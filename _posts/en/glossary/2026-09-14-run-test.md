## The Theory (The What)

**`runTest { }`** (from `kotlinx-coroutines-test`) is the test builder for suspend code. It runs the block in a `TestScope` backed by a [`TestDispatcher`]({{ "/en/glossary/test-dispatcher/" | relative_url }}) with a virtual clock: `delay(5_000)` completes instantly, `advanceUntilIdle()` drains pending work deterministically, and the test fails if any coroutine launched in the scope is still active at the end. It replaces [`runBlocking`]({{ "/en/glossary/run-blocking/" | relative_url }}) in tests.

```kotlin
// Not found in FAS — standalone example
@Test
fun `export writes the bundle`() = runTest {
    val manager = BackupManager(io = StandardTestDispatcher(testScheduler), /* fakes */)
    val result = manager.exportTo(uri)
    assertTrue(result.isSuccess)
}
```

## The Senior Nuance

- **It only controls dispatchers it knows about.** Code that hops to a hard-coded `Dispatchers.IO` leaves the virtual clock; the test races. Inject dispatchers ([`@IoDispatcher`]({{ "/en/glossary/io-dispatcher/" | relative_url }})) and pass `StandardTestDispatcher(testScheduler)`.
- **`Main` still needs [`setMain`]({{ "/en/glossary/set-main/" | relative_url }}).** `runTest` does not install a Main dispatcher; ViewModel tests combine both.
- **Leaked coroutines fail the test** ("UncompletedCoroutinesError") — a feature: an un-cancelled collector in production would leak too.
- **`runBlocking` in tests hides timing bugs** because real delays run in real time. `runTest` makes them explicit.
- See [Context & Dispatchers]({{ "/en/02-coroutines-flow/context-dispatchers/" | relative_url }}).
