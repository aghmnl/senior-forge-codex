## The Theory (The What)

**`Dispatchers.setMain(dispatcher)`** (from `kotlinx-coroutines-test`) replaces the global [`Dispatchers.Main`]({{ "/en/glossary/dispatchers-main/" | relative_url }}) for the duration of a JVM unit test, where no Android [`Looper`]({{ "/en/glossary/looper/" | relative_url }}) exists. Anything that uses `Main` — [`viewModelScope`]({{ "/en/glossary/viewmodel-scope/" | relative_url }}), `Main.immediate`, `lifecycleScope` — then runs on the supplied [`TestDispatcher`]({{ "/en/glossary/test-dispatcher/" | relative_url }}). `resetMain()` restores the original.

```kotlin
// From FollowApp Suite — SettingsViewModelTest.kt
@Before
fun setup() {
    Dispatchers.setMain(testDispatcher)
}

@After
fun tearDown() {
    Dispatchers.resetMain()
}
```

## The Senior Nuance

- **It is process-global state.** Forgetting `resetMain()` leaks the test dispatcher into the next test class. Pair them in `@Before`/`@After`, or use a JUnit rule that does both.
- **It only reaches `Main`.** A `withContext(Dispatchers.IO)` inside the class under test still hops to a real thread the test cannot control. That gap is what dispatcher injection ([`@IoDispatcher`]({{ "/en/glossary/io-dispatcher/" | relative_url }})) closes.
- **Without it, `Dispatchers.Main` throws** ("Module with the Main dispatcher is missing") the first time a ViewModel launches in a plain JVM test.
