## The Theory (The What)

**`async { }`** is the coroutine builder that starts a child coroutine and returns a [`Deferred<T>`]({{ "/en/glossary/deferred/" | relative_url }}) — a [`Job`]({{ "/en/glossary/job/" | relative_url }}) that also carries a result. Like [`launch`]({{ "/en/glossary/launch/" | relative_url }}), it attaches the new coroutine to the [`Job`]({{ "/en/glossary/job/" | relative_url }}) of the [`CoroutineScope`]({{ "/en/glossary/coroutine-scope/" | relative_url }}) it is called on, so it is fully structured: cancelling the parent cancels it, and the parent waits for it. Unlike `launch`, its block's value is retrievable with [`await()`]({{ "/en/glossary/await/" | relative_url }}).

```kotlin
// Not found in FAS — standalone example
suspend fun loadDashboard(): Dashboard = coroutineScope {
    val header = async { api.header() }
    val items = async { api.items() }
    Dashboard(header.await(), items.await())
}
```

## The Senior Nuance

- **Its failure has two paths.** An exception in an `async` block is stored in the [`Deferred`]({{ "/en/glossary/deferred/" | relative_url }}) and rethrown at [`await()`]({{ "/en/glossary/await/" | relative_url }}) — *and* it fails the parent [`Job`]({{ "/en/glossary/job/" | relative_url }}) immediately, unless that parent is a supervisor. So inside a plain [`coroutineScope`]({{ "/en/glossary/coroutine-scope-builder/" | relative_url }}) a `try/catch` around `await()` cannot save the sibling: by then it is already cancelled. Per-child recovery needs [`supervisorScope`]({{ "/en/glossary/supervisor-scope/" | relative_url }}).
- **`async` is for values; `launch` is for effects.** An `async` whose result nobody awaits is a `launch` with a hidden exception.
- **Start both, then await both.** `async { a() }.await(); async { b() }.await()` is sequential.
