## The Theory (The What)

**`scrollBy(value)`** is the [suspend]({{ "/en/glossary/suspend-functions/" | relative_url }}) extension on Compose's `ScrollableState` (and therefore `LazyListState`) that scrolls by a pixel delta and suspends until the scroll is applied. Like every scroll mutation in Compose — `animateScrollTo`, `scrollToItem`, a user drag — it runs under a `MutatorMutex`: only one scroll may own the state at a time, and a new one **cancels the one in flight** with a [`CancellationException`]({{ "/en/glossary/cancellation-exception/" | relative_url }}).

```kotlin
// From FollowApp Suite — TasksScreen.kt
try {
    lazyListState.scrollBy(direction * autoScrollStep)
} catch (e: CancellationException) {
    // Preempted by another scroll mutation (e.g. the
    // reorder re-anchor); keep scrolling unless the
    // effect itself was cancelled
    if (!isActive) throw e
}
```

## The Senior Nuance

- **Its cancellation is not your cancellation.** Being preempted by another mutation throws inside your coroutine while your [`Job`]({{ "/en/glossary/job/" | relative_url }}) is still alive. That is why the code above checks [`isActive`]({{ "/en/glossary/is-active/" | relative_url }}) before deciding whether to rethrow.
- **It is a suspend call, so it needs a coroutine.** From a click handler use `rememberCoroutineScope().launch { }`; from an effect, [`LaunchedEffect`]({{ "/en/glossary/launched-effect/" | relative_url }}).
- **Return value is the consumed delta.** At a scroll limit it returns less than requested; check `canScrollForward` / `canScrollBackward` first to avoid churn.
- See [Structured Concurrency]({{ "/en/02-coroutines-flow/structured-concurrency/" | relative_url }}).
