## The Theory (The What)

**`awaitAll()`** is the extension on `Collection<Deferred<T>>` (and the top-level `awaitAll(vararg)`) that suspends until *every* [`Deferred`]({{ "/en/glossary/deferred/" | relative_url }}) completes and returns their values as a `List<T>` in the same order. It is the idiomatic way to fan out N [`async`]({{ "/en/glossary/async/" | relative_url }}) calls and gather the results. It fails fast: the first `Deferred` that fails makes `awaitAll()` rethrow immediately, without waiting for the rest.

```kotlin
// Not found in FAS — standalone example
suspend fun anyHasChildren(ids: List<String>): Boolean = coroutineScope {
    ids.map { id -> async { countActiveSubtasksUseCase(id) > 0 } }
        .awaitAll()
        .any { it }
}
```

## The Senior Nuance

- **`map { async }.awaitAll()` vs `map { await() }`.** `deferreds.map { it.await() }` gives the same list but waits *sequentially*: a failure in the third is not seen until the first two are done. `awaitAll()` observes all of them at once.
- **Fail-fast is only half the story.** Inside a plain [`coroutineScope`]({{ "/en/glossary/coroutine-scope-builder/" | relative_url }}) the failing `async` already cancelled its siblings via the parent. `awaitAll()`'s early rethrow just gets you out of the wait sooner.
- **Do not use it for `Deferred<Unit>`.** N parallel effects with no result are [`launch`]({{ "/en/glossary/launch/" | relative_url }}) inside `coroutineScope`, which waits for all children by itself.
- See [Launch vs Async/Await]({{ "/en/02-coroutines-flow/launch-vs-async-await/" | relative_url }}).
