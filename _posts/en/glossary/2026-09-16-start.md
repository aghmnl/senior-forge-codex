## The Theory (The What)

**`Job.start()`** explicitly starts a coroutine that was created with [`CoroutineStart.LAZY`]({{ "/en/glossary/coroutine-start/" | relative_url }}). It returns `true` if the call actually started it, `false` if it was already running or finished. On a coroutine created with the default start mode it is a no-op. It does *not* suspend and does *not* wait — it only flips the coroutine from *New* to *Active*.

```kotlin
// Not found in FAS — standalone example
val warmup = launch(start = CoroutineStart.LAZY) { preloadCache() }
if (userOptedIn) warmup.start() else warmup.cancel()   // decide later, never leave it New
```

## The Senior Nuance

- **`start()` is fire; `join()` is wait; `await()` is both plus a value.** On a lazy [`Deferred`]({{ "/en/glossary/deferred/" | relative_url }}), `await()` already starts it, so `start()` is only needed when you want it running *before* you are ready to wait.
- **The `Boolean` result is a cheap "did I win the race".** Two callers may `start()` the same lazy job; only one gets `true`.
- **A lazy job you never `start()`, `join()` or `cancel()` keeps its parent alive.** See [`CoroutineStart`]({{ "/en/glossary/coroutine-start/" | relative_url }}).
