## The Theory (The What)

**OkHttp** is Square's HTTP client — the engine under [Retrofit]({{ "/en/glossary/retrofit/" | relative_url }}) and, since Android 4.4, the implementation behind the platform's `HttpURLConnection`. It manages connection pooling, HTTP/2 multiplexing, transparent gzip, response caching and interceptors. Requests run either synchronously (`call.execute()`, which **blocks the calling thread**) or asynchronously (`call.enqueue(callback)`, which runs on OkHttp's own `Dispatcher` [thread pool]({{ "/en/glossary/thread-pool/" | relative_url }}) and reports through a [callback]({{ "/en/glossary/callbacks/" | relative_url }})).

```kotlin
// Not found in FAS — standalone example
val client = OkHttpClient.Builder()
    .addInterceptor(HttpLoggingInterceptor())
    .connectTimeout(10, TimeUnit.SECONDS)
    .build()
```

## The Senior Nuance

- **`execute()` on Main is a `NetworkOnMainThreadException`.** The platform throws before the socket even opens. `enqueue()` or a Retrofit `suspend` call is the main-safe path.
- **OkHttp's dispatcher is not `Dispatchers.IO`.** It is a separate pool with its own limits (64 requests, 5 per host). A coroutine awaiting a Retrofit call is suspended, not parked on IO.
- **One `OkHttpClient` per app.** Each instance owns a connection pool and thread pool; creating them per request throws both away.
