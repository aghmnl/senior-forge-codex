## The Theory (The What)

**`check(condition) { "message" }`** validates an *invariant of the object's state*: if the condition is false it throws `IllegalStateException`. It is the sibling of [`require`]({{ "/en/glossary/require/" | relative_url }}) — same shape, different exception, different meaning: `require` says the caller's arguments are wrong, `check` says the object itself is in a state it should never be in. Like `require`, it declares a [contract]({{ "/en/glossary/contract/" | relative_url }}), so the compiler applies a [Smart Casts]({{ "/en/01-kotlin-core/smart-casts/" | relative_url }}) smart cast after it: `check(connection is Open)` makes `connection` an `Open` for the rest of the function.

```kotlin
// Not found in FAS — standalone example
class BillingConnector {
    private var state: ConnectionState = ConnectionState.Idle

    fun launchPurchase(activity: Activity) {
        check(state is ConnectionState.Connected) { "launchPurchase called before connect(), state=$state" }
        // `state` is smart-cast to Connected here
        state.client.launchBillingFlow(activity, params())
    }
}
```

## The Senior Nuance

- **`check` replaces `!!` on state.** `check(x != null)` followed by plain `x` is the honest version of `x!!`: same crash on violation, but with a message that names the broken [invariant]({{ "/en/glossary/invariant/" | relative_url }}) instead of an anonymous [`NullPointerException`]({{ "/en/glossary/null-pointer-exception/" | relative_url }}).
- **Choose the exception by who is at fault.** If a test hits an `IllegalStateException`, the bug is inside the class; an `IllegalArgumentException` points at the caller. This split is worth more than the check itself.
- **`error("msg")` for the unreachable branch.** When a `when` arm should be impossible, `error()` (which throws `IllegalStateException`) documents that better than a silent `else`.
