## The Theory (The What)

A **getter** is the accessor that runs every time a property is read. Kotlin generates a default one that returns the [backing field]({{ "/en/glossary/backing-field/" | relative_url }}); you can replace it with a custom body: `val isEmpty: Boolean get() = items.isEmpty()`. A property with a custom getter may have no backing field at all — it is a computed value. That matters for [Smart Casts]({{ "/en/01-kotlin-core/smart-casts/" | relative_url }}): the compiler only smart-casts properties whose getter is the default one, because a custom getter can return something different on every call.

```kotlin
// Not found in FAS — standalone example
class Session(private val tokenProvider: () -> String?) {
    val token: String?
        get() = tokenProvider()          // custom getter: recomputed on every read

    fun length(): Int {
        // Does not compile: `token` has a custom getter, so the compiler cannot smart-cast it
        // return if (token != null) token.length else 0
        val t = token                    // read once, then the local val is stable
        return t?.length ?: 0
    }
}
```

## The Senior Nuance

- **Custom getter = unstable value.** Two consecutive reads of `token` above may differ. A smart cast would be unsound, so the compiler refuses it even though the property is a [`val`]({{ "/en/glossary/val/" | relative_url }}). Read once into a local.
- **Keep getters cheap and pure.** A getter that does I/O, allocates or has side effects turns every property read into a hidden call; readers assume `x.foo` costs nothing.
- **Getters across module boundaries are always unstable.** A public `val` in another module could gain a custom getter in a later version, so the compiler never smart-casts it.
- See [Smart Casts]({{ "/en/01-kotlin-core/smart-casts/" | relative_url }}).
