## The Theory (The What)

**`require(condition) { "message" }`** validates a *precondition on arguments*: if the condition is false it throws `IllegalArgumentException` with the lazily-built message. It is the stdlib's [assertion]({{ "/en/glossary/assertion/" | relative_url }}) for "the caller passed something invalid", as opposed to [`check`]({{ "/en/glossary/check/" | relative_url }}), which guards the object's own state. It carries a [contract]({{ "/en/glossary/contract/" | relative_url }}) — `returns() implies condition` — so the compiler applies a [Smart Casts]({{ "/en/01-kotlin-core/smart-casts/" | relative_url }}) smart cast after the call: `require(x is Foo)` makes `x` a `Foo` from then on.

```kotlin
// Not found in FAS — standalone example
fun schedule(task: Task, delayMs: Long) {
    require(delayMs >= 0) { "delayMs must be >= 0, was $delayMs" }
    require(task.state is TaskState.Pending) { "task ${task.id} is not pending" }
    // ...
}
```

## The Senior Nuance

- **Argument vs state decides `require` vs `check`.** `IllegalArgumentException` tells the reader "you called me wrong"; `IllegalStateException` tells them "I was in the wrong state". Picking the right one makes the [stack trace]({{ "/en/glossary/stack-trace/" | relative_url }}) self-explanatory.
- **Always pass the message lambda.** It is evaluated only on failure, so it costs nothing on the happy path and explains which [invariant]({{ "/en/glossary/invariant/" | relative_url }}) broke.
- **`require` at the boundary, not everywhere.** Validate once where untrusted input enters (public API, parsing); inside, rely on the type system.
- See [Smart Casts]({{ "/en/01-kotlin-core/smart-casts/" | relative_url }}).
