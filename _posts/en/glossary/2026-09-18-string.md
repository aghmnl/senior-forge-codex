## The Theory (The What)

**`String`** is Kotlin's immutable sequence of characters, mapped to `java.lang.String` on the [JVM]({{ "/en/glossary/jvm/" | relative_url }}). Every operation that "changes" a string (`plus`, `replace`, `trim`) returns a new instance; the original never mutates, which makes strings safe to share across threads and to use as map keys. In the type system `String` is the non-nullable form and `String?` the nullable one — the pair used throughout [Null Safety: Elvis & Safe Calls]({{ "/en/01-kotlin-core/null-safety-elvis-safe-calls/" | relative_url }}) to illustrate that nullability is part of the type, not a property of the value.

```kotlin
// Not found in FAS — standalone example
val name: String = "forge"
val upper = name.uppercase()     // new String; `name` is unchanged
val maybe: String? = null
val len = maybe?.length ?: 0     // String? must be unwrapped explicitly
```

## The Senior Nuance

- **Immutable means concatenation allocates.** Building a string in a loop with `+` creates one new object per iteration; use `buildString { }` / `StringBuilder` in hot paths.
- **`==` is `equals`, `===` is identity.** Kotlin's `==` compares content, so the Java pitfall of comparing strings by reference does not exist — but interning still does, so never rely on `===` for strings.
- **`String!` from Java is a [platform type]({{ "/en/glossary/platform-types/" | relative_url }}).** A Java method returning `String` without annotations may still hand you `null`; declare the Kotlin side as `String?` or annotate the Java side.
