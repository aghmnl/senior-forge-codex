## The Theory (The What)

**`throw`** raises an exception: `throw IllegalStateException("reason")`. In Kotlin it is an *expression* of type `Nothing`, not a statement — which is why it can sit on the right-hand side of the [Elvis operator]({{ "/en/glossary/elvis-operator/" | relative_url }}) (`value ?: throw ...`), inside a `when` branch, or as the body of a single-expression function. `Nothing` is a subtype of every type, so the compiler knows execution never continues past a `throw` and applies a [Smart Casts]({{ "/en/01-kotlin-core/smart-casts/" | relative_url }}) smart cast to the value on the left. [Null Safety: Elvis & Safe Calls]({{ "/en/01-kotlin-core/null-safety-elvis-safe-calls/" | relative_url }}) uses `?: throw IllegalStateException(...)` as the honest replacement for `!!`.

```kotlin
// Not found in FAS — standalone example
// `throw` is an expression: it fits where a value is expected
val details = productDetails ?: throw IllegalStateException("details not loaded")
// details: ProductDetails (non-null) from here on

fun fail(msg: String): Nothing = throw IllegalStateException(msg)   // Nothing-returning helper
```

## The Senior Nuance

- **`throw` as expression is what makes `?: throw` work.** Because its type is `Nothing`, `T? ?: Nothing` collapses to `T`; the same trick powers `?: return` and `?: continue`.
- **Throw with a message, and the right type.** [`IllegalStateException`]({{ "/en/glossary/illegal-state-exception/" | relative_url }}) for broken state, `IllegalArgumentException` for bad input, a domain exception when the caller is expected to recover. A bare `throw Exception()` gives the reader nothing.
- **Unchecked everywhere.** Kotlin has no checked exceptions; a `throw` is invisible in the signature. Document it in KDoc, or prefer a `Result`/sealed return when failure is a normal outcome, not a bug.
