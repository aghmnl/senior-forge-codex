## The Theory (The What)

**`val`** declares a read-only reference: it is assigned once and cannot be reassigned. It is the default choice in Kotlin — every declaration starts as `val` and is promoted to [`var`]({{ "/en/glossary/var/" | relative_url }}) only with a reason. A `val` property gets a [getter]({{ "/en/glossary/getter/" | relative_url }}) but no setter. Read-only is not the same as [immutable]({{ "/en/glossary/immutability/" | relative_url }}): `val list = mutableListOf(1)` cannot be repointed, but its contents can still change. For the compiler, a `val` local or a `val` property without a custom getter is a *stable* value, which is what makes [Smart Casts]({{ "/en/01-kotlin-core/smart-casts/" | relative_url }}) smart casts possible after an [`is`]({{ "/en/glossary/is-operator/" | relative_url }}) or null check.

```kotlin
// From FollowApp Suite — RecurrenceCalculator.kt
// `until` is a val: after the null check it is smart-cast to Long for the rest of the expression
val until = (rule.end as? RecurrenceEnd.UntilDate)?.date
return if (until != null && candidate > until) null else candidate
```

## The Senior Nuance

- **`val` is what unlocks the smart cast.** The compiler can only narrow a type when it can prove the value did not change between the check and the use; a `val` with the default getter is that proof. Capturing a [`var`]({{ "/en/glossary/var/" | relative_url }}) into a local `val` is the idiomatic fix when a smart cast is refused.
- **A `val` with a custom getter is not stable.** `val now: Long get() = System.currentTimeMillis()` is a `val`, yet every read may differ, so the compiler will not smart-cast it. Neither will an `open` `val`, which a subclass could override.
- **Read-only reference, not frozen object.** Pair `val` with read-only types (`List`, not `MutableList`) when you actually want immutability.
