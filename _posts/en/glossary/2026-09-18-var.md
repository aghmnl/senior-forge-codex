## The Theory (The What)

**`var`** declares a mutable reference that can be reassigned any number of times. A `var` property gets both a [getter]({{ "/en/glossary/getter/" | relative_url }}) and a setter. Because its value may change between two reads — from another [thread]({{ "/en/glossary/thread/" | relative_url }}), a [callback]({{ "/en/glossary/callbacks/" | relative_url }}), or a setter with side effects — the compiler treats a `var` property as *unstable* and refuses to [Smart Casts]({{ "/en/01-kotlin-core/smart-casts/" | relative_url }}) smart-cast it after an [`is`]({{ "/en/glossary/is-operator/" | relative_url }}) or null check. A local `var` can still be smart-cast as long as it is not captured and modified in a lambda.

```kotlin
// Not found in FAS — standalone example
class Repo {
    var cache: Any? = null

    // Does not compile: `cache` is a var property and could change after the check
    // fun size() = if (cache is List<*>) cache.size else 0

    // Idiomatic fix: capture into a local val, then the smart cast applies
    fun size(): Int {
        val snapshot = cache
        return if (snapshot is List<*>) snapshot.size else 0
    }
}
```

## The Senior Nuance

- **The refusal is a safety guarantee, not a compiler limitation.** If the compiler smart-cast a `var` property, a reassignment between check and use would surface as a [`ClassCastException`]({{ "/en/glossary/class-cast-exception/" | relative_url }}) or [`NullPointerException`]({{ "/en/glossary/null-pointer-exception/" | relative_url }}) at [runtime]({{ "/en/glossary/runtime/" | relative_url }}). The type system only makes promises it can enforce.
- **Snapshot into a `val`.** `val snapshot = cache` freezes what you read; every later use refers to the same object, so the smart cast is sound.
- **Fewer `var`s, fewer bugs.** Each `var` is a piece of state the reader has to track; prefer [`val`]({{ "/en/glossary/val/" | relative_url }}) plus a new value (`copy`, `update { }`) over in-place mutation.
