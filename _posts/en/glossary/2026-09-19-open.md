## The Theory (The What)

**`open`** is the modifier that makes a class inheritable or a member overridable. Kotlin inverts Java's default: every class and member is `final` unless marked `open`, so extension is opt-in and deliberate. A [Data Classes: copy, equals, toString]({{ "/en/01-kotlin-core/data-classes/" | relative_url }}) **cannot** be `open` — nor `abstract`, `sealed` or `inner` — because its generated [`equals`]({{ "/en/glossary/equals/" | relative_url }}), `hashCode` and [`copy`]({{ "/en/glossary/copy/" | relative_url }}) are derived from *its own* [primary constructor]({{ "/en/glossary/primary-constructor/" | relative_url }}) and a subclass would break them.

```kotlin
// Not found in FAS — standalone example
open class Repository(open val name: String) {      // inheritable
    open fun load() { }                             // overridable
}

class TaskRepository(name: String) : Repository(name) {
    override fun load() { }
}

// data class Admin(...) : User(...)   // does not compile: a data class cannot be open
```

## The Senior Nuance

- **`final` by default is a design stance.** Inheritance is a contract you must maintain forever; Kotlin makes you declare that intent. Prefer composition or an interface, and reach for `open` when polymorphism is genuinely the design.
- **`open` also affects the compiler's reasoning.** An `open val` can be overridden by a subclass with a custom [getter]({{ "/en/glossary/getter/" | relative_url }}), so it is not stable and will not [smart-cast]({{ "/en/01-kotlin-core/smart-casts/" | relative_url }}).
- **Mocking libraries are not a reason to open a class.** Depend on interfaces, or use a test-only fake; `allopen`/`mockk` workarounds leak test concerns into production design.
