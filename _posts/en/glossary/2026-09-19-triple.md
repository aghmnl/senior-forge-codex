## The Theory (The What)

**`Triple<A, B, C>`** is a stdlib [Data Classes: copy, equals, toString]({{ "/en/01-kotlin-core/data-classes/" | relative_url }}) holding three values — `first`, `second`, `third` — with `Pair` as its two-value sibling. Being a data class it comes with [`equals`]({{ "/en/glossary/equals/" | relative_url }}), `hashCode`, `toString`, [`copy`]({{ "/en/glossary/copy/" | relative_url }}) and [`componentN`]({{ "/en/glossary/component-n/" | relative_url }}), which is what lets you write `val (a, b, c) = triple`. It exists for the throwaway case: returning several values from a local computation without declaring a type for them.

```kotlin
// From FollowApp Suite — MyTasksApplication.kt
// Triple + destructuring to read three preferences at once
val (language, themeMode, contrastLevel) = runBlocking {
    Triple(
        languagePreferences.getLanguage().first(),
        themePreferences.getThemeMode().first(),
        themePreferences.getContrastLevel().first()
    )
}
```

## The Senior Nuance

- **`Triple` names positions, not meanings.** `first`/`second`/`third` carry no domain information, so a `Triple` that crosses a module or API boundary is a missed data class. Keep it local, where the destructuring is right next to the construction.
- **Three is the practical ceiling.** There is no `Quadruple`, deliberately: past three values, positional access stops being readable and a named data class is the answer.
- **Destructuring is positional.** Swapping two same-typed components of a `Triple` compiles and silently swaps the meaning at the call site — the usual [destructuring]({{ "/en/glossary/destructuring/" | relative_url }}) caveat.
