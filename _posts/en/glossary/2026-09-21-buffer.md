## The Theory (The What)

**`buffer(capacity)`** is the [`Flow`]({{ "/en/glossary/flow/" | relative_url }}) operator that decouples producer from collector: [upstream]({{ "/en/glossary/upstream/" | relative_url }}) emissions go into a channel and the producer keeps working while the [downstream]({{ "/en/glossary/downstream/" | relative_url }}) collector processes earlier values. Without it, [`emit`]({{ "/en/glossary/emit/" | relative_url }}) suspends until the collector is done. `flowOn` implies a buffer — crossing a dispatcher boundary needs a channel anyway — which is why [withContext vs flowOn]({{ "/en/02-coroutines-flow/with-context-vs-flow-on/" | relative_url }}) is not only a thread change but also a concurrency change.

```kotlin
// Not found in FAS — standalone example
// Without buffer: total time ≈ sum of producer and collector times
pages().collect { render(it) }

// With buffer: producer and collector overlap
pages().buffer().collect { render(it) }

// flowOn already buffers: no extra buffer() needed for the hop itself
pages().flowOn(Dispatchers.IO).collect { render(it) }
```

## The Senior Nuance

- **Buffering trades memory and staleness for throughput.** An unbounded buffer in front of a slow collector grows without limit; `conflate()` (keep the latest only) is usually the right choice for UI state.
- **`flowOn` buffers whether you want it or not.** Adding `flowOn` to a chain can change timing and ordering behaviour in tests even when the dispatcher is irrelevant — a common surprise.
- **Adjacent operators fuse.** `buffer()` next to `flowOn` or another `buffer` is merged by the runtime into a single channel with the widest capacity, so stacking them is not additive.
- See [withContext vs flowOn]({{ "/en/02-coroutines-flow/with-context-vs-flow-on/" | relative_url }}).
