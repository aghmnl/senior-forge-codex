## The Theory (The What)

**`emit(value)`** is the suspending function a [`Flow`]({{ "/en/glossary/flow/" | relative_url }}) builder calls to push a value to its collector. It suspends until the downstream [`collect`]({{ "/en/glossary/collect/" | relative_url }}) block has finished processing that value, which is what makes a cold flow backpressure-aware by default: a slow collector slows the producer. `emit` must be called from the builder's own coroutine — see [context preservation]({{ "/en/glossary/context-preservation/" | relative_url }}).

```kotlin
// Not found in FAS — standalone example
fun ticker(): Flow<Int> = flow {
    var i = 0
    while (true) {
        emit(i++)        // suspends until the collector has handled this value
        delay(1_000)
    }
}
```

## The Senior Nuance

- **`emit` is sequential and suspending — that is the whole backpressure model.** No queue builds up unless you ask for one with [`buffer`]({{ "/en/glossary/buffer/" | relative_url }}), `conflate` or a `flowOn` (which buffers as a side effect).
- **Never `emit` from another coroutine.** `launch { emit(x) }` or `withContext { emit(x) }` inside a `flow { }` throws at runtime; use `channelFlow` + `send` when emissions really come from elsewhere.
- **`emitAll` forwards another flow.** `emitAll(otherFlow)` is the idiomatic way to splice a flow into a builder without collecting it by hand.
- See [withContext vs flowOn]({{ "/en/02-coroutines-flow/with-context-vs-flow-on/" | relative_url }}).
