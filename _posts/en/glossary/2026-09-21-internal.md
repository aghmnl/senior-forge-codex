## The Theory (The What)

**`internal`** makes a declaration visible everywhere inside the **same module** — a Gradle module, in an Android project — and invisible outside it. It sits between [`private`]({{ "/en/glossary/private/" | relative_url }}) (file or class) and `public` (everything), and it is the modifier that makes a multi-module architecture real: a `:feature:tasks` module can expose three public entry points and keep the rest internal. For [Extension Functions]({{ "/en/01-kotlin-core/extension-functions/" | relative_url }}) it is the usual sweet spot.

```kotlin
// Not found in FAS — standalone example
// Visible across the :feature:orders module, invisible to :app and other features
internal fun Order.toUiModel(): OrderUiModel = OrderUiModel(id, total.format())

internal class OrderMapper       // implementation detail of the module
```

## The Senior Nuance

- **Module boundaries only exist if you mark them.** Without `internal`, every helper is public API and other modules will import it, which quietly turns a layered project into a ball of mud.
- **It is compile-time, per module — not per package.** Two Gradle modules that both declare an `internal` helper do not clash; two packages in the same module see each other's internals.
- **Java cannot honour it.** From Java the declaration is public with a mangled name, so `internal` protects you from Kotlin callers, not from Java ones.
- See [namespace]({{ "/en/glossary/namespace/" | relative_url }}) and [Extension Functions]({{ "/en/01-kotlin-core/extension-functions/" | relative_url }}).
