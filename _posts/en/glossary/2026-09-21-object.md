## The Theory (The What)

**`object`** declares a class and its single instance at once — Kotlin's built-in [singleton]({{ "/en/glossary/singleton/" | relative_url }}). The instance is created lazily and thread-safely on first access, and there is no constructor to call: `Off`, not `Off()`. It comes in three forms: a named declaration (`object Registry`), a [companion object]({{ "/en/glossary/companion-object/" | relative_url }}) (`companion object`), and an anonymous expression (`object : Listener { }`). Marking it `data` adds `toString`, `equals` and `hashCode` — see [Data Objects: Singleton & Memory Savings]({{ "/en/01-kotlin-core/data-objects/" | relative_url }}).

```kotlin
// From FollowApp Suite — FilterState.kt
sealed class ScaleFilterState {
    object Off : ScaleFilterState()                       // one instance, no state
    data class Include(val values: Set<String>) : ScaleFilterState()
    object Exclude : ScaleFilterState()
}
```

## The Senior Nuance

- **Its lifetime is the process, not a screen.** An `object` is initialised once and never released, so any state you put in it outlives every `Activity` and `ViewModel`. Holding a `Context` there is a permanent [memory leak]({{ "/en/glossary/memory-leaks/" | relative_url }}).
- **Lazy and thread-safe by construction.** The JVM class-initialisation lock guarantees it, so you never need a double-checked locking dance.
- **Not injectable, not swappable in tests.** An `object` is a hard dependency at the call site; prefer a class with [`@Singleton`]({{ "/en/glossary/singleton-scope/" | relative_url }}) when a fake is needed.
- See [Data Objects: Singleton & Memory Savings]({{ "/en/01-kotlin-core/data-objects/" | relative_url }}).
