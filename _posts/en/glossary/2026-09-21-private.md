## The Theory (The What)

**`private`** is the narrowest visibility modifier: a private top-level declaration is visible only inside its **file**, and a private class member only inside its **class**. It is Kotlin's default answer to "who should see this?" — start private and widen only when a caller genuinely needs it. An [Extension Functions]({{ "/en/01-kotlin-core/extension-functions/" | relative_url }}) cannot access the private members of the type it extends, because it compiles to a static method outside the class.

```kotlin
// Not found in FAS — standalone example
private fun String.toOrderId() = OrderId(this)   // only this file

class Repo {
    private val cache = mutableMapOf<String, Task>()   // only this class
}
```

## The Senior Nuance

- **Private is a promise you can still keep tomorrow.** Anything public is API: someone will depend on it and you will not be able to change it. Narrow visibility keeps refactoring cheap.
- **It is not a security boundary.** Reflection and the JVM can still reach it; `private` communicates intent to humans and the compiler, not to attackers.
- **Private top-level beats a nested `object` of helpers.** File-scoped helpers keep the [namespace]({{ "/en/glossary/namespace/" | relative_url }}) clean without inventing a container.
- See [`internal`]({{ "/en/glossary/internal/" | relative_url }}) and [Extension Functions]({{ "/en/01-kotlin-core/extension-functions/" | relative_url }}).
