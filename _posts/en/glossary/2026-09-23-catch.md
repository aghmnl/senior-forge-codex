## The Theory (The What)

**`catch`** is the [`Flow`]({{ "/en/glossary/flow/" | relative_url }}) operator that handles exceptions raised **upstream** of it: the builder and every operator declared above. It never sees a failure from the [downstream]({{ "/en/glossary/downstream/" | relative_url }}) — an exception inside the `collect` block is outside its reach. Inside the block, `it` is the [`Throwable`]({{ "/en/glossary/throwable/" | relative_url }}), and calling [`emit`]({{ "/en/glossary/emit/" | relative_url }}) turns the failure into a normal emission, which is how a fallback value reaches the collector. It rethrows [`CancellationException`]({{ "/en/glossary/cancellation-exception/" | relative_url }}) automatically, so a cancelled flow stays cancelled.

```kotlin
// De FollowApp Suite — LabelsListViewModel.kt
.catch { e ->
    Log.e(TAG, "Error loading labels", e)
    _uiState.update { it.copy(isLoading = false, errorMessageRes = e.toUserMessage()) }
}
.collect { /* ... */ }
```

## The Senior Nuance

- **Position is the API, as with `flowOn`.** A `catch` written above an operator does not protect it. Put it below everything whose failures you mean to handle, and above nothing you want to keep transparent.
- **It cannot reach the `collect` block.** Move risky consumer work into an [`onEach`]({{ "/en/glossary/on-each/" | relative_url }}) above the `catch`, or give the block its own [`try/catch`]({{ "/en/glossary/try-catch/" | relative_url }}).
- **Logging alone is not handling.** A `catch` that only logs leaves the UI on a spinner; move the [state holder]({{ "/en/glossary/state-holder/" | relative_url }}) into an error state.
- **It respects [exception transparency]({{ "/en/glossary/exception-transparency/" | relative_url }}).** A producer must not catch its own emissions; that is what this operator is for.
