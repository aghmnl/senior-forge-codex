## The Theory (The What)

**`onEach`** is an intermediate [`Flow`]({{ "/en/glossary/flow/" | relative_url }}) operator that runs a side effect for each value and passes it through unchanged. It is the declarative counterpart of a `collect` body: same code, but it sits *inside* the chain, so it can be placed above a [`catch`]({{ "/en/glossary/catch/" | relative_url }}) and have its failures handled by that operator — which a `collect` block, being [downstream]({{ "/en/glossary/downstream/" | relative_url }}), cannot.

```kotlin
// Not found in FAS — standalone example
// A failure in the mapping IS covered, because onEach is upstream of catch
repository.tasks()
    .onEach { cache.write(it) }
    .catch { e -> _uiState.update { it.toError(e) } }
    .collect { _uiState.value = it }
```

## The Senior Nuance

- **It is how you make consumer-side work catchable.** Move the risky part from the `collect` block into an `onEach` above the `catch`, and the operator covers it.
- **It does not start the flow.** `onEach` is intermediate and lazy, so a chain that ends in `onEach` with no terminal operator runs nothing — a classic silent no-op. Pair it with `launchIn(scope)` when you want it to be the whole consumer.
- **Use it for effects, not transformations.** If you are producing a new value, that is `map`; `onEach` returning something is a smell, since its result is discarded.
