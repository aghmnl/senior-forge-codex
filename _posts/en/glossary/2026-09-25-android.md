## The Theory (The What)

**Android** is Google's operating system for phones, tablets, TVs, watches and cars, built on the Linux kernel. Apps are written mainly in [Kotlin]({{ "/en/glossary/kotlin/" | relative_url }}), compiled to DEX bytecode and run on the [Android Runtime (ART)]({{ "/en/glossary/android-runtime/" | relative_url }}). The platform gives each app a process and a set of components managed by the system — `Activity`, `Service`, [BroadcastReceiver]({{ "/en/glossary/broadcast-receiver/" | relative_url }}) and `ContentProvider` — whose [lifecycle]({{ "/en/glossary/lifecycle/" | relative_url }}) the system drives, not the app.

```kotlin
// Not found in FAS — standalone example
// The system, not the app, decides when these callbacks run
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)   // may be a re-creation after rotation
        setContent { App() }
    }
}
```

## The Senior Nuance

- **The system owns the lifecycle.** A rotation destroys and recreates the `Activity`; low memory can kill the whole process while the app is in the background. Most Android architecture (ViewModels, saved state, [lifecycle-aware]({{ "/en/glossary/lifecycle-aware/" | relative_url }}) collection) exists to survive decisions the app does not make.
- **One [main thread]({{ "/en/glossary/main-thread/" | relative_url }}) draws the UI.** Blocking it freezes the screen and, after a few seconds, produces an [ANR]({{ "/en/glossary/anr/" | relative_url }}). That constraint is why [coroutines]({{ "/en/glossary/coroutines/" | relative_url }}) and dispatchers matter so much on Android.
- **API levels are a compatibility contract.** `minSdk` decides which devices can install the app; `targetSdk` decides which behavior changes the system applies to it. Raising `targetSdk` is a migration, not a version bump.
