## The Theory (The What)

**`stateIn(scope, started, initialValue)`** turns a cold [Flow]({{ "/en/glossary/flow/" | relative_url }}) into a [StateFlow]({{ "/en/glossary/stateflow/" | relative_url }}). It launches **one** collection of the [upstream]({{ "/en/glossary/upstream/" | relative_url }}) in `scope` and shares its latest value with every subscriber, so three screens observing the result cost one query instead of three. `started` decides when that collection runs: `SharingStarted.Eagerly` (immediately, forever), `Lazily` (at the first subscriber, forever) or [WhileSubscribed]({{ "/en/glossary/while-subscribed/" | relative_url }}) (only while someone is collecting). A suspending overload, `stateIn(scope)`, waits for the first value instead of taking an initial one.

```kotlin
// Not found in FAS — standalone example
val uiState: StateFlow<TasksUiState> = getActiveTasksUseCase()
    .map { tasks -> TasksUiState(tasks = tasks, isLoading = false) }
    .stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5_000),
        initialValue = TasksUiState(isLoading = true)
    )
```

## The Senior Nuance

- **It replaces the `init { launch { collect { _state.value = it } } }` pattern.** The state is declared as a transformation of its sources instead of being pushed from a side coroutine, and it only runs while it is needed.
- **The initial value is still a design decision.** It is what the UI shows until the upstream emits; `isLoading = true` is honest, an empty list is not.
- **Do not call it inside a function.** Every call creates a new shared collection. `fun state() = flow.stateIn(...)` called per recomposition or per screen creates many — it belongs in a property, created once.
- Its sibling `shareIn` produces a [SharedFlow]({{ "/en/glossary/sharedflow/" | relative_url }}) instead: no initial value, configurable replay.
