## The Theory (The What)

**Eager** means doing the work **right away**, when something is created, instead of waiting until the result is needed. Its opposite is **lazy**: postponing the work until the first time someone asks for it. In coroutines the distinction shows up in when a [Flow]({{ "/en/glossary/flow/" | relative_url }}) starts being collected: a [cold stream]({{ "/en/glossary/cold-stream/" | relative_url }}) is lazy by nature (nothing runs until someone collects), while `SharingStarted.Eagerly` or a `launch` in `init` start working immediately.

```kotlin
// From FollowApp Suite — SettingsViewModel.kt
// Eager: the collection starts as soon as the ViewModel is created,
// whether the screen is looking at it or not
init {
    viewModelScope.launch {
        getPremiumStatusUseCase()
            .collect { premium -> _uiState.update { it.copy(isPremium = premium) } }
    }
}
```

## The Senior Nuance

- **Eager trades resources for readiness.** The data is there before anyone asks, at the cost of doing work that may never be used.
- **Lazy trades a first-use delay for doing only what is needed.** Kotlin has lazy tools at several levels: [by lazy]({{ "/en/01-kotlin-core/lateinit-vs-lazy/" | relative_url }}) for properties, [Sequence]({{ "/en/glossary/sequences/" | relative_url }}) for collections, and cold flows for streams.
- **In Android UI state, lazy usually wins.** Work that runs only while a screen is visible, with [SharingStarted.WhileSubscribed]({{ "/en/glossary/sharing-started/" | relative_url }}), saves battery and data without making the app slower for the user.
