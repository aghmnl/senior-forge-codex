## The Theory (The What)

**`it`** is the **implicit name of the single parameter of a [lambda]({{ "/en/glossary/lambdas/" | relative_url }})**. When a lambda receives exactly one parameter and you do not name it, Kotlin lets you refer to it as `it`. `list.filter { it > 0 }` is the same as `list.filter { n -> n > 0 }`.

```kotlin
// From FollowApp Suite — TasksViewModel.kt
// `it` is the current state that update {} passes to the lambda
_uiState.update { it.copy(errorMessageRes = null) }

// From FollowApp Suite — TasksViewModel.kt
// Here `it` is each Boolean emitted by _restored
_restored.filter { it }
```

## The Senior Nuance

- **Name the parameter when `it` stops being obvious.** In short lambdas `it` reads well. In nested lambdas each one has its own `it`, and the inner one hides the outer one; naming them (`state ->`, `task ->`) avoids confusion.
- **In `update {}`, everything derived from `it` is atomic.** `it` is the value that `update` will compare before storing, so anything computed from it is protected; anything read outside the lambda is not.
