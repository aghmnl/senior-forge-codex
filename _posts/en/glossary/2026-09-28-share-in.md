## The Theory (The What)

**`shareIn(scope, started, replay)`** turns a cold [Flow]({{ "/en/glossary/flow/" | relative_url }}) into a [SharedFlow]({{ "/en/glossary/sharedflow/" | relative_url }}). It launches **one** collection of the [upstream]({{ "/en/glossary/upstream/" | relative_url }}) in `scope` and broadcasts its emissions to every subscriber, so several consumers share a single execution instead of each running their own. `started` decides when that collection runs (`SharingStarted.Eagerly`, `Lazily` or [WhileSubscribed]({{ "/en/glossary/while-subscribed/" | relative_url }})), and `replay` how many past values a new subscriber receives. It is the sibling of [stateIn]({{ "/en/glossary/state-in/" | relative_url }}), which produces a [StateFlow]({{ "/en/glossary/stateflow/" | relative_url }}) instead.

```kotlin
// Not found in FAS — standalone example
// One socket connection shared by every screen that needs live prices
val prices: SharedFlow<Price> = priceSocket.connect()      // cold: one connection per collector
    .shareIn(
        scope = applicationScope,
        started = SharingStarted.WhileSubscribed(5_000),
        replay = 1
    )
```

## The Senior Nuance

- **`shareIn` or `stateIn`?** `stateIn` when there is a meaningful current value and an initial value to show; `shareIn` when the stream has no "current value" semantics, or when equal consecutive values must still be delivered.
- **The scope is the lifetime of the shared upstream.** Sharing in `viewModelScope` ties it to one screen; sharing in an application-level scope shares it across screens but also keeps it alive as long as the app, so the `started` strategy matters.
- **Upstream errors do not reach subscribers.** An exception in the upstream fails the sharing coroutine in `scope` instead of being delivered to collectors, so [catch]({{ "/en/glossary/catch/" | relative_url }}) or [retry]({{ "/en/glossary/retry/" | relative_url }}) belongs **before** `shareIn`.
- **Create it once, as a property.** Calling `shareIn` inside a function creates a new shared collection per call and defeats the purpose.
