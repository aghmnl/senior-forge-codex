## The Theory (The What)

**`tryEmit(value)`** is the **non-suspending** way to put a value into a [MutableSharedFlow]({{ "/en/glossary/mutable-shared-flow/" | relative_url }}). It returns `true` if the value was accepted and `false` if it would have had to suspend, that is, when the buffer is full under the `SUSPEND` policy. It exists for code that cannot call a [suspend function]({{ "/en/glossary/suspend-functions/" | relative_url }}), such as [callbacks]({{ "/en/glossary/callbacks/" | relative_url }}), listeners and interceptors. Its suspending sibling is [emit]({{ "/en/glossary/emit/" | relative_url }}).

```kotlin
// Not found in FAS — standalone example
private val _clicks = MutableSharedFlow<Unit>(
    extraBufferCapacity = 1,
    onBufferOverflow = BufferOverflow.DROP_OLDEST
)

// A View listener cannot suspend: tryEmit is the bridge
button.setOnClickListener { _clicks.tryEmit(Unit) }
```

## The Senior Nuance

- **With the default configuration it always fails when someone is listening.** [`MutableSharedFlow<T>()`]({{ "/en/glossary/mutable-shared-flow/" | relative_url }}) has no buffer, so with at least one subscriber there is nowhere to put the value and `tryEmit` returns `false`. It needs `extraBufferCapacity` above zero, or a drop policy.
- **With no subscribers it returns `true` and the value may still be lost.** "Accepted" is not "delivered": with `replay = 0` and nobody collecting, the value is dropped, and `tryEmit` still reports success.
- **With a drop policy it never fails.** Under `DROP_OLDEST` or `DROP_LATEST` it always returns `true`, because overflow is resolved by discarding a value instead of suspending. Ignoring the returned `Boolean` is only safe in that configuration.
