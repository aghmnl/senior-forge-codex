## The Theory (The What)

**`close()`** tells a [Channel]({{ "/en/glossary/channel/" | relative_url }}) that **no more values are coming**. Values already in the buffer are still delivered; after that, a `for` loop over the channel ends normally. From then on, [send]({{ "/en/glossary/send/" | relative_url }}) throws an exception, and so does [receive]({{ "/en/glossary/receive/" | relative_url }}) once the channel is empty. It is the sender's job to call it.

```kotlin
// Not found in FAS — standalone example
val channel = Channel<Int>(Channel.BUFFERED)
launch {
    try {
        for (n in 1..3) channel.send(n)
    } finally {
        channel.close()            // also closes it if sending fails
    }
}
for (n in channel) println(n)      // 1, 2, 3, then the loop ends
```

## The Senior Nuance

- **Forgetting it leaves receivers waiting forever.** The loop never ends, the coroutine never finishes and its scope never completes. Calling it in `finally`, or using [produce]({{ "/en/glossary/produce/" | relative_url }}), avoids that.
- **`close()` is not `cancel()`.** Closing lets the receiver drain what is left; cancelling (from the receiving side) discards the remaining values right away.
