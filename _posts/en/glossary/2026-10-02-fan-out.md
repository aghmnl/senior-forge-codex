## The Theory (The What)

**Fan-out** is when **several consumers read from the same [Channel]({{ "/en/glossary/channel/" | relative_url }})**, and the values are **split between them**: each value goes to exactly one consumer, whichever is free. It is the usual way to spread work across a fixed number of workers. The opposite, several producers sending into one channel, is called **fan-in**.

```kotlin
// Not found in FAS — standalone example
val jobs = Channel<File>(Channel.UNLIMITED)
files.forEach { jobs.send(it) }
jobs.close()

repeat(3) {                        // three workers, one queue
    launch { for (file in jobs) upload(file) }
}
```

## The Senior Nuance

- **Fan-out limits concurrency for free.** With three workers, at most three uploads run at once, however many files are queued.
- **It is not broadcast.** If every consumer must see every value, the tool is a [SharedFlow]({{ "/en/glossary/sharedflow/" | relative_url }}), not a channel.
