## The Theory (The What)

A **listener** is an object (or a [lambda]({{ "/en/glossary/lambdas/" | relative_url }})) that you register with an API so that the API **calls you back** when something happens: a click, a purchase update, a new location. It is the most common shape of a [callback]({{ "/en/glossary/callbacks/" | relative_url }}) on Android. The code inside a listener runs when the event fires, usually on a thread the API chooses, and it is **not a coroutine**, so it cannot call suspend functions.

```kotlin
// From FollowApp Suite — BillingConnector.kt
// Play Billing reports purchase updates through a listener
private val purchasesUpdatedListener = PurchasesUpdatedListener { result, purchases ->
    onPurchasesUpdated(result, purchases)
}
```

## The Senior Nuance

- **Every listener that is registered must be unregistered.** A listener holds a reference to whatever it uses; one that is never removed keeps a screen, a `Context` or a ViewModel alive: a [memory leak]({{ "/en/glossary/memory-leaks/" | relative_url }}).
- **Bridging a listener to coroutines.** Since it cannot suspend, it publishes values with [trySend]({{ "/en/glossary/try-send/" | relative_url }}) (inside [callbackFlow]({{ "/en/glossary/callback-flow/" | relative_url }})) or by assigning a [MutableStateFlow]({{ "/en/glossary/mutable-state-flow/" | relative_url }}), or wraps a one-shot callback with [suspendCancellableCoroutine]({{ "/en/glossary/suspend-cancellable-coroutine/" | relative_url }}).
