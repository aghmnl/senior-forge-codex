## The Theory (The What)

**`receive()`** takes the next value out of a [Channel]({{ "/en/glossary/channel/" | relative_url }}). It is a [suspend function]({{ "/en/glossary/suspend-functions/" | relative_url }}): when the channel is empty, it **suspends** until someone [sends]({{ "/en/glossary/send/" | relative_url }}) a value. The coroutine that calls it is the channel's **receiver**, and each value is received by exactly one receiver. Calling it on a channel that is [closed]({{ "/en/glossary/close/" | relative_url }}) and empty throws an exception.

```kotlin
// Not found in FAS — standalone example
val first = channel.receive()      // suspends until a value arrives

// The usual way to receive everything: the loop calls receive for you
// and ends when the channel is closed and empty
for (value in channel) process(value)
```

## The Senior Nuance

- **Prefer the `for` loop over calling `receive()` by hand.** The loop ends cleanly when the channel closes; a manual `receive()` on a closed, empty channel throws.
- `receiveCatching()` returns a result instead of throwing, for code that needs to tell "closed" apart from a value.
