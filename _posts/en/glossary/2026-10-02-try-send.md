## The Theory (The What)

**`trySend(value)`** is the **non-suspending** way to put a value into a [Channel]({{ "/en/glossary/channel/" | relative_url }}). It never waits: if there is room, it adds the value; if not, it gives up. It returns a `ChannelResult` that says whether it worked. It exists for code that cannot call a suspend function, such as [callbacks]({{ "/en/glossary/callbacks/" | relative_url }}) and listeners, and it is how values are sent inside [callbackFlow]({{ "/en/glossary/callback-flow/" | relative_url }}). Its suspending sibling is [send]({{ "/en/glossary/send/" | relative_url }}).

```kotlin
// Not found in FAS — standalone example
val events = Channel<Click>(Channel.BUFFERED)

button.setOnClickListener {
    val result = events.trySend(Click)
    if (result.isFailure) Log.w(TAG, "Click dropped: buffer full or channel closed")
}
```

## The Senior Nuance

- **It can fail, and the failure is silent unless you check.** On a full buffer, a rendezvous channel with no receiver, or a closed channel, the value is not sent. Ignoring the result is only safe when losing a value is acceptable.
- It is the channel counterpart of [tryEmit]({{ "/en/glossary/try-emit/" | relative_url }}) on a `MutableSharedFlow`.
