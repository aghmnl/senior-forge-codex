## The Theory (The What)

An **API** (Application Programming Interface) is the set of functions, classes and rules a piece of software exposes so other code can use it without knowing how it works inside. The Android [SDK]({{ "/en/glossary/sdk/" | relative_url }}), a library like Play Billing, a backend reachable over HTTP and a module's public classes are all APIs.

## The Senior Nuance

- **The shape of an API decides how you consume it.** A [suspend function]({{ "/en/glossary/suspend-functions/" | relative_url }}), a [`Flow`]({{ "/en/glossary/flow/" | relative_url }}), a [callback]({{ "/en/glossary/callbacks/" | relative_url }}) or a [listener]({{ "/en/glossary/listener/" | relative_url }}) each need a different bridge into [coroutines]({{ "/en/glossary/coroutines/" | relative_url }}): [callback]({{ "/en/glossary/callbacks/" | relative_url }}) APIs are wrapped with [`suspendCancellableCoroutine`]({{ "/en/glossary/suspend-cancellable-coroutine/" | relative_url }}) (one value) or [`callbackFlow`]({{ "/en/glossary/callback-flow/" | relative_url }}) (many values).
- **Public API is a promise.** Everything a module exposes can be used by others, so it becomes hard to change; exposing less (read-only types, `internal`) keeps that promise small.
