## The Theory (The What)

**`debounce(timeout)`** is a [`Flow`]({{ "/en/glossary/flow/" | relative_url }}) operator that emits a value only after the upstream has been **quiet for `timeout`**. Each new value restarts the timer and discards the pending one, so a burst of values produces just the last of them. The last value is always emitted when the [flow]({{ "/en/glossary/flow/" | relative_url }}) completes.

```kotlin
// Not found in FAS — standalone example
queryFlow
    .debounce(300)                  // wait until the user stops typing
    .distinctUntilChanged()
    .collectLatest { search(it) }
```

## The Senior Nuance

- **The classic case is search-as-you-type**: one request when the user pauses, not one per keystroke.
- **It delays every value, including the first one.** For a button that must react instantly and then ignore repeated clicks, debounce is the wrong tool; that is throttling.
- **On a hot [event]({{ "/en/glossary/one-shot-event/" | relative_url }}) stream, debouncing loses [events]({{ "/en/glossary/one-shot-event/" | relative_url }}) on purpose.** Fine for text input, wrong for [events]({{ "/en/glossary/one-shot-event/" | relative_url }}) where each one matters.
