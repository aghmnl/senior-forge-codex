## The Theory (The What)

**`remember { }`** stores a value in the [composition]({{ "/en/glossary/composition/" | relative_url }}) the first time a composable runs and returns that same value on every [recomposition]({{ "/en/glossary/recomposition/" | relative_url }}), instead of computing it again. With keys, `remember(key1, key2) { }`, the value is recomputed only when one of the keys changes.

```kotlin
// Not found in FAS — standalone example
val pending = remember(tasks) { tasks.filter { !it.isCompleted } }
```

## The Senior Nuance

- **It survives [recomposition]({{ "/en/glossary/recomposition/" | relative_url }}), not configuration changes.** Rotation or process death clear it; `rememberSaveable` is the version that survives them.
- **Keys must cover every input.** Forgetting one means using a stale value when that input changes.
- **It also preserves identity**, which matters for [skipping]({{ "/en/glossary/skipping/" | relative_url }}): the same remembered [list]({{ "/en/glossary/list/" | relative_url }}) is the same instance on every [recomposition]({{ "/en/glossary/recomposition/" | relative_url }}).
- See [Recomposition & Stability]({{ "/en/03-jetpack-compose/recomposition-stability/" | relative_url }}).
