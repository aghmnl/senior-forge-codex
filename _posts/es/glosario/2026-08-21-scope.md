## The Theory (El Qué)

Un **scope** define la región de código donde un nombre (variable, función, clase) es visible y accesible. En Kotlin, los scopes se crean con bloques (`{}`), funciones, clases, archivos y módulos. Una variable declarada dentro de una rama `when` no es visible fuera de esa rama; una función private tiene scope limitado a su archivo o clase.

Los scopes tienen dos propósitos: controlan la **visibilidad** (quién puede ver este nombre) y el **tiempo de vida** (cuánto tiempo existe este valor). Cuando un scope termina, las variables locales se vuelven elegibles para el [garbage collector]({{ "/es/glosario/garbage-collector/" | relative_url }}).

## The Senior Nuance (El Matiz Senior)

- Las [scope functions]({{ "/es/01-kotlin-core/scope-functions/" | relative_url }}) de Kotlin (`let`, `run`, `with`, `apply`, `also`) toman su nombre de este concepto: crean un scope temporal donde el objeto de contexto es el foco principal.
- Los **coroutine scopes** (`viewModelScope`, `lifecycleScope`, `GlobalScope`) definen el tiempo de vida de las coroutines — cuando el scope se cancela, todas las coroutines dentro de él se cancelan. Entender esto es crítico para evitar memory leaks.
- En inyección de dependencias, los **scopes** (`@Singleton`, `@ActivityScoped`) determinan el tiempo de vida de las dependencias provistas. Un scope mismatch (inyectar un objeto con scope de Activity en un Singleton) es una fuente común de leaks.
- Los **modificadores de visibilidad** (`private`, `internal`, `protected`, `public`) son declaraciones de scope — controlan qué partes del código pueden acceder a un símbolo.
