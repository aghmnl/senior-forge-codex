## The Theory (El Qué)

Un **DSL** (Domain-Specific Language, Lenguaje Específico del Dominio) es un mini-lenguaje adaptado a un dominio de problema específico. En Kotlin, los DSLs se construyen usando lambdas con [receiver types]({{ "/es/glosario/receiver-type/" | relative_url }}), [extension functions]({{ "/es/glosario/extension-functions/" | relative_url }}) y sobrecarga de operadores. El resultado es código que se lee como una descripción declarativa en vez de instrucciones imperativas. Jetpack Compose, Gradle Kotlin DSL y Ktor routing son todos DSLs de Kotlin.

```kotlin
// De FollowApp Suite — BackupSerializer.kt
// apply {} como un builder DSL sobre JSONObject
private fun taskToJson(task: TaskEntity): JSONObject = JSONObject().apply {
    put("id", task.id)
    put("title", task.title)
    put("description", task.description)
    put("parentTaskId", task.parentTaskId)
    put("status", task.status)
    put("isCompleted", task.isCompleted)
}
```

```kotlin
// De FollowApp Suite — CsvExporter.kt
// buildString {} — un DSL de la stdlib para construir strings
fun serialize(tasks: List<TaskEntity>): String = buildString {
    append(COLUMNS.joinToString(","))
    append("\r\n")
    for (task in tasks) {
        append(rowFor(task).joinToString(",", transform = ::escape))
        append("\r\n")
    }
}
```

## The Senior Nuance (El Matiz Senior)

- La magia detrás de los DSLs de Kotlin es la lambda con receptor (`T.() -> Unit`). Dentro de la lambda, `this` es el objeto receptor, así que podés llamar sus métodos sin cualificación. `apply {}`, `buildString {}`, `buildList {}` todos usan este mecanismo.
- `@DslMarker` previene la fuga de scope en DSLs anidados. Sin él, las lambdas internas pueden accidentalmente llamar métodos de receptores exteriores. Compose usa `@LayoutScopeMarker` para asegurar que no puedas llamar `Modifier.weight()` de `Column` dentro de un `Row`.
- Un DSL bien diseñado es descubrible a través del autocompletado del IDE — el [receiver type]({{ "/es/glosario/receiver-type/" | relative_url }}) restringe qué métodos están disponibles, guiando al desarrollador. Es metaprogramación type-safe: el compilador valida la estructura del DSL, a diferencia de DSLs basados en strings (XML, YAML).
