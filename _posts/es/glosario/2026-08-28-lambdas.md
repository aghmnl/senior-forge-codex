## The Theory (El Qué)

Una **lambda** en Kotlin es un literal de función anónima — un bloque de código que puede pasarse como valor, almacenarse en una variable o usarse como argumento de funciones de orden superior. Las lambdas se encierran en llaves `{ }`, con los parámetros antes de la flecha `->`. Si una lambda es el último parámetro de una función, puede colocarse fuera de los paréntesis (trailing lambda syntax).

```kotlin
// De FollowApp Suite — TasksViewModel.kt
val tags = allLabels
    .filter { (label, _) -> label.type == LabelType.TAG }
    .flatMap { (_, options) -> options.map { it.label } }
    .distinct()
    .sorted()
```

## The Senior Nuance (El Matiz Senior)

- Las lambdas en Kotlin compilan a inner classes anónimas (u objetos `Function`) en la [JVM]({{ "/es/glosario/jvm/" | relative_url }}). Cada lambda no [inline]({{ "/es/glosario/inline-functions/" | relative_url }}) crea una allocation de objeto. En hot paths, esto importa — usá funciones de orden superior `inline` para eliminar este costo.
- Una lambda captura variables de su [scope]({{ "/es/glosario/scope/" | relative_url }}) contenedor. A diferencia de Java, las lambdas de Kotlin pueden capturar y *modificar* variables `var` — el compilador las envuelve en un objeto `Ref`. Esto es conveniente pero puede causar problemas sutiles en código concurrente.
- El [destructuring]({{ "/es/glosario/destructuring/" | relative_url }}) en parámetros de lambda (`.map { (key, value) -> ... }`) hace la iteración sobre [maps]({{ "/es/glosario/maps/" | relative_url }}) y pairs más limpia, pero recordá: el destructuring enlaza por posición, no por nombre.
