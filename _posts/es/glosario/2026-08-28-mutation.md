## The Theory (El Qué)

**Mutation** (mutación) significa cambiar el estado de un objeto después de que fue creado. En Kotlin, `var` declara una variable mutable (reasignable), mientras que `val` declara una referencia de solo lectura. Para colecciones, [`MutableList`]({{ "/es/glosario/mutable-list/" | relative_url }}), [`MutableMap`]({{ "/es/glosario/mutable-map/" | relative_url }}) y [`MutableSet`]({{ "/es/glosario/mutable-set/" | relative_url }}) exponen operaciones de mutación ([`add`]({{ "/es/glosario/add/" | relative_url }}), [`remove`]({{ "/es/glosario/remove/" | relative_url }}), [`put`]({{ "/es/glosario/put/" | relative_url }})), mientras que sus contrapartes de solo lectura ([`List`]({{ "/es/glosario/list/" | relative_url }}), [`Map`]({{ "/es/glosario/maps/" | relative_url }}), [`Set`]({{ "/es/glosario/sets/" | relative_url }})) no lo hacen.

```kotlin
// De FollowApp Suite — PresetMapper.kt
// Patrón construir-luego-exponer: mutar localmente, retornar inmutable
val result = mutableMapOf<String, LabelFilterState>()
obj.keys().forEach { key ->
    runCatching { LabelFilterState.valueOf(obj.getString(key)) }
        .onSuccess { result[key] = it }
}
return result  // retornado como Map — los llamadores ven solo lectura
```

## The Senior Nuance (El Matiz Senior)

- Las colecciones de solo lectura de Kotlin no son verdaderamente inmutables — son interfaces que ocultan los métodos de mutación, pero la instancia subyacente puede castearse a su contraparte mutable. Para inmutabilidad estructural, usá `kotlinx.collections.immutable` (`persistentListOf`, `persistentMapOf`).
- En arquitecturas de [flujo unidireccional]({{ "/es/glosario/unidirectional-data-flow/" | relative_url }}), evitar la mutación es la base: en vez de modificar el estado en el lugar, se crea un nuevo objeto de estado vía `copy()`. Esto hace que las [transiciones de estado]({{ "/es/glosario/state-transitions/" | relative_url }}) sean explícitas, rastreables y thread-safe.
- El patrón "construir mutable, exponer inmutable" (como en el ejemplo FAS) es Kotlin idiomático: usá un [`MutableMap`]({{ "/es/glosario/mutable-map/" | relative_url }}) internamente durante la construcción, luego retornalo como [`Map`]({{ "/es/glosario/maps/" | relative_url }}). Las funciones [`buildMap {}`]({{ "/es/glosario/build-map/" | relative_url }}), [`buildList {}`]({{ "/es/glosario/build-list/" | relative_url }}) y `buildSet {}` formalizan este patrón.

**Documentación oficial:** [Collection types: read-only vs mutable](https://kotlinlang.org/docs/collections-overview.html#collection-types)
