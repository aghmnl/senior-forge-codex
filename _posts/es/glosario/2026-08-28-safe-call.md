## La Teoría (El Qué)

El operador **safe call** (`?.`) accede a un miembro de un receptor nullable solo si el receptor no es null; de lo contrario, la expresión entera evalúa a `null`. Es uno de los mecanismos centrales de [null safety]({{ "/es/01-kotlin-core/null-safety-elvis-safe-calls/" | relative_url }}) de Kotlin y se puede encadenar: `user?.address?.city` retorna `null` si cualquier eslabón de la cadena es null, sin lanzar [NullPointerException]({{ "/es/glosario/null-pointer-exception/" | relative_url }}).

## El Matiz Senior

- Los safe calls se componen limpiamente con el operador Elvis (`?.` + `?:`) y con las [scope functions]({{ "/es/01-kotlin-core/scope-functions/" | relative_url }}) (`?.let { ... }`). La combinación `nullable?.let { use(it) } ?: fallback()` es el patrón idiomático en Kotlin para "hacer algo si está presente, caso contrario hacer otra cosa."
- Cada `?.` en una cadena introduce un punto potencial de propagación de `null`. Cadenas largas (`a?.b?.c?.d?.e`) pueden ocultar problemas estructurales — si existen cinco niveles de nullabilidad, el modelo de datos quizás necesite rediseñarse en lugar de más safe calls.
- A nivel de bytecode, `x?.method()` compila a un null check + llamada condicional. No hay penalización de rendimiento comparado con escribir el `if` manualmente — es puro [syntax sugar]({{ "/es/glosario/syntax-sugar/" | relative_url }}).
