## The Theory (El Qué)

Un **Set** en Kotlin es una colección no ordenada de elementos únicos. La biblioteca estándar provee `Set<T>` (solo lectura) y [`MutableSet<T>`]({{ "/es/glosario/mutable-set/" | relative_url }}) (modificable). Las implementaciones comunes incluyen `HashSet` (basado en hash, O(1) lookup), `LinkedHashSet` (preserva orden de inserción) y `TreeSet` (ordenado). Las funciones de fábrica como [`setOf()`]({{ "/es/glosario/set-of/" | relative_url }}) y `mutableSetOf()` crean instancias de forma concisa.

```kotlin
// De FollowApp Suite — BulkSelectionTest.kt
val selected = setOf("1", "2", "3", "4")
val visible = listOf("1", "2", "3")
val result = toggleSelectAll(selected, visible)
assertEquals(setOf("4"), result)
```

## The Senior Nuance (El Matiz Senior)

- Como los [maps]({{ "/es/glosario/maps/" | relative_url }}), los sets dependen de `hashCode()` y [`equals()`]({{ "/es/glosario/equals/" | relative_url }}) para la identidad de elementos. Cuando almacenás instancias de `data class` en un set, solo las propiedades del [constructor primario]({{ "/es/glosario/primary-constructor/" | relative_url }}) determinan la unicidad — las propiedades del cuerpo se ignoran.
- La interfaz `Set` de Kotlin es de solo lectura pero no verdaderamente inmutable: el `HashSet` subyacente puede castearse y modificarse. Para inmutabilidad garantizada, usá `persistentSetOf()` de `kotlinx.collections.immutable`.
- Las operaciones de sets como `union`, `intersect`, `subtract` y el operador `-` son poderosas para lógica de selección masiva — el ejemplo FAS de arriba usa la diferencia de sets para computar las selecciones restantes después de un toggle.
