## The Theory (El Qué)

**`@Binds`** es una anotación de [Dagger]({{ "/es/glosario/dagger/" | relative_url }}) usada dentro de un [`@Module`]({{ "/es/glosario/module-annotation/" | relative_url }}) para declarar que una interface debe ser satisfecha por una implementación específica. A diferencia de `@Provides`, que requiere un cuerpo de método, `@Binds` es un método `abstract` — el [procesador de anotaciones]({{ "/es/glosario/annotation-processing/" | relative_url }}) genera el binding en [compile time]({{ "/es/glosario/compile-time/" | relative_url }}) sin overhead en runtime.

```kotlin
// From FollowApp Suite — RepositoryModule.kt
@Module
@InstallIn(SingletonComponent::class)
abstract class RepositoryModule {

    @Binds
    abstract fun bindTaskRepository(
        taskRepositoryImpl: TaskRepositoryImpl
    ): TaskRepository

    @Binds
    abstract fun bindLabelRepository(
        labelRepositoryImpl: LabelRepositoryImpl
    ): LabelRepository
}
```

## The Senior Nuance (El Matiz Senior)

- **`@Binds` vs `@Provides`**: Usá `@Binds` cuando mapeás una interface a su implementación (no se necesita lógica). Usá `@Provides` cuando necesitás llamar un constructor, configurar un builder, o retornar un tipo de terceros. `@Binds` genera código más eficiente — [Dagger]({{ "/es/glosario/dagger/" | relative_url }}) puede saltear la clase factory por completo.
- **Regla del parámetro único**: Un método `@Binds` toma exactamente un parámetro (la implementación) y retorna el tipo de la interface. La implementación debe tener un constructor [`@Inject`]({{ "/es/glosario/inject/" | relative_url }}) para que Dagger sepa cómo crearla.
- **El module debe ser abstract**: Los métodos `@Binds` son `abstract`, así que la clase module debe ser `abstract class` (no `object`). Por eso los proyectos separan modules: `abstract class RepositoryModule` para `@Binds`, `object DatabaseModule` para `@Provides`.
- **Scoping**: `@Binds` en sí no scopea el binding. Agregá `@Singleton` u otra anotación de scope para cachear la instancia durante el lifetime del component.
