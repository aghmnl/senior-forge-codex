## The Theory (El Qué)

Un **DAO** (Data Access Object) es un patrón de diseño que encapsula todo el acceso a una fuente de datos detrás de una interface. En Android, [Room]({{ "/es/glosario/room/" | relative_url }}) usa interfaces anotadas con `@Dao` donde cada método mapea a una operación SQL. El [procesador de anotaciones]({{ "/es/glosario/annotation-processing/" | relative_url }}) genera la implementación en [compile time]({{ "/es/glosario/compile-time/" | relative_url }}) — vos escribís la query, Room escribe el [bytecode]({{ "/es/glosario/bytecode/" | relative_url }}).

```kotlin
// From FollowApp Suite — LabelDao.kt
@Dao
interface LabelDao {

    @Query("SELECT * FROM labels ORDER BY name ASC")
    fun getLabelsStream(): Flow<List<LabelEntity>>

    @Query("SELECT * FROM labels WHERE name = :name LIMIT 1")
    suspend fun getLabelByName(name: String): LabelEntity?

    @Insert(onConflict = OnConflictStrategy.IGNORE)
    suspend fun insertLabel(label: LabelEntity): Long

    @Query("DELETE FROM labels WHERE id = :labelId")
    suspend fun deleteLabel(labelId: String)
}
```

## The Senior Nuance (El Matiz Senior)

- **SQL verificado en compile time**: [Room]({{ "/es/glosario/room/" | relative_url }}) valida cada `@Query` contra el schema de base de datos durante el build. Un typo en un nombre de columna o un type mismatch es un error de build, no un crash en [runtime]({{ "/es/glosario/runtime/" | relative_url }}).
- **Los returns con Flow son reactivos**: Un método DAO que retorna `Flow<List<T>>` re-emite automáticamente cada vez que la tabla subyacente cambia. Esto elimina lógica de refresh manual y se combina naturalmente con [coroutines]({{ "/es/glosario/coroutines/" | relative_url }}).
- **[Suspend functions]({{ "/es/glosario/suspend-functions/" | relative_url }}) para operaciones one-shot**: Los métodos DAO `suspend fun` corren en el contexto de coroutine del caller. Room asegura que se ejecutan fuera del main thread — llamar un DAO suspend desde `Dispatchers.Main` igual corre la query en el executor de background de Room.
- **DAO como frontera de abstracción**: Los repositorios dependen de DAOs, no de Room directamente. Esto significa que podés swapear la implementación de base de datos o proveer un DAO in-memory para testing sin cambiar la lógica de negocio.
