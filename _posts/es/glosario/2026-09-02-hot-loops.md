## The Theory (El Qué)

Un **hot loop** (loop de alta frecuencia) es un loop que se ejecuta a muy alta frecuencia o itera sobre colecciones grandes en paths críticos de performance. En Android, los ejemplos canónicos son `onDraw()` (llamado 60–120 veces por segundo), `onMeasure()`/`onLayout()`, y lambdas de recomposición de [Jetpack Compose]({{ "/es/glosario/jetpack-compose/" | relative_url }}). Cualquier [allocation]({{ "/es/glosario/allocations/" | relative_url }}) dentro de un hot loop multiplica su costo por la cantidad de iteraciones, creando presión en el [Garbage Collector]({{ "/es/glosario/garbage-collector/" | relative_url }}) que causa drops de frames (jank).

```kotlin
// Not found in FAS — standalone example
// MAL: allocating dentro de onDraw — 60 objetos/seg × 3 = 180 allocations/seg
override fun onDraw(canvas: Canvas) {
    val paint = Paint()                      // allocation cada frame
    val rect = RectF(0f, 0f, width, height)  // allocation cada frame
    canvas.drawRoundRect(rect, 12f, 12f, paint)
}

// BIEN: pre-asignar y reusar
private val paint = Paint()
private val rect = RectF()

override fun onDraw(canvas: Canvas) {
    rect.set(0f, 0f, width.toFloat(), height.toFloat())
    canvas.drawRoundRect(rect, 12f, 12f, paint)
}
```

## The Senior Nuance (El Matiz Senior)

- El presupuesto de 16ms por frame (60 fps) u 8ms (120 fps) significa que cada microsegundo cuenta dentro de un hot loop. Un solo [autoboxing]({{ "/es/glosario/autoboxing/" | relative_url }}) en un loop de 1,000 iteraciones crea 1,000 objetos `Integer` en el [heap]({{ "/es/glosario/heap/" | relative_url }}). Usá [`IntArray`]({{ "/es/glosario/intarray/" | relative_url }}) y tipos [primitivos]({{ "/es/glosario/primitives/" | relative_url }}) para evitar esto.
- Las [inline functions]({{ "/es/glosario/inline-functions/" | relative_url }}) son críticas dentro de hot loops: un [lambda]({{ "/es/glosario/lambdas/" | relative_url }}) no-inline pasado a una [función de orden superior]({{ "/es/01-kotlin-core/higher-order-functions-lambdas/" | relative_url }}) asigna un objeto wrapper en cada llamada. Las funciones de stdlib de Kotlin (`map`, `filter`, `forEach`) son todas `inline`, así que no asignan — pero las HOFs custom deben marcarse como `inline` explícitamente.
- En Compose, la recomposición es el hot loop. Las funciones Composable se re-ejecutan cuando sus inputs cambian. Asignar dentro de un composable (crear objetos nuevos en el body en vez de usar `remember`) causa los mismos problemas que asignar en `onDraw()`.
- El Memory Profiler y el Allocation Tracker de Android Studio visualizan allocations a lo largo del tiempo. El flame chart de "Allocations" muestra exactamente qué métodos están asignando en hot paths. Perfilá primero — nunca optimices hot loops basándote solo en intuición.
- La concatenación de strings (`"$a + $b"`) dentro de un hot loop asigna un nuevo `StringBuilder` y `String` en cada iteración. Para construcción repetida de strings, reusá un `StringBuilder` declarado fuera del loop.
