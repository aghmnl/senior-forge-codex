## The Theory (El Qué)

**`IntArray`** (y sus hermanos `LongArray`, `FloatArray`, `DoubleArray`, `BooleanArray`, `ByteArray`, `ShortArray`, `CharArray`) es el array especializado de Kotlin que mapea directamente a un array primitivo de la JVM (`int[]`). A diferencia de `Array<Int>` o `List<Int>`, que almacenan objetos `Integer` boxeados en el [heap]({{ "/es/glosario/heap/" | relative_url }}), un `IntArray` almacena valores `int` crudos en un bloque contiguo de memoria — cero [autoboxing]({{ "/es/glosario/autoboxing/" | relative_url }}), cero [allocations]({{ "/es/glosario/allocations/" | relative_url }}) por elemento.

```kotlin
// Not found in FAS — standalone example
val boxed: List<Int> = listOf(1, 2, 3)     // 3 objetos Integer + wrapper List en el heap
val unboxed: IntArray = intArrayOf(1, 2, 3) // un int[] — memoria plana, sin boxing

// Convirtiendo entre ellos
val fromList: IntArray = boxed.toIntArray()
val fromArray: List<Int> = unboxed.toList()  // re-boxea cada elemento
```

## The Senior Nuance (El Matiz Senior)

- La diferencia importa en paths críticos de performance: iterar sobre un `IntArray` de 10,000 elementos crea cero basura, mientras que iterar sobre `List<Int>` puede triggear 10,000 [allocations]({{ "/es/glosario/allocations/" | relative_url }}) de [autoboxing]({{ "/es/glosario/autoboxing/" | relative_url }}) dependiendo de cómo se construyó la lista. En `onDraw()` o recomposición de Compose, esta es la diferencia entre rendering fluido y jank.
- `IntArray` carece de la rica API de Collection (`map`, `filter`, `flatMap` retornando `List`). Kotlin provee extension functions como `IntArray.map {}` que retornan `List<R>` — lo cual re-boxea los resultados. Para procesamiento verdaderamente libre de allocations, usá loops indexados o `forEach` que opera in-place.
- Los [primitivos]({{ "/es/glosario/primitives/" | relative_url }}) en Kotlin compilan a primitivos de la JVM solo cuando son non-nullable y no genéricos. `IntArray` es la forma de mantener esa garantía para colecciones de valores.
- En Android, `IntArray` se usa comúnmente para arrays de IDs de recursos, arrays de colores y arrays de dimensiones donde los valores se pasan a métodos del framework que esperan `int[]`. `writeIntArray()`/`createIntArray()` de Parcelable también trabajan directamente con `IntArray`.
- Las [inline functions]({{ "/es/glosario/inline-functions/" | relative_url }}) de Kotlin como `IntArray.sumOf {}` o `IntArray.count {}` procesan el array sin asignar objetos de iterador o lambda, combinando dos estrategias de evitación de allocations.
