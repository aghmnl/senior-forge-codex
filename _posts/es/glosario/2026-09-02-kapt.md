## The Theory (El Qué)

**kapt** (Kotlin Annotation Processing Tool) es el pipeline original de [procesamiento de anotaciones]({{ "/es/glosario/annotation-processing/" | relative_url }}) para proyectos Kotlin. Conecta código Kotlin con la API `javax.annotation.processing` de Java, generando primero [stubs]({{ "/es/glosario/stubs/" | relative_url }}) Java a partir del [código fuente]({{ "/es/glosario/source-code/" | relative_url }}) Kotlin, y luego ejecutando procesadores de anotaciones Java contra esos stubs. kapt está siendo reemplazado por [KSP]({{ "/es/glosario/ksp/" | relative_url }}), que procesa símbolos Kotlin directamente sin generación de stubs.

## The Senior Nuance (El Matiz Senior)

- **La generación de stubs es el cuello de botella**: kapt debe generar un archivo de stub Java por cada archivo fuente Kotlin antes de que corra cualquier procesador. Este paso solo puede duplicar el [tiempo de compilación]({{ "/es/glosario/compile-time/" | relative_url }}) en proyectos grandes — es la razón principal por la que los equipos migran a [KSP]({{ "/es/glosario/ksp/" | relative_url }}).
- **Ventaja de compatibilidad**: kapt funciona con cualquier procesador de anotaciones Java out of the box. Si una biblioteca solo soporta procesamiento de anotaciones Java (sin backend KSP), kapt es la única opción.
- **Se declara vía plugin de Gradle**: `plugins { id("org.jetbrains.kotlin.kapt") }`, luego las dependencias usan `kapt(...)` en lugar de `implementation(...)` para los artifacts del procesador.
- **Camino de migración**: La mayoría de las bibliotecas Android principales ([Dagger]({{ "/es/glosario/dagger/" | relative_url }})/[Hilt]({{ "/es/glosario/hilt/" | relative_url }}), [Room]({{ "/es/glosario/room/" | relative_url }}), Moshi) ahora soportan [KSP]({{ "/es/glosario/ksp/" | relative_url }}). Google recomienda migrar de kapt a KSP para builds más rápidos. La migración es típicamente mecánica: reemplazar `kapt(...)` con `ksp(...)` en `build.gradle.kts` y cambiar el artifact del procesador.
- **Estado deprecado**: kapt está en modo mantenimiento. JetBrains recomienda KSP para todos los proyectos nuevos y promueve activamente la migración de los existentes.
