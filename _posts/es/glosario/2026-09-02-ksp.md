## The Theory (El Qué)

**KSP** (Kotlin Symbol Processing) es la API moderna de [procesamiento de anotaciones]({{ "/es/glosario/annotation-processing/" | relative_url }}) para Kotlin. A diferencia de [kapt]({{ "/es/glosario/kapt/" | relative_url }}), que genera [stubs]({{ "/es/glosario/stubs/" | relative_url }}) Java y ejecuta procesadores Java, KSP opera directamente sobre los símbolos del compilador de Kotlin — ve código Kotlin como Kotlin, entiende features específicos de Kotlin ([suspend functions]({{ "/es/glosario/suspend-functions/" | relative_url }}), [extension functions]({{ "/es/glosario/extension-functions/" | relative_url }}), nullability), y corre significativamente más rápido.

```kotlin
// From FollowApp Suite — build.gradle.kts (core/data)
plugins {
    alias(libs.plugins.ksp)
    alias(libs.plugins.hilt.android)
}

dependencies {
    ksp(libs.hilt.compiler)
}
```

## The Senior Nuance (El Matiz Senior)

- **Sin stubs, sin overhead**: KSP evita la generación de stubs Java que hace lento a [kapt]({{ "/es/glosario/kapt/" | relative_url }}). En la práctica esto significa ~2× más rápido en [tiempos de compilación]({{ "/es/glosario/compile-time/" | relative_url }}) para procesamiento de anotaciones — una diferencia significativa en proyectos con muchos módulos.
- **API nativa de Kotlin**: Los procesadores KSP trabajan con `KSDeclaration`, `KSClassDeclaration`, `KSFunctionDeclaration` — tipos que modelan directamente las construcciones de Kotlin. Esto permite a los procesadores manejar features de Kotlin (nullability, parámetros default, `value class`) correctamente, lo que kapt no puede.
- **Procesamiento incremental**: KSP soporta procesamiento incremental out of the box — solo reprocesa archivos que cambiaron. El soporte incremental de kapt es limitado y a menudo se deshabilita en la práctica.
- **DSL de Gradle**: Las dependencias de procesadores usan `ksp(...)` en lugar de `kapt(...)`. El codebase de FAS usa KSP exclusivamente — el compiler de [Hilt]({{ "/es/glosario/hilt/" | relative_url }}) y el de [Room]({{ "/es/glosario/room/" | relative_url }}) corren ambos a través de KSP.
- **Multiplatform ready**: KSP funciona con proyectos Kotlin Multiplatform, mientras que kapt es solo JVM.
