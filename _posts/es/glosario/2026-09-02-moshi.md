## The Theory (El Qué)

**Moshi** es una biblioteca de serialización JSON para Kotlin y Java de Square. Convierte entre strings JSON y objetos Kotlin/Java. Moshi puede funcionar vía [runtime reflection]({{ "/es/glosario/runtime-reflection/" | relative_url }}) (`moshi-kotlin-reflect`) o vía [procesamiento de anotaciones]({{ "/es/glosario/annotation-processing/" | relative_url }}) (`moshi-kotlin-codegen`), que genera clases `JsonAdapter` en [compile time]({{ "/es/glosario/compile-time/" | relative_url }}) — el path de codegen es el preferido en Android tanto por rendimiento como por tamaño de APK.

## The Senior Nuance (El Matiz Senior)

- **Codegen vs reflexión**: `moshi-kotlin-codegen` usa [KSP]({{ "/es/glosario/ksp/" | relative_url }}) (o [kapt]({{ "/es/glosario/kapt/" | relative_url }})) para generar adapters en compile time — no se necesita la dependencia `kotlin-reflect`, sin overhead de reflexión, y [R8]({{ "/es/glosario/r8/" | relative_url }}) puede shrinkear el resultado libremente. El adapter de reflexión trae ~2.5 MB de `kotlin-reflect`, lo cual es significativo en Android.
- **`@JsonClass(generateAdapter = true)`**: Esta anotación dispara la codegen del adapter. El adapter generado maneja nullability, valores default y keys desconocidas correctamente — cosas que Gson notoriamente hace mal con Kotlin.
- **Kotlin-first**: Moshi entiende el sistema de tipos de Kotlin — nullable vs non-null, valores default de parámetros, y data classes. Gson fue diseñado para Java y silenciosamente asigna `null` a propiedades non-null de Kotlin, causando crashes downstream.
- **Integración con Retrofit**: Moshi se combina comúnmente con Retrofit vía `MoshiConverterFactory`. Los adapters generados aseguran que el parsing de respuestas de API sea rápido y type-safe.
- **Alternativa: Kotlinx.Serialization**: Para proyectos Kotlin puros, `kotlinx.serialization` es la alternativa first-party — usa un compiler plugin en lugar de procesamiento de anotaciones y funciona con Kotlin Multiplatform.
