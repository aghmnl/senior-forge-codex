## The Theory (El Qué)

**`noinline`** es un modificador para parámetros [lambda]({{ "/es/glosario/lambdas/" | relative_url }}) de [inline functions]({{ "/es/glosario/inline-functions/" | relative_url }}) que previene que una lambda específica sea inlineada. Cuando una función es `inline`, todos sus parámetros lambda se inlinean por defecto — su cuerpo se copia en el call site. Marcar uno como `noinline` lo mantiene como un objeto `Function` regular [asignado]({{ "/es/glosario/allocations/" | relative_url }}) en el [heap]({{ "/es/glosario/heap/" | relative_url }}), lo cual es necesario cuando necesitás almacenar, pasar o retornar la lambda.

```kotlin
// Not found in FAS — standalone example
inline fun measure(
    action: () -> Unit,          // inlineada — cero allocation
    noinline onComplete: () -> Unit  // NO inlineada — se mantiene como objeto Function
) {
    val start = System.nanoTime()
    action()
    val elapsed = System.nanoTime() - start
    // Necesitamos guardar onComplete para después — solo posible porque es noinline
    completionCallbacks += onComplete
}
```

## The Senior Nuance (El Matiz Senior)

- Necesitás `noinline` cuando una lambda debe tratarse como un objeto: almacenarse en una colección, pasarse a una función no-inline, asignarse a una variable, o retornarse desde la función. Las lambdas inlineadas no existen como objetos — son código pegado en el call site — así que no pueden ser referenciadas.
- Las lambdas `noinline` [asignan]({{ "/es/glosario/allocations/" | relative_url }}) un objeto `Function` en el [heap]({{ "/es/glosario/heap/" | relative_url }}), como cualquier lambda regular. En [hot loops]({{ "/es/glosario/hot-loops/" | relative_url }}), esto importa — preferí reestructurar la API para mantener las lambdas inlineables en vez de usar `noinline`.
- Contraste con [`crossinline`]({{ "/es/glosario/crossinline/" | relative_url }}): `noinline` previene el inlining completamente (la lambda se convierte en un objeto del heap). `crossinline` sigue inlineando la lambda pero bloquea non-local `return`. Elegí según si necesitás la lambda como *objeto* (`noinline`) o solo necesitás cruzar un boundary de ejecución (`crossinline`).
- Si todos los parámetros lambda de una función `inline` están marcados como `noinline`, el compilador advierte que hacer la función `inline` no tiene sentido — la función en sí se inlinearía pero no gana ningún beneficio ya que ninguna de sus lambdas evita la allocation.
- En la práctica, `noinline` es raro. La mayoría de las inline functions existen precisamente para evitar la allocation de lambdas. El caso de uso típico es una inline function con *múltiples* parámetros lambda donde uno necesita inlining (el hot path) y otro necesita ser almacenado (un callback para después).
