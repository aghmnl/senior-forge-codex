## The Theory (El Qué)

**Room** es la librería de persistencia de Android Jetpack que provee una capa de abstracción verificada en compile time sobre SQLite. Usa [annotation processing]({{ "/es/glosario/annotation-processing/" | relative_url }}) para generar el código boilerplate de operaciones de base de datos: definís data classes `@Entity`, interfaces `@Dao` con queries SQL, y una clase abstracta `@Database` — Room genera las clases `_Impl` que hacen el trabajo SQLite real.

```kotlin
// From FollowApp Suite — MyTasksDatabase.kt
@Database(
    entities = [TaskEntity::class, LabelEntity::class, LabelOptionEntity::class, PresetEntity::class],
    version = 2,
    exportSchema = true
)
abstract class MyTasksDatabase : RoomDatabase() {
    abstract fun taskDao(): TaskDao
    abstract fun labelDao(): LabelDao
    abstract fun labelOptionDao(): LabelOptionDao
    abstract fun presetDao(): PresetDao
    abstract fun backupDao(): BackupDao
}
```

## The Senior Nuance (El Matiz Senior)

- **Verificación SQL en compile time**: Room valida queries SQL en [compile time]({{ "/es/glosario/compile-time/" | relative_url }}) contra el schema. Un typo en un nombre de columna o un type mismatch es un error de build, no un crash en [runtime]({{ "/es/glosario/runtime/" | relative_url }}) — a diferencia de SQLite crudo o `ContentValues`.
- **Integración con Flow y [coroutines]({{ "/es/glosario/coroutines/" | relative_url }})**: Los DAOs de Room pueden retornar `Flow<List<T>>` para queries observables (el Flow re-emite cada vez que la tabla cambia) y [suspend functions]({{ "/es/glosario/suspend-functions/" | relative_url }}) para operaciones one-shot. Esto elimina patrones basados en [callbacks]({{ "/es/glosario/callbacks/" | relative_url }}) para acceso a base de datos.
- **Migraciones**: `Room.databaseBuilder(...).addMigrations(MIGRATION_1_2)` maneja la evolución del schema. Los desarrolladores senior escriben migraciones explícitamente (no `fallbackToDestructiveMigration()`) y las testean con el `MigrationTestHelper` de Room para prevenir pérdida de datos en producción.
- **[Runtime reflection]({{ "/es/glosario/runtime-reflection/" | relative_url }}) en la inicialización**: `Room.databaseBuilder(ctx, MyDb::class.java)` usa `::class.java` para localizar la clase `_Impl` generada. Es un punto de entrada de reflexión liviano — Room en sí usa [annotation processing]({{ "/es/glosario/annotation-processing/" | relative_url }}), no reflexión, para el trabajo pesado.
- **Testing**: El `inMemoryDatabaseBuilder` de Room crea una base de datos que vive solo en RAM — rápida, aislada y automáticamente limpiada. El codebase de FAS usa este patrón en métodos de setup `@Before` para tests de integración.
