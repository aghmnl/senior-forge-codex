## The Theory (El Qué)

**`@Stable`** es una anotación de Compose que le promete al compilador que las propiedades públicas de un tipo notificarán a Compose cuando cambien. Este contrato permite que Compose **omita la recomposición** de funciones [`@Composable`]({{ "/es/glosario/composable/" | relative_url }}) cuando sus parámetros `@Stable` no han cambiado.

El contrato de `@Stable` requiere:

1. `equals()` siempre retorna el mismo resultado para las mismas dos instancias.
2. Cuando una propiedad pública cambia, Compose es notificado (vía el sistema de snapshots).
3. Todas las propiedades públicas son [tipos primitivos]({{ "/es/glosario/primitives/" | relative_url }}) o son ellas mismas `@Stable`.

Las clases que usan [delegated properties]({{ "/es/01-kotlin-core/delegated-properties/" | relative_url }}) respaldadas por `mutableStateOf()` cumplen este contrato naturalmente: el sistema de snapshots notifica a Compose de cada escritura.

```kotlin
@Stable
class CounterState {
    var count by mutableStateOf(0)
        private set

    fun increment() { count++ }
}
```

Compose también tiene `@Immutable` — una garantía más estricta de que todas las propiedades nunca cambiarán después de la construcción. `@Stable` es el contrato más débil y más común: las propiedades pueden cambiar, pero Compose lo sabrá.

## The Senior Nuance (El Matiz Senior)

- Un Senior sabe que el plugin del compilador de Compose infiere automáticamente la estabilidad para muchos tipos — `data class` con todos campos estables, tipos primitivos, `String`, `List<Stable>`. La anotación `@Stable` solo es necesaria cuando el compilador no puede probar estabilidad (por ejemplo, clases con interfaces como propiedades, o tipos de módulos no-Compose). Usá las Compose Compiler Metrics (`-Pcompose.compiler.metricsDestination`) para verificar qué clases son estables.
- Las clases `@Stable` que contienen `by mutableStateOf()` son el patrón estándar para state holders multi-propiedad que viven fuera de la composición — como el `ReorderState` en controladores de drag-and-drop. A diferencia de `remember { mutableStateOf() }` que tiene scope a un solo composable, una instancia `@Stable` puede compartirse a lo largo del árbol de composables.
- Marcar una clase como `@Stable` cuando no satisface genuinamente el contrato (propiedades mutables sin respaldo de snapshots) causa **recomposiciones omitidas sobre datos desactualizados** — uno de los bugs de Compose más difíciles de diagnosticar porque la UI deja de actualizarse silenciosamente.
- En proyectos multi-módulo, el compilador de Compose no puede ver dentro de módulos no-Compose. Los tipos de esos módulos se tratan como inestables por defecto, forzando recomposición aun cuando los valores no cambiaron. La solución es agregar `@Stable` a esos tipos o crear un archivo de configuración de estabilidad.
