## The Theory (El Qué)

**`buildMap { }`** es la contraparte para [`Map`]({{ "/es/glosario/maps/" | relative_url }}) de [`buildList`]({{ "/es/glosario/build-list/" | relative_url }}): una [Builder Function]({{ "/es/glosario/builder-functions/" | relative_url }}) [inline]({{ "/es/glosario/inline-functions/" | relative_url }}) cuyo receiver es un [`MutableMap`]({{ "/es/glosario/mutable-map/" | relative_url }}) y que devuelve un `Map` de solo lectura.

```kotlin
// No encontrado en FAS — ejemplo standalone
fun activeFilters(state: TasksUiState): Map<String, LabelFilterState> = buildMap {
    state.labelFilters.forEach { (name, value) ->
        if (value != LabelFilterState.OFF) put(name, value)
    }
    state.doneFilter?.let { put("done", it) }
}
```

## The Senior Nuance (El Matiz Senior)

- Reemplaza el patrón `mutableMapOf` + poblar + retornar cuando el map se construye genuinamente una sola vez, y elimina la posibilidad de que la referencia mutable escape. FollowApp Suite todavía usa la forma explícita con `mutableMapOf` donde la lógica de acumulación es lo bastante larga como para querer una variable con nombre — las dos son correctas; `buildMap` es la más ajustada.
- Preferilo sobre `mapOf(*pairs.toTypedArray())` o `associate { }` cuando las entradas son condicionales: `associate` asigna un `Pair` por elemento, `buildMap` llama a [`put`]({{ "/es/glosario/put/" | relative_url }}) directamente.
- Como todo builder, el resultado queda congelado al retornar, así que es seguro publicarlo en estado compartido sin [Defensive Copy]({{ "/es/glosario/defensive-copy/" | relative_url }}).
