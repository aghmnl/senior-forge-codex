## The Theory (El Qué)

**`filter { }`** devuelve un [`List`]({{ "/es/glosario/list/" | relative_url }}) nuevo con los elementos que cumplen un predicado. `filterNot` es su inverso, `filterIsInstance<T>()` filtra por tipo, y `filterKeys`/`filterValues` hacen lo mismo sobre un [`Map`]({{ "/es/glosario/maps/" | relative_url }}).

```kotlin
// De FollowApp Suite — TasksViewModel.kt
val done = tasks.filter { it.isCompleted }
val notDone = tasks.filter { !it.isCompleted }

// De FollowApp Suite — TasksUiState.kt
val selectedTasks: List<Task> get() = activeTasks.filter { it.id in selectedTaskIds }
```

## The Senior Nuance (El Matiz Senior)

- El costo del predicado es el costo del operador, multiplicado por `n`. `it.id in selectedTaskIds` es `O(1)` porque `selectedTaskIds` es un [`Set`]({{ "/es/glosario/sets/" | relative_url }}); la misma línea sobre un `List` haría todo el filtro `O(n·m)` — la causa de jank más común en una pantalla de lista.
- Dos pasadas de `filter` para producir grupos complementarios (como arriba) recorren la lista dos veces; `partition { }` lo hace en una y devuelve las dos mitades. Con listas chicas suele ganar la claridad, y es una decisión que vale tomar conscientemente.
- Siempre asigna. Cuando `filter` alimenta a `first`/`any`, las [Terminal Operations]({{ "/es/glosario/terminal-operations/" | relative_url }}) `firstOrNull { }`/`any { }` cortan temprano sin construir lista alguna — y sobre una [Sequence]({{ "/es/glosario/sequences/" | relative_url }}) toda la cadena se detiene en la primera coincidencia.
