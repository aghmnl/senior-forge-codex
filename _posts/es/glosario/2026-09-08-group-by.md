## The Theory (El Qué)

**`groupBy { }`** devuelve un `Map<K, List<T>>` indexado por el resultado del selector, con cada elemento recolectado en su bucket. `groupBy(keySelector, valueTransform)` mapea los valores en el camino, y `groupingBy { }` inicia un agrupamiento lazy para folds y conteos.

```kotlin
// De FollowApp Suite — LabelRepositoryImpl.kt
val optionsByLabelId = allOptions.groupBy { it.labelId }
labels.associate { labelEntity ->
    val label = labelEntity.toDomain()
    val options = (optionsByLabelId[labelEntity.id] ?: emptyList()).map { it.toDomain() }
    label to options
}
```

## The Senior Nuance (El Matiz Senior)

- Esta es la corrección del antipatrón del join dentro de un loop. Agrupar una vez y buscar cada clave es `O(n + m)`; llamar `allOptions.filter { it.labelId == id }` dentro de un loop sobre labels es `O(n·m)`.
- Es eager y asigna un [`Map`]({{ "/es/glosario/maps/" | relative_url }}) más un [`List`]({{ "/es/glosario/list/" | relative_url }}) por clave, así que fuerza a materializar una cadena de [Sequences]({{ "/es/glosario/sequences/" | relative_url }}). Para contar, `groupingBy { }.eachCount()` evita construir las listas intermedias por completo.
- Las claves se comparan con [`equals`]({{ "/es/glosario/equals/" | relative_url }}) y se hashean, así que un selector que devuelve una [Data Class]({{ "/es/01-kotlin-core/data-classes/" | relative_url }}) funciona, mientras que uno que devuelve un objeto mutable produce buckets duplicados en silencio. El orden de iteración del resultado sigue el de primera aparición (`LinkedHashMap`).
