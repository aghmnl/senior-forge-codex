## The Theory (El Qué)

**`remove`** elimina un elemento de una `MutableCollection` por valor y devuelve si se quitó algo. [`MutableList`]({{ "/es/glosario/mutable-list/" | relative_url }}) tiene además `removeAt(index)`, que devuelve el elemento quitado, y `removeAll { }` para borrado por predicado. En un [`MutableMap`]({{ "/es/glosario/mutable-map/" | relative_url }}), `remove(key)` devuelve el valor anterior o `null`.

```kotlin
// De FollowApp Suite — DragToReorder.kt
itemCoords.entries.removeAll { it.key != key && it.value === coords }
```

## The Senior Nuance (El Matiz Senior)

- `remove(element)` compara con [`equals`]({{ "/es/glosario/equals/" | relative_url }}), no por identidad — en una lista de [Data Classes]({{ "/es/01-kotlin-core/data-classes/" | relative_url }}) borra el *primer elemento estructuralmente igual*, que rara vez es el que querías. Preferí `removeAt` o `removeAll { it.id == id }`.
- `removeAll { }` sobre una lista es una sola pasada; un loop de llamadas a `remove` es `O(n²)` y, si corre mientras se itera, lanza `ConcurrentModificationException`. Remover a través de `entries` (como arriba) es la forma soportada de mutar un map durante el recorrido.
- En un [`ArrayList`]({{ "/es/glosario/arraylist/" | relative_url }}), quitar desplaza la cola: `removeAt(0)` es `O(n)`, `removeAt(lastIndex)` es `O(1)`.

**Documentación oficial:** [`MutableCollection.remove`](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.collections/-mutable-collection/remove.html)
