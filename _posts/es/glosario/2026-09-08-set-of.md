## The Theory (El Qué)

**`setOf(vararg elements)`** crea un [`Set`]({{ "/es/glosario/sets/" | relative_url }}) de solo lectura, respaldado por un `LinkedHashSet`, así que descarta duplicados y el orden de iteración es el de inserción. `emptySet()` devuelve un singleton compartido.

```kotlin
// De FollowApp Suite — TasksViewModel.kt
filters = setOf(TaskStatus.ACTIVE)

// De FollowApp Suite — ArchiveViewModel.kt
_uiState.update { it.copy(selectedTaskIds = setOf(taskId)) }
```

## The Senior Nuance (El Matiz Senior)

- Declarar un campo de estado de UI como `Set<String>` en vez de `List<String>` enuncia un invariante que el sistema de tipos después hace cumplir: los ids de selección no pueden repetirse. En FollowApp Suite eso es lo que permite expresar el toggle de selección como álgebra de sets con `+`/`-` que devuelve valores nuevos.
- La igualdad de `Set` ignora el orden, así que dos estados con los mismos ids en distinto orden comparan iguales — exactamente el comportamiento que querés para un chequeo de [`equals`]({{ "/es/glosario/equals/" | relative_url }}) en Compose, y exactamente el equivocado para una lista ordenada de filas.
- Los elementos deben tener `hashCode`/[`equals`]({{ "/es/glosario/equals/" | relative_url }}) estables. `setOf` sobre objetos mutables construye una estructura cuyo [`contains`]({{ "/es/glosario/contains/" | relative_url }}) deja de funcionar en silencio después de la primera [mutación]({{ "/es/glosario/mutation/" | relative_url }}).
