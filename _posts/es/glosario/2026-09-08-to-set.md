## The Theory (El Qué)

**`toSet()`** devuelve un [`Set`]({{ "/es/glosario/sets/" | relative_url }}) nuevo de solo lectura con los elementos distintos del receiver, preservando el orden de inserción vía `LinkedHashSet`. Deduplica y además convierte un [`contains`]({{ "/es/glosario/contains/" | relative_url }}) `O(n)` en uno `O(1)`.

```kotlin
// De FollowApp Suite — BulkSelection.kt
val groupSet = groupTaskIds.toSet()
return if (groupSet.all { it in selectedTaskIds }) {
    selectedTaskIds - groupSet
} else {
    selectedTaskIds + groupSet
}
```

## The Senior Nuance (El Matiz Senior)

- Sacar `toSet()` fuera de un loop es la corrección de performance de mayor valor en código Android con muchas listas: `O(n·m)` pasa a `O(n + m)` a cambio de una sola allocation.
- Dentro del loop es lo contrario — `list.toSet()` evaluado por elemento reconstruye toda la estructura en cada iteración y es estrictamente peor que el escaneo lineal que venía a reemplazar.
- `toSet()` también normaliza para comparar: dos listas con los mismos elementos en distinto orden tienen `toSet()` iguales. Usalo a propósito, porque descarta tanto el orden como los duplicados.
