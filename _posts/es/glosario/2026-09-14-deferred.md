## The Theory (El Qué)

Un **`Deferred<T>`** es un [`Job`]({{ "/es/glosario/job/" | relative_url }}) que además lleva un resultado: el handle que devuelve `async { }`. Representa un valor que va a existir más tarde. [`await()`]({{ "/es/glosario/await/" | relative_url }}) suspende hasta que el valor está listo y lo devuelve — o relanza la excepción con la que falló el bloque.

```kotlin
// Not found in FAS — standalone example
val (labels, presets) = coroutineScope {
    val l = async { labelRepository.getAll() }
    val p = async { presetRepository.getAll() }
    l.await() to p.await()
}
```

## The Senior Nuance (El Matiz Senior)

- **Las excepciones se guardan, no se propagan al handler.** Un bloque `async` que falla conserva su excepción adentro del `Deferred` hasta el `await()`; un [`CoroutineExceptionHandler`]({{ "/es/glosario/coroutine-exception-handler/" | relative_url }}) nunca la ve. Envolvé el `await`, no el `async`.
- **Nunca `async` sin `await`.** Si no necesitás el valor, usá [`launch`]({{ "/es/glosario/launch/" | relative_url }}); un `Deferred` sin await se traga silenciosamente su fallo.
- **La descomposición paralela va adentro de un [`coroutineScope`]({{ "/es/glosario/coroutine-scope-builder/" | relative_url }})**, así un fallo en una rama cancela la otra y el llamador ve una única excepción.
- Es el análogo en coroutines de un `Future`/`Promise`, con cancelación estructurada incorporada.
