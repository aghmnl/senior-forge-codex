## The Theory (El Qué)

**`runTest { }`** (de `kotlinx-coroutines-test`) es el builder de test para código suspendible. Corre el bloque en un `TestScope` respaldado por un [`TestDispatcher`]({{ "/es/glosario/test-dispatcher/" | relative_url }}) con reloj virtual: `delay(5_000)` completa al instante, `advanceUntilIdle()` drena el trabajo pendiente de forma determinista, y el test falla si alguna coroutine lanzada en el scope sigue activa al final. Reemplaza a [`runBlocking`]({{ "/es/glosario/run-blocking/" | relative_url }}) en los tests.

```kotlin
// Not found in FAS — standalone example
@Test
fun `export writes the bundle`() = runTest {
    val manager = BackupManager(io = StandardTestDispatcher(testScheduler), /* fakes */)
    val result = manager.exportTo(uri)
    assertTrue(result.isSuccess)
}
```

## The Senior Nuance (El Matiz Senior)

- **Solo controla los dispatchers que conoce.** El código que salta a un `Dispatchers.IO` hardcodeado se va del reloj virtual; el test tiene una race. Inyectá los dispatchers ([`@IoDispatcher`]({{ "/es/glosario/io-dispatcher/" | relative_url }})) y pasá `StandardTestDispatcher(testScheduler)`.
- **`Main` sigue necesitando [`setMain`]({{ "/es/glosario/set-main/" | relative_url }}).** `runTest` no instala un dispatcher Main; los tests de ViewModel combinan ambos.
- **Las coroutines filtradas hacen fallar el test** ("UncompletedCoroutinesError") — una feature: un collector sin cancelar en producción también sería un leak.
- **`runBlocking` en tests esconde bugs de timing** porque los delays reales corren en tiempo real. `runTest` los hace explícitos.
