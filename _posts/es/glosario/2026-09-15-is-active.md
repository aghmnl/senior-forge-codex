## The Theory (El Qué)

**`isActive`** es el `Boolean` que informa si el [`Job`]({{ "/es/glosario/job/" | relative_url }}) actual sigue corriendo — `false` una vez que fue cancelado o completó. Es la comprobación de cancelación *que no lanza*, la contraparte de [`ensureActive()`]({{ "/es/glosario/ensure-active/" | relative_url }}): leerlo nunca interrumpe nada, así que es la herramienta correcta cuando necesitás *bifurcar* según la cancelación en vez de detenerte.

```kotlin
// From FollowApp Suite — TasksScreen.kt
try {
    lazyListState.scrollBy(direction * autoScrollStep)
} catch (e: CancellationException) {
    // Preempted by another scroll mutation (e.g. the
    // reorder re-anchor); keep scrolling unless the
    // effect itself was cancelled
    if (!isActive) throw e
}
```

## The Senior Nuance (El Matiz Senior)

- **Distingue dos cancelaciones.** Una [`CancellationException`]({{ "/es/glosario/cancellation-exception/" | relative_url }}) atrapada puede venir de que *tu* coroutine fue cancelada (`isActive == false` → relanzar) o de que una operación interna fue interrumpida mientras vos seguís vivo (`isActive == true` → continuar). Esa distinción es la única razón legítima para atrapar una.
- **En un loop, preferí `while (isActive)` a `while (true)`.** Hace que un loop de CPU sea [cooperativo]({{ "/es/glosario/cooperative-cancellation/" | relative_url }}) sin lanzar a mitad de iteración.
- **También está en `CoroutineScope`.** Dentro de un bloque `launch` o `LaunchedEffect`, un `isActive` pelado resuelve al job de la coroutine que lo contiene.
