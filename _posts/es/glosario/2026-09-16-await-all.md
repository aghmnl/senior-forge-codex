## The Theory (El Qué)

**`awaitAll()`** es la extensión sobre `Collection<Deferred<T>>` (y el `awaitAll(vararg)` de nivel superior) que suspende hasta que *todos* los [`Deferred`]({{ "/es/glosario/deferred/" | relative_url }}) completan y devuelve sus valores como `List<T>` en el mismo orden. Es la forma idiomática de disparar N llamadas [`async`]({{ "/es/glosario/async/" | relative_url }}) y juntar los resultados. Falla rápido: el primer `Deferred` que falla hace que `awaitAll()` relance de inmediato, sin esperar al resto.

```kotlin
// Not found in FAS — standalone example
suspend fun anyHasChildren(ids: List<String>): Boolean = coroutineScope {
    ids.map { id -> async { countActiveSubtasksUseCase(id) > 0 } }
        .awaitAll()
        .any { it }
}
```

## The Senior Nuance (El Matiz Senior)

- **`map { async }.awaitAll()` vs `map { await() }`.** `deferreds.map { it.await() }` da la misma lista pero espera *secuencialmente*: un fallo en el tercero no se ve hasta que terminaron los dos primeros. `awaitAll()` los observa a todos a la vez.
- **Fallar rápido es solo la mitad de la historia.** Dentro de un [`coroutineScope`]({{ "/es/glosario/coroutine-scope-builder/" | relative_url }}) común el `async` que falló ya canceló a sus hermanos vía el padre. El relanzamiento temprano de `awaitAll()` solo te saca de la espera antes.
- **No lo uses para `Deferred<Unit>`.** N efectos paralelos sin resultado son [`launch`]({{ "/es/glosario/launch/" | relative_url }}) dentro de `coroutineScope`, que espera a todos los hijos por sí solo.
- Ver [Launch vs Async/Await]({{ "/es/02-coroutines-flow/launch-vs-async-await/" | relative_url }}).
