## The Theory (El Qué)

**`Job.start()`** arranca explícitamente una coroutine creada con [`CoroutineStart.LAZY`]({{ "/es/glosario/coroutine-start/" | relative_url }}). Devuelve `true` si la llamada efectivamente la arrancó, `false` si ya estaba corriendo o terminó. Sobre una coroutine creada con el modo de arranque por defecto no hace nada. *No* suspende y *no* espera — solo pasa la coroutine de *New* a *Active*.

```kotlin
// Not found in FAS — standalone example
val warmup = launch(start = CoroutineStart.LAZY) { preloadCache() }
if (userOptedIn) warmup.start() else warmup.cancel()   // decide later, never leave it New
```

## The Senior Nuance (El Matiz Senior)

- **`start()` dispara; `join()` espera; `await()` es las dos cosas más un valor.** Sobre un [`Deferred`]({{ "/es/glosario/deferred/" | relative_url }}) lazy, `await()` ya lo arranca, así que `start()` solo hace falta cuando querés que corra *antes* de estar listo para esperar.
- **El `Boolean` de retorno es un "¿gané la carrera?" barato.** Dos llamadores pueden hacer `start()` sobre el mismo job lazy; solo uno recibe `true`.
- **Un job lazy que nunca recibe `start()`, `join()` ni `cancel()` mantiene vivo a su padre.** Ver [`CoroutineStart`]({{ "/es/glosario/coroutine-start/" | relative_url }}).
- Ver [Launch vs Async/Await]({{ "/es/02-coroutines-flow/launch-vs-async-await/" | relative_url }}).
