## The Theory (El Qué)

**Jank** es un tironeo visible: un frame que no llegó a su deadline, así que la pantalla muestra el frame anterior de nuevo. A 60 Hz cada frame tiene ~**16,6 ms** para medirse, ubicarse, dibujarse y componerse — todo en el [main thread]({{ "/es/glosario/main-thread/" | relative_url }}); a 120 Hz son ~8,3 ms. Cualquier trabajo en Main que exceda ese presupuesto pierde frames. El jank es la versión *chica* de una [blocking call]({{ "/es/glosario/blocking-call/" | relative_url }}) en Main; un [ANR]({{ "/es/glosario/anr/" | relative_url }}) es la grande.

```kotlin
// Not found in FAS — standalone example
// 40 ms of JSON parsing on Main during a scroll = 2–3 dropped frames per item
LazyColumn { items(rows) { row -> Text(parseHeavy(row)) } }   // parse off Main instead
```

## The Senior Nuance (El Matiz Senior)

- **El jank es acumulativo.** Diez tareas de 5 ms en un frame producen el mismo jank que una de 50 ms. `Choreographer` y Perfetto muestran la línea de tiempo de frames; Play Console reporta "slow rendering" como vital.
- **No solo el I/O lo causa.** Pasadas de layout sobre jerarquías profundas, loops con muchas allocations y tormentas de [recomposition]({{ "/es/glosario/recomposition/" | relative_url }}) son todos tiempo del main thread. El arreglo no siempre es [`withContext`]({{ "/es/glosario/with-context/" | relative_url }}); a veces es hacer menos trabajo.
- **El usuario lo nota a partir de ~2 frames perdidos.** Por eso "son solo 30 ms" no es defensa.
