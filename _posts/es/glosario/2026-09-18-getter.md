## The Theory (El Qué)

Un **getter** es el accessor que se ejecuta cada vez que se lee una propiedad. Kotlin genera uno por defecto que devuelve el [backing field]({{ "/es/glosario/backing-field/" | relative_url }}); podés reemplazarlo por un cuerpo custom: `val isEmpty: Boolean get() = items.isEmpty()`. Una propiedad con getter custom puede no tener backing field — es un valor computado. Eso importa para los smart casts ([Smart Casts]({{ "/es/01-kotlin-core/smart-casts/" | relative_url }})): el compilador solo smart-castea propiedades cuyo getter es el por defecto, porque un getter custom puede devolver algo distinto en cada llamada.

```kotlin
// Not found in FAS — standalone example
class Session(private val tokenProvider: () -> String?) {
    val token: String?
        get() = tokenProvider()          // getter custom: se recalcula en cada lectura

    fun length(): Int {
        // No compila: `token` tiene getter custom, el compilador no puede smart-castearlo
        // return if (token != null) token.length else 0
        val t = token                    // leer una vez; el val local es estable
        return t?.length ?: 0
    }
}
```

## The Senior Nuance (El Matiz Senior)

- **Getter custom = valor inestable.** Dos lecturas consecutivas de `token` pueden diferir. Un smart cast sería incorrecto, así que el compilador lo rechaza aunque la propiedad sea [`val`]({{ "/es/glosario/val/" | relative_url }}). Leé una vez a una variable local.
- **Getters baratos y puros.** Un getter que hace I/O, aloca o tiene efectos secundarios convierte cada lectura de propiedad en una llamada oculta; quien lee asume que `x.foo` no cuesta nada.
- **Los getters de otro módulo siempre son inestables.** Un `val` público de otro módulo podría ganar un getter custom en una versión futura, así que el compilador nunca lo smart-castea.
- Ver [Smart Casts]({{ "/es/01-kotlin-core/smart-casts/" | relative_url }}).
