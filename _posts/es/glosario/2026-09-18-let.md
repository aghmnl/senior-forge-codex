## The Theory (El Qué)

**`let`** es una scope function ([Scope Functions]({{ "/es/01-kotlin-core/scope-functions/" | relative_url }})): `x.let { it -> ... }` llama a la lambda con `x` como `it` y devuelve el resultado de la lambda. Combinado con un [safe call]({{ "/es/glosario/safe-call/" | relative_url }}) — `x?.let { ... }` — el bloque corre solo cuando `x` no es [`null`]({{ "/es/glosario/null/" | relative_url }}), y adentro `it` es no-nulo. Eso hace de `?.let` la forma idiomática de "hacer algo con este valor si está presente" en [Null Safety: Elvis & Safe Calls]({{ "/es/01-kotlin-core/null-safety-elvis-safe-calls/" | relative_url }}), y la razón por la que aparece en las estrategias para eliminar `!!`. Su hermano [`run`]({{ "/es/glosario/run/" | relative_url }}) hace lo mismo con `this` como receptor.

```kotlin
// De FollowApp Suite — AuthPreferences
// Safe call + let + Elvis: guardar cuando está presente, eliminar cuando ausente
fun saveSession(session: UserSession, prefs: MutablePreferences) {
    session.photoUrl?.let { prefs[photoUrlKey] = it }
        ?: prefs.remove(photoUrlKey)
}
```

## The Senior Nuance (El Matiz Senior)

- **`let` devuelve el valor del bloque — esa es su fuerza y su trampa.** `x?.let { transform(it) }` mapea un nullable en una línea; pero `x?.let { ... } ?: fallback` corre el fallback *también* cuando el bloque mismo devuelve null. El ejemplo de FAS de arriba es seguro porque la asignación devuelve `Unit`.
- **Preferí `let` para transformaciones, `if` para ramificar.** `if (x != null) { ... } else { ... }` es más claro que una cadena `let`/Elvis cuando ambas ramas tienen lógica; `let` brilla cuando necesitás el resultado.
- **Nombrá el parámetro al anidar.** `it` dentro de `it` es ilegible: `user?.let { u -> u.address?.let { a -> ... } }`.
