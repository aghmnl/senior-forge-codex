## The Theory (El Qué)

**`require(condition) { "mensaje" }`** valida una *precondición sobre argumentos*: si la condición es falsa lanza `IllegalArgumentException` con el mensaje construido de forma lazy. Es la [assertion]({{ "/es/glosario/assertion/" | relative_url }}) de la stdlib para "el llamador pasó algo inválido", a diferencia de [`check`]({{ "/es/glosario/check/" | relative_url }}), que protege el estado propio del objeto. Lleva un [contract]({{ "/es/glosario/contract/" | relative_url }}) — `returns() implies condition` — así que el compilador aplica un smart cast ([Smart Casts]({{ "/es/01-kotlin-core/smart-casts/" | relative_url }})) después de la llamada: `require(x is Foo)` convierte a `x` en `Foo` de ahí en adelante.

```kotlin
// Not found in FAS — standalone example
fun schedule(task: Task, delayMs: Long) {
    require(delayMs >= 0) { "delayMs debe ser >= 0, era $delayMs" }
    require(task.state is TaskState.Pending) { "la task ${task.id} no está pendiente" }
    // ...
}
```

## The Senior Nuance (El Matiz Senior)

- **Argumento vs. estado decide `require` vs. `check`.** `IllegalArgumentException` le dice al lector "me llamaste mal"; `IllegalStateException` le dice "yo estaba en un estado incorrecto". Elegir bien hace que el [stack trace]({{ "/es/glosario/stack-trace/" | relative_url }}) se explique solo.
- **Pasá siempre la lambda del mensaje.** Se evalúa solo al fallar, así que no cuesta nada en el camino feliz y explica qué [invariante]({{ "/es/glosario/invariant/" | relative_url }}) se rompió.
- **`require` en el borde, no en todos lados.** Validá una vez donde entra input no confiable (API pública, parsing); adentro, confiá en el sistema de tipos.
- Ver [Smart Casts]({{ "/es/01-kotlin-core/smart-casts/" | relative_url }}).
