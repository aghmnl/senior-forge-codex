## The Theory (El Qué)

**`run`** es una scope function ([Scope Functions]({{ "/es/01-kotlin-core/scope-functions/" | relative_url }})) que ejecuta una lambda con el objeto como `this` y devuelve el resultado de la lambda: `x.run { this.foo() }` o, como no-extensión, `run { ... }` para agrupar sentencias en una sola expresión. Con un [safe call]({{ "/es/glosario/safe-call/" | relative_url }}) — `x?.run { ... }` — el bloque corre solo cuando `x` no es [`null`]({{ "/es/glosario/null/" | relative_url }}), exactamente como [`let`]({{ "/es/glosario/let/" | relative_url }}) pero con acceso al receptor en vez de `it`; por eso [Null Safety: Elvis & Safe Calls]({{ "/es/01-kotlin-core/null-safety-elvis-safe-calls/" | relative_url }}) lista a ambos como formas de manejar el caso null explícitamente en vez de usar `!!`.

```kotlin
// Not found in FAS — standalone example
// run con receptor: configurar y devolver un valor en una sola expresión
val request = connection?.run {
    connectTimeout = 5_000
    readTimeout = 10_000
    build()
} ?: return null

// run sin receptor: varias sentencias donde se espera una expresión
val label = run {
    val first = user.firstName.trim()
    val last = user.lastName.trim()
    "$first $last"
}
```

## The Senior Nuance (El Matiz Senior)

- **`run` vs. `let` es `this` vs. `it`.** Elegí `run` cuando el bloque llama mayormente miembros del objeto (configuración, builders); elegí `let` cuando el objeto es un argumento que pasás. Mezclarlos al azar es el olor más común en scope functions.
- **`run` devuelve la última expresión, `apply` devuelve el receptor.** Usá `run` cuando necesitás un resultado computado, `apply` cuando querés de vuelta el objeto configurado.
- **El `run { }` sin receptor es un bloque-expresión.** Te deja mantener un `val` de asignación única mientras lo computás en varios pasos, lo que le gana a una `var` que mutás.
