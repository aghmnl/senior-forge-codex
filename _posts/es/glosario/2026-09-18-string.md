## The Theory (El Qué)

**`String`** es la secuencia inmutable de caracteres de Kotlin, mapeada a `java.lang.String` en la [JVM]({{ "/es/glosario/jvm/" | relative_url }}). Toda operación que "cambia" un string (`plus`, `replace`, `trim`) devuelve una instancia nueva; el original nunca muta, lo que hace a los strings seguros para compartir entre threads y para usar como claves de map. En el sistema de tipos, `String` es la forma no-nullable y `String?` la nullable — el par que usa [Null Safety: Elvis & Safe Calls]({{ "/es/01-kotlin-core/null-safety-elvis-safe-calls/" | relative_url }}) para ilustrar que la nullabilidad es parte del tipo, no una propiedad del valor.

```kotlin
// Not found in FAS — standalone example
val name: String = "forge"
val upper = name.uppercase()     // String nuevo; `name` no cambia
val maybe: String? = null
val len = maybe?.length ?: 0     // String? hay que desenvolverlo explícitamente
```

## The Senior Nuance (El Matiz Senior)

- **Inmutable significa que concatenar aloca.** Armar un string en un loop con `+` crea un objeto nuevo por iteración; usá `buildString { }` / `StringBuilder` en caminos calientes.
- **`==` es `equals`, `===` es identidad.** El `==` de Kotlin compara contenido, así que la trampa de Java de comparar strings por referencia no existe — pero el interning sí, así que nunca dependas de `===` con strings.
- **`String!` desde Java es un [platform type]({{ "/es/glosario/platform-types/" | relative_url }}).** Un método Java que devuelve `String` sin anotaciones igual puede darte `null`; declará el lado Kotlin como `String?` o anotá el lado Java.
