## The Theory (El Qué)

**`val`** declara una referencia de solo lectura: se asigna una vez y no puede reasignarse. Es la opción por defecto en Kotlin — toda declaración empieza como `val` y se promueve a [`var`]({{ "/es/glosario/var/" | relative_url }}) solo con un motivo. Una propiedad `val` tiene [getter]({{ "/es/glosario/getter/" | relative_url }}) pero no setter. Solo lectura no es lo mismo que [inmutable]({{ "/es/glosario/immutability/" | relative_url }}): `val list = mutableListOf(1)` no puede reapuntarse, pero su contenido sí puede cambiar. Para el compilador, un `val` local o una propiedad `val` sin getter custom es un valor *estable*, y eso es lo que hace posibles los smart casts ([Smart Casts]({{ "/es/01-kotlin-core/smart-casts/" | relative_url }})) después de un chequeo [`is`]({{ "/es/glosario/is-operator/" | relative_url }}) o de null.

```kotlin
// De FollowApp Suite — RecurrenceCalculator.kt
// `until` es un val: después del chequeo de null se smart-castea a Long para el resto de la expresión
val until = (rule.end as? RecurrenceEnd.UntilDate)?.date
return if (until != null && candidate > until) null else candidate
```

## The Senior Nuance (El Matiz Senior)

- **`val` es lo que destraba el smart cast.** El compilador solo puede refinar un tipo cuando puede probar que el valor no cambió entre el chequeo y el uso; un `val` con el getter por defecto es esa prueba. Capturar un [`var`]({{ "/es/glosario/var/" | relative_url }}) en un `val` local es el arreglo idiomático cuando un smart cast es rechazado.
- **Un `val` con getter custom no es estable.** `val now: Long get() = System.currentTimeMillis()` es un `val`, pero cada lectura puede diferir, así que el compilador no lo smart-castea. Tampoco a un `val` `open`, que una subclase podría sobreescribir.
- **Referencia de solo lectura, no objeto congelado.** Combiná `val` con tipos de solo lectura (`List`, no `MutableList`) cuando de verdad querés inmutabilidad.
