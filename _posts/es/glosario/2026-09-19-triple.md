## The Theory (El Qué)

**`Triple<A, B, C>`** es una data class ([Data Classes: copy, equals, toString]({{ "/es/01-kotlin-core/data-classes/" | relative_url }})) de la stdlib que guarda tres valores — `first`, `second`, `third` — con `Pair` como su hermano de dos. Al ser data class trae [`equals`]({{ "/es/glosario/equals/" | relative_url }}), `hashCode`, `toString`, [`copy`]({{ "/es/glosario/copy/" | relative_url }}) y [`componentN`]({{ "/es/glosario/component-n/" | relative_url }}), que es lo que te deja escribir `val (a, b, c) = triple`. Existe para el caso descartable: devolver varios valores de un cálculo local sin declarar un tipo para ellos.

```kotlin
// De FollowApp Suite — MyTasksApplication.kt
// Triple + destructuring para leer tres preferencias de una
val (language, themeMode, contrastLevel) = runBlocking {
    Triple(
        languagePreferences.getLanguage().first(),
        themePreferences.getThemeMode().first(),
        themePreferences.getContrastLevel().first()
    )
}
```

## The Senior Nuance (El Matiz Senior)

- **`Triple` nombra posiciones, no significados.** `first`/`second`/`third` no llevan información de dominio, así que un `Triple` que cruza un límite de módulo o de API es una data class que faltó. Mantenelo local, con el destructuring pegado a la construcción.
- **Tres es el techo práctico.** No existe `Quadruple`, a propósito: pasados los tres valores el acceso posicional deja de ser legible y la respuesta es una data class con nombres.
- **El destructuring es posicional.** Intercambiar dos componentes del mismo tipo de un `Triple` compila y cambia el significado en silencio en el lugar de uso — la advertencia habitual del [destructuring]({{ "/es/glosario/destructuring/" | relative_url }}).
