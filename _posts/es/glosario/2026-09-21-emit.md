## The Theory (El Qué)

**`emit(value)`** es la función suspendible que llama un builder de [`Flow`]({{ "/es/glosario/flow/" | relative_url }}) para empujar un valor a su colector. Suspende hasta que el bloque [`collect`]({{ "/es/glosario/collect/" | relative_url }}) downstream terminó de procesar ese valor, y eso es lo que hace que un cold flow tenga backpressure por defecto: un colector lento frena al productor. `emit` tiene que llamarse desde la coroutine propia del builder — ver [preservación del contexto]({{ "/es/glosario/context-preservation/" | relative_url }}).

```kotlin
// Not found in FAS — standalone example
fun ticker(): Flow<Int> = flow {
    var i = 0
    while (true) {
        emit(i++)        // suspende hasta que el colector procesó este valor
        delay(1_000)
    }
}
```

## The Senior Nuance (El Matiz Senior)

- **`emit` es secuencial y suspendible — ese es todo el modelo de backpressure.** No se acumula ninguna cola salvo que la pidas con [`buffer`]({{ "/es/glosario/buffer/" | relative_url }}), `conflate` o un `flowOn` (que bufferea como efecto secundario).
- **Nunca hagas `emit` desde otra coroutine.** `launch { emit(x) }` o `withContext { emit(x) }` dentro de un `flow { }` lanza en runtime; usá `channelFlow` + `send` cuando las emisiones vienen realmente de otro lado.
- **`emitAll` reenvía otro flow.** `emitAll(otroFlow)` es la forma idiomática de insertar un flow en un builder sin colectarlo a mano.
- Ver [withContext vs flowOn]({{ "/es/02-coroutines-flow/with-context-vs-flow-on/" | relative_url }}).
