## The Theory (El Qué)

**`object`** declara de una sola vez una clase y su instancia única — el [singleton]({{ "/es/glosario/singleton/" | relative_url }}) incorporado de Kotlin. La instancia se crea de forma lazy y segura entre threads en el primer acceso, y no hay constructor que llamar: `Off`, no `Off()`. Viene en tres formas: declaración con nombre (`object Registry`), [companion object]({{ "/es/glosario/companion-object/" | relative_url }}) (`companion object`) y expresión anónima (`object : Listener { }`). Marcarlo `data` agrega `toString`, `equals` y `hashCode` — ver [Data Objects: Singleton & Memory Savings]({{ "/es/01-kotlin-core/data-objects/" | relative_url }}).

```kotlin
// De FollowApp Suite — FilterState.kt
sealed class ScaleFilterState {
    object Off : ScaleFilterState()                       // una instancia, sin estado
    data class Include(val values: Set<String>) : ScaleFilterState()
    object Exclude : ScaleFilterState()
}
```

## The Senior Nuance (El Matiz Senior)

- **Su vida es la del proceso, no la de una pantalla.** Un `object` se inicializa una vez y nunca se libera, así que cualquier estado que le pongas sobrevive a toda `Activity` y a todo `ViewModel`. Guardar un `Context` ahí es un [memory leak]({{ "/es/glosario/memory-leaks/" | relative_url }}) permanente.
- **Lazy y thread-safe por construcción.** Lo garantiza el lock de inicialización de clases de la JVM, así que nunca necesitás el baile del double-checked locking.
- **No es inyectable ni reemplazable en tests.** Un `object` es una dependencia dura en el lugar de la llamada; preferí una clase con [`@Singleton`]({{ "/es/glosario/singleton-scope/" | relative_url }}) cuando necesitás un fake.
- Ver [Data Objects: Singleton & Memory Savings]({{ "/es/01-kotlin-core/data-objects/" | relative_url }}).
