## The Theory (El Qué)

**`catch`** es el operador de [`Flow`]({{ "/es/glosario/flow/" | relative_url }}) que maneja las excepciones lanzadas **upstream** de él: el builder y cada operador declarado más arriba. Nunca ve una falla del [downstream]({{ "/es/glosario/downstream/" | relative_url }}) — una excepción adentro del bloque `collect` queda fuera de su alcance. Dentro del bloque, `it` es el [`Throwable`]({{ "/es/glosario/throwable/" | relative_url }}), y llamar a [`emit`]({{ "/es/glosario/emit/" | relative_url }}) convierte la falla en una emisión normal, que es como le llega un valor de respaldo al colector. Relanza [`CancellationException`]({{ "/es/glosario/cancellation-exception/" | relative_url }}) automáticamente, así que un flow cancelado sigue cancelado.

```kotlin
// De FollowApp Suite — LabelsListViewModel.kt
.catch { e ->
    Log.e(TAG, "Error loading labels", e)
    _uiState.update { it.copy(isLoading = false, errorMessageRes = e.toUserMessage()) }
}
.collect { /* ... */ }
```

## The Senior Nuance (El Matiz Senior)

- **La posición es la API, igual que con `flowOn`.** Un `catch` escrito arriba de un operador no lo protege. Ponelo debajo de todo aquello cuyas fallas querés manejar, y arriba de nada que quieras dejar transparente.
- **No puede alcanzar el bloque `collect`.** Mové el trabajo riesgoso del consumidor a un [`onEach`]({{ "/es/glosario/on-each/" | relative_url }}) por encima del `catch`, o dale al bloque su propio [`try/catch`]({{ "/es/glosario/try-catch/" | relative_url }}).
- **Loguear no es manejar.** Un `catch` que solo loguea deja la UI girando; mové el [state holder]({{ "/es/glosario/state-holder/" | relative_url }}) a un estado de error.
- **Respeta la [transparencia a las excepciones]({{ "/es/glosario/exception-transparency/" | relative_url }}).** Un productor no debe atrapar sus propias emisiones; para eso está este operador.
