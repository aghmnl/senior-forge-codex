## The Theory (El Qué)

**`onEach`** es un operador intermedio de [`Flow`]({{ "/es/glosario/flow/" | relative_url }}) que ejecuta un efecto secundario por cada valor y lo deja pasar sin cambiarlo. Es la contraparte declarativa del cuerpo de un `collect`: el mismo código, pero ubicado *adentro* de la cadena, así que puede ponerse arriba de un [`catch`]({{ "/es/glosario/catch/" | relative_url }}) y que ese operador maneje sus fallas — algo que un bloque `collect`, al estar [downstream]({{ "/es/glosario/downstream/" | relative_url }}), no puede.

```kotlin
// Not found in FAS — standalone example
// Una falla en el mapeo SÍ queda cubierta, porque onEach está upstream del catch
repository.tasks()
    .onEach { cache.write(it) }
    .catch { e -> _uiState.update { it.toError(e) } }
    .collect { _uiState.value = it }
```

## The Senior Nuance (El Matiz Senior)

- **Es la forma de volver atrapable el trabajo del consumidor.** Movés la parte riesgosa del bloque `collect` a un `onEach` por encima del `catch`, y el operador la cubre.
- **No arranca el flow.** `onEach` es intermedio y lazy, así que una cadena que termina en `onEach` sin operador terminal no ejecuta nada — un no-op silencioso clásico. Combinalo con `launchIn(scope)` cuando querés que sea todo el consumidor.
- **Usalo para efectos, no para transformaciones.** Si estás produciendo un valor nuevo, eso es `map`; un `onEach` que devuelve algo es un olor, porque su resultado se descarta.
