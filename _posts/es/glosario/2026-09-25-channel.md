## The Theory (El Qué)

Un **`Channel<T>`** es una primitiva de comunicación entre [coroutines]({{ "/es/glosario/coroutines/" | relative_url }}): un lado llama a `send`, el otro a `receive`, y **cada valor se le entrega a exactamente un receptor**. Su capacidad decide cuándo suspende `send`: `RENDEZVOUS` (por defecto, sin buffer: emisor y receptor se encuentran), `BUFFERED`, `UNLIMITED` o `CONFLATED` (se queda solo con el último). Un channel es un [stream hot]({{ "/es/glosario/hot-stream/" | relative_url }}): los valores que se le envían esperan ahí haya o no alguien recibiendo todavía. Se puede exponer como [Flow]({{ "/es/glosario/flow/" | relative_url }}) con `receiveAsFlow()`.

```kotlin
// Not found in FAS — standalone example
private val _events = Channel<UiEvent>(Channel.BUFFERED)
val events: Flow<UiEvent> = _events.receiveAsFlow()

fun onSaved() {
    _events.trySend(UiEvent.ShowSaved)   // espera en el buffer hasta que la UI colecte
}
```

## The Senior Nuance (El Matiz Senior)

- **Cola, no difusión.** Con dos colectores sobre `receiveAsFlow()`, cada evento va a uno solo. Es lo opuesto de [SharedFlow]({{ "/es/glosario/sharedflow/" | relative_url }}), donde cada colector recibe cada valor.
- **Los eventos en buffer sobreviven a la falta de colector.** Un evento enviado mientras la pantalla rota espera en el buffer y se entrega cuando la UI vuelve a colectar, y por eso los channels son una opción común para eventos de UI de una sola vez. No es infalible: un evento que ya salió del channel se puede perder si el colector se cancela antes de manejarlo.
- **`send` vs `trySend`.** `send` suspende cuando el buffer está lleno; `trySend` retorna de inmediato con un resultado que dice si el valor fue aceptado. Además, los channels se tienen que cerrar; un `Flow` no.
