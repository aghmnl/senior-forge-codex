## The Theory (El Qué)

**Kotlin** es un lenguaje de programación de tipado estático creado por JetBrains. Compila a [bytecode]({{ "/es/glosario/bytecode/" | relative_url }}) para la [JVM]({{ "/es/glosario/jvm/" | relative_url }}) (y de ahí al formato DEX de Android), y también a JavaScript, binarios nativos y WebAssembly. Desde 2019 Google declaró el desarrollo Android **Kotlin-first**: las librerías nuevas de Jetpack, [Jetpack Compose]({{ "/es/glosario/jetpack-compose/" | relative_url }}) y las [coroutines]({{ "/es/glosario/coroutines/" | relative_url }}) están diseñadas para él.

```kotlin
// Not found in FAS — standalone example
// Null safety, data classes y coroutines: tres razones por las que Android lo adoptó
data class Task(val id: String, val title: String, val dueAt: Long?)

suspend fun overdue(repo: TaskRepository, now: Long): List<Task> =
    repo.getAll().filter { task -> task.dueAt?.let { it < now } ?: false }
```

## The Senior Nuance (El Matiz Senior)

- **100% interoperable con Java.** Kotlin llama a Java y Java llama a Kotlin en el mismo proyecto, y eso es lo que permitió migrar los codebases Android de a un archivo por vez. Las costuras aparecen en los [platform types]({{ "/es/glosario/platform-types/" | relative_url }}) y en anotaciones como [@JvmStatic]({{ "/es/glosario/jvm-static/" | relative_url }}).
- **Su seguridad la impone el compilador.** La nulabilidad en el sistema de tipos, el `when` exhaustivo sobre [sealed classes]({{ "/es/glosario/sealed-class/" | relative_url }}) y las colecciones de solo lectura atrapan familias enteras de bugs antes del runtime.
- **Muchas de sus features son trabajo del compilador, no magia en runtime.** Las data classes, las extension functions, las [inline functions]({{ "/es/glosario/inline-functions/" | relative_url }}) y las suspend functions compilan a bytecode JVM común, y por eso entender a qué compilan es un tema de nivel Senior.
