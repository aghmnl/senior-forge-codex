## The Theory (El Qué)

**`LiveData<T>`** es el contenedor de datos observable de Android Architecture Components, anterior a [Flow]({{ "/es/glosario/flow/" | relative_url }}). Es **[lifecycle-aware]({{ "/es/glosario/lifecycle-aware/" | relative_url }}) por sí mismo**: `observe(owner, observer)` solo entrega valores mientras el owner está `STARTED` o `RESUMED`, y quita al observer automáticamente cuando el owner pasa a `DESTROYED`. `MutableLiveData` expone `setValue` (main thread) y `postValue` (cualquier thread). Es el antecesor del patrón `_uiState` / `uiState` que después adoptó [StateFlow]({{ "/es/glosario/stateflow/" | relative_url }}).

```kotlin
// Not found in FAS — standalone example
class LegacyViewModel : ViewModel() {
    private val _count = MutableLiveData(0)
    val count: LiveData<Int> = _count

    fun increment() {
        _count.value = (_count.value ?: 0) + 1   // solo en el main thread
    }
}

// En un Fragment: deja de entregar en background y se desuscribe al destruirse
viewModel.count.observe(viewLifecycleOwner) { render(it) }
```

## The Senior Nuance (El Matiz Senior)

- **Sin filtro por igualdad.** Cada `setValue` notifica a los observers, aunque el valor sea igual. [StateFlow]({{ "/es/glosario/stateflow/" | relative_url }}) descarta las escrituras iguales. El código migrado desde LiveData que dependía de notificaciones repetidas deja de funcionar en silencio.
- **`postValue` junta valores.** Varios `postValue` antes de que corra el main thread entregan solo el último: una forma de [conflation]({{ "/es/glosario/conflation/" | relative_url }}) que sorprende a quien esperaba recibir todos.
- **Valor inicial opcional y nullable.** `value` puede ser `null` antes de que se asigne algo, lo que empuja chequeos de null hacia la UI. `StateFlow` obliga a tener un valor inicial real.
- **Por qué el código nuevo prefiere StateFlow.** LiveData es solo de Android, tiene muy pocos operadores y ata el lifecycle al contenedor. Con `StateFlow` el contenedor es [Kotlin]({{ "/es/glosario/kotlin/" | relative_url }}) puro y la conciencia del lifecycle pasa al colector ([repeatOnLifecycle]({{ "/es/glosario/repeat-on-lifecycle/" | relative_url }}), [collectAsStateWithLifecycle]({{ "/es/glosario/collect-as-state-with-lifecycle/" | relative_url }})). Igual conviene conocer LiveData: la mayoría de los codebases legacy lo usan.
