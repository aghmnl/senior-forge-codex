## The Theory (El Qué)

**`stateIn(scope, started, initialValue)`** convierte un [Flow]({{ "/es/glosario/flow/" | relative_url }}) cold en un [StateFlow]({{ "/es/glosario/stateflow/" | relative_url }}). Lanza **una sola** colección del [upstream]({{ "/es/glosario/upstream/" | relative_url }}) en `scope` y comparte su último valor con cada suscriptor, así que tres pantallas observando el resultado cuestan una query en vez de tres. `started` decide cuándo corre esa colección: `SharingStarted.Eagerly` (de inmediato, para siempre), `Lazily` (con el primer suscriptor, para siempre) o [WhileSubscribed]({{ "/es/glosario/while-subscribed/" | relative_url }}) (solo mientras alguien colecta). Una sobrecarga suspendible, `stateIn(scope)`, espera el primer valor en vez de recibir uno inicial.

```kotlin
// Not found in FAS — standalone example
val uiState: StateFlow<TasksUiState> = getActiveTasksUseCase()
    .map { tasks -> TasksUiState(tasks = tasks, isLoading = false) }
    .stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5_000),
        initialValue = TasksUiState(isLoading = true)
    )
```

## The Senior Nuance (El Matiz Senior)

- **Reemplaza el patrón `init { launch { collect { _state.value = it } } }`.** El estado se declara como una transformación de sus fuentes en vez de empujarse desde una coroutine lateral, y solo corre mientras hace falta.
- **El valor inicial sigue siendo una decisión de diseño.** Es lo que muestra la UI hasta que el upstream emite; `isLoading = true` es honesto, una lista vacía no.
- **No lo llames adentro de una función.** Cada llamada crea una colección compartida nueva. `fun state() = flow.stateIn(...)` llamado en cada recomposición o en cada creación de pantalla crea muchas: va en una propiedad, creada una sola vez.
- Su hermano `shareIn` produce un [SharedFlow]({{ "/es/glosario/sharedflow/" | relative_url }}) en su lugar: sin valor inicial y con replay configurable.
