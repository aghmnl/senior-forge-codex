## The Theory (El Qué)

**Eager** significa hacer el trabajo **de inmediato**, cuando algo se crea, en vez de esperar a que el resultado haga falta. Lo opuesto es **lazy**: postergar el trabajo hasta la primera vez que alguien lo pide. En coroutines la diferencia aparece en cuándo empieza a colectarse un [Flow]({{ "/es/glosario/flow/" | relative_url }}): un [cold stream]({{ "/es/glosario/cold-stream/" | relative_url }}) es lazy por naturaleza (no corre nada hasta que alguien colecta), mientras que `SharingStarted.Eagerly` o un `launch` en `init` empiezan a trabajar de inmediato.

```kotlin
// De FollowApp Suite — SettingsViewModel.kt
// Eager: la colección arranca apenas se crea el ViewModel,
// esté la pantalla mirando o no
init {
    viewModelScope.launch {
        getPremiumStatusUseCase()
            .collect { premium -> _uiState.update { it.copy(isPremium = premium) } }
    }
}
```

## The Senior Nuance (El Matiz Senior)

- **Eager cambia recursos por disponibilidad.** Los datos están listos antes de que alguien los pida, a costa de hacer trabajo que quizás nunca se use.
- **Lazy cambia una demora en el primer uso por hacer solo lo necesario.** Kotlin tiene herramientas lazy en varios niveles: [by lazy]({{ "/es/01-kotlin-core/lateinit-vs-lazy/" | relative_url }}) para propiedades, [Sequence]({{ "/es/glosario/sequences/" | relative_url }}) para colecciones, y los flows cold para streams.
- **En el estado de UI de Android, lazy suele ganar.** El trabajo que corre solo mientras una pantalla está visible, con [SharingStarted.WhileSubscribed]({{ "/es/glosario/sharing-started/" | relative_url }}), ahorra batería y datos sin que la app se vuelva más lenta para el usuario.
