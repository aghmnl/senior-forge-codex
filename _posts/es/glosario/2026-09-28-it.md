## The Theory (El Qué)

**`it`** es el **nombre implícito del único parámetro de un [lambda]({{ "/es/glosario/lambdas/" | relative_url }})**. Cuando un lambda recibe exactamente un parámetro y no le ponés nombre, Kotlin te deja referirte a él como `it`. `list.filter { it > 0 }` es lo mismo que `list.filter { n -> n > 0 }`.

```kotlin
// De FollowApp Suite — TasksViewModel.kt
// `it` es el estado actual que update {} le pasa al lambda
_uiState.update { it.copy(errorMessageRes = null) }

// De FollowApp Suite — TasksViewModel.kt
// Acá `it` es cada Boolean que emite _restored
_restored.filter { it }
```

## The Senior Nuance (El Matiz Senior)

- **Poné nombre al parámetro cuando `it` deja de ser obvio.** En lambdas cortos `it` se lee bien. En lambdas anidados cada uno tiene su propio `it`, y el de adentro tapa al de afuera; nombrarlos (`state ->`, `task ->`) evita confusiones.
- **En `update {}`, todo lo que se deriva de `it` es atómico.** `it` es el valor que `update` va a comparar antes de guardar, así que todo lo calculado a partir de él está protegido; lo que se lee afuera del lambda no.
