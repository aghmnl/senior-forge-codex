## The Theory (El Qué)

Una **query** (consulta) es un pedido a una base de datos para leer (o modificar) datos. En Android suele ser SQL ejecutado por [Room]({{ "/es/glosario/room/" | relative_url }}): cada método de un [DAO]({{ "/es/glosario/dao/" | relative_url }}) anotado con `@Query` lleva el SQL que ejecuta. Cuando el método devuelve un [Flow]({{ "/es/glosario/flow/" | relative_url }}), la query es **observable**: Room la vuelve a ejecutar cada vez que cambia la tabla que lee, y emite el resultado nuevo.

```kotlin
// De FollowApp Suite — LabelOptionDao.kt
// Una query observable: se vuelve a ejecutar y emite cada vez que cambia label_options
@Query("SELECT * FROM label_options ORDER BY sort_order ASC, label ASC")
fun getAllOptionsStream(): Flow<List<LabelOptionEntity>>
```

## The Senior Nuance (El Matiz Senior)

- **Una query observable cuesta por cada collector.** Como un `Flow` de Room es un [cold stream]({{ "/es/glosario/cold-stream/" | relative_url }}), cada [collector]({{ "/es/glosario/collector/" | relative_url }}) ejecuta su propia query y su propio observer. Varias pantallas colectando la misma multiplican el trabajo, salvo que se comparta con [shareIn]({{ "/es/glosario/share-in/" | relative_url }}) o [stateIn]({{ "/es/glosario/state-in/" | relative_url }}).
- **Ordená y filtrá en SQL cuando se pueda.** La base de datos lo hace más rápido y con menos memoria que ordenar una lista en Kotlin, sobre todo con un índice en la columna ordenada.
- Room verifica el SQL en tiempo de compilación: un error de tipeo en el nombre de una columna es un error de build, no un crash.
