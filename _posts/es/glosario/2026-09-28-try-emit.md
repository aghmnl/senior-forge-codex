## The Theory (El Qué)

**`tryEmit(value)`** es la forma **no suspendible** de meter un valor en un [MutableSharedFlow]({{ "/es/glosario/mutable-shared-flow/" | relative_url }}). Devuelve `true` si el valor fue aceptado y `false` si hubiera tenido que suspender, es decir, cuando el buffer está lleno con la política `SUSPEND`. Existe para el código que no puede llamar a una [suspend function]({{ "/es/glosario/suspend-functions/" | relative_url }}), como los [callbacks]({{ "/es/glosario/callbacks/" | relative_url }}), los listeners y los interceptores. Su hermano suspendible es [emit]({{ "/es/glosario/emit/" | relative_url }}).

```kotlin
// Not found in FAS — standalone example
private val _clicks = MutableSharedFlow<Unit>(
    extraBufferCapacity = 1,
    onBufferOverflow = BufferOverflow.DROP_OLDEST
)

// Un listener de View no puede suspender: tryEmit es el puente
button.setOnClickListener { _clicks.tryEmit(Unit) }
```

## The Senior Nuance (El Matiz Senior)

- **Con la configuración por defecto siempre falla cuando alguien escucha.** [`MutableSharedFlow<T>()`]({{ "/es/glosario/mutable-shared-flow/" | relative_url }}) no tiene buffer, así que con al menos un suscriptor no hay dónde dejar el valor y `tryEmit` devuelve `false`. Necesita `extraBufferCapacity` mayor que cero, o una política de descarte.
- **Sin suscriptores devuelve `true` y el valor igual se puede perder.** "Aceptado" no es "entregado": con `replay = 0` y nadie colectando, el valor se descarta, y `tryEmit` igual informa éxito.
- **Con una política de descarte nunca falla.** Con `DROP_OLDEST` o `DROP_LATEST` siempre devuelve `true`, porque el overflow se resuelve descartando un valor en vez de suspender. Ignorar el `Boolean` que devuelve solo es seguro con esa configuración.
