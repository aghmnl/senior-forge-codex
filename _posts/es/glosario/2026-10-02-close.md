## The Theory (El Qué)

**`close()`** le avisa a un [Channel]({{ "/es/glosario/channel/" | relative_url }}) que **no vienen más valores**. Los valores que ya estaban en el buffer igual se entregan; después de eso, un ciclo `for` sobre el channel termina normalmente. A partir de ahí, [send]({{ "/es/glosario/send/" | relative_url }}) lanza una excepción, y también [receive]({{ "/es/glosario/receive/" | relative_url }}) una vez que el channel está vacío. Llamarlo es responsabilidad de quien envía.

```kotlin
// Not found in FAS — standalone example
val channel = Channel<Int>(Channel.BUFFERED)
launch {
    try {
        for (n in 1..3) channel.send(n)
    } finally {
        channel.close()            // también lo cierra si el envío falla
    }
}
for (n in channel) println(n)      // 1, 2, 3, y el ciclo termina
```

## The Senior Nuance (El Matiz Senior)

- **Olvidarlo deja a los receptores esperando para siempre.** El ciclo nunca termina, la coroutine nunca finaliza y su scope nunca completa. Llamarlo en `finally`, o usar [produce]({{ "/es/glosario/produce/" | relative_url }}), lo evita.
- **`close()` no es `cancel()`.** Cerrar deja que el receptor termine de leer lo que queda; cancelar (desde el lado que recibe) descarta los valores restantes de inmediato.
