## The Theory (El Qué)

Un **listener** es un objeto (o un [lambda]({{ "/es/glosario/lambdas/" | relative_url }})) que registrás en una API para que la API **te llame de vuelta** cuando pasa algo: un click, una actualización de compra, una ubicación nueva. Es la forma más común de [callback]({{ "/es/glosario/callbacks/" | relative_url }}) en Android. El código adentro de un listener corre cuando se dispara el evento, normalmente en un thread que elige la API, y **no es una coroutine**, así que no puede llamar a suspend functions.

```kotlin
// De FollowApp Suite — BillingConnector.kt
// Play Billing informa las actualizaciones de compras mediante un listener
private val purchasesUpdatedListener = PurchasesUpdatedListener { result, purchases ->
    onPurchasesUpdated(result, purchases)
}
```

## The Senior Nuance (El Matiz Senior)

- **Todo listener que se registra se tiene que desregistrar.** Un listener guarda una referencia a lo que usa; uno que nunca se quita mantiene viva una pantalla, un `Context` o un ViewModel: una [memory leak]({{ "/es/glosario/memory-leaks/" | relative_url }}).
- **Conectar un listener con coroutines.** Como no puede suspender, publica valores con [trySend]({{ "/es/glosario/try-send/" | relative_url }}) (adentro de [callbackFlow]({{ "/es/glosario/callback-flow/" | relative_url }})) o asignando un [MutableStateFlow]({{ "/es/glosario/mutable-state-flow/" | relative_url }}), o envuelve un callback de una sola vez con [suspendCancellableCoroutine]({{ "/es/glosario/suspend-cancellable-coroutine/" | relative_url }}).
