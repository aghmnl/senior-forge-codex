## The Theory (El Qué)

Una **API** (Application Programming Interface, interfaz de programación de aplicaciones) es el conjunto de funciones, clases y reglas que un software expone para que otro código lo use sin saber cómo funciona por dentro. El [SDK]({{ "/es/glosario/sdk/" | relative_url }}) de Android, una librería como Play Billing, un backend accesible por HTTP y las clases públicas de un módulo son todas APIs.

## The Senior Nuance (El Matiz Senior)

- **La forma de una API decide cómo se consume.** Una [suspend function]({{ "/es/glosario/suspend-functions/" | relative_url }}), un [`Flow`]({{ "/es/glosario/flow/" | relative_url }}), un [callback]({{ "/es/glosario/callbacks/" | relative_url }}) o un [listener]({{ "/es/glosario/listener/" | relative_url }}) necesitan cada uno un puente distinto hacia las [coroutines]({{ "/es/glosario/coroutines/" | relative_url }}): las APIs de [callbacks]({{ "/es/glosario/callbacks/" | relative_url }}) se envuelven con [`suspendCancellableCoroutine`]({{ "/es/glosario/suspend-cancellable-coroutine/" | relative_url }}) (un valor) o [`callbackFlow`]({{ "/es/glosario/callback-flow/" | relative_url }}) (muchos valores).
- **La API pública es una promesa.** Todo lo que un módulo expone lo pueden usar otros, así que se vuelve difícil de cambiar; exponer menos (tipos de solo lectura, `internal`) mantiene chica esa promesa.
