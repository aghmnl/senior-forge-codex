## The Theory (El Qué)

**`debounce(timeout)`** es un operador de [`Flow`]({{ "/es/glosario/flow/" | relative_url }}) que emite un valor solo después de que el upstream estuvo **en silencio durante `timeout`**. Cada valor nuevo reinicia el timer y descarta el pendiente, así que una ráfaga de valores [produce]({{ "/es/glosario/produce/" | relative_url }}) solo el último. El último valor siempre se emite cuando el [flow]({{ "/es/glosario/flow/" | relative_url }}) se completa.

```kotlin
// Not found in FAS — standalone example
queryFlow
    .debounce(300)                  // esperar a que el usuario deje de escribir
    .distinctUntilChanged()
    .collectLatest { search(it) }
```

## The Senior Nuance (El Matiz Senior)

- **El caso clásico es la búsqueda mientras se escribe**: un request cuando el usuario hace una pausa, no uno por tecla.
- **Demora todos los valores, incluido el primero.** Para un botón que tiene que reaccionar al instante y después ignorar clicks repetidos, debounce es la herramienta equivocada; eso es throttling.
- **Sobre un stream de [eventos]({{ "/es/glosario/one-shot-event/" | relative_url }}) hot, debounce pierde [eventos]({{ "/es/glosario/one-shot-event/" | relative_url }}) a propósito.** Bien para texto, mal para [eventos]({{ "/es/glosario/one-shot-event/" | relative_url }}) donde cada uno importa.
