## The Theory (El Qué)

Un **scope** (ámbito) define la región de código donde un nombre (variable, función, clase) es visible y accesible. En Kotlin, los scopes se crean mediante bloques (`{}`), funciones, clases, archivos y módulos. Una variable declarada dentro de una rama `when` no es visible fuera de esa rama; una función privada tiene scope limitado a su archivo o clase.

Los scopes cumplen dos propósitos: controlan la **visibilidad** (quién puede ver este nombre) y el **tiempo de vida** (cuánto tiempo existe este valor). Cuando un scope termina, las variables locales se vuelven elegibles para [recolección de basura]({{ "/es/glosario/garbage-collector/" | relative_url }}).

## The Senior Nuance (El Matiz Senior)

- Las [scope functions]({{ "/es/01-kotlin-core/scope-functions/" | relative_url }}) de Kotlin (`let`, `run`, `with`, `apply`, `also`) llevan este nombre porque crean un scope temporal donde el objeto de contexto es el foco principal.
- Los **coroutine scopes** (`viewModelScope`, `lifecycleScope`, `GlobalScope`) definen el tiempo de vida de las corrutinas — cuando el scope se cancela, todas las corrutinas dentro de él se cancelan. Entender esto es crítico para evitar memory leaks.
- En inyección de dependencias, los **scopes** (`@Singleton`, `@ActivityScoped`) determinan el tiempo de vida de las dependencias provistas. Un desajuste de scope (inyectar un objeto con scope de activity en un singleton) es una fuente común de leaks.
- Los **modificadores de visibilidad** (`private`, `internal`, `protected`, `public`) son declaraciones de scope — controlan qué partes del código pueden acceder a un símbolo.
